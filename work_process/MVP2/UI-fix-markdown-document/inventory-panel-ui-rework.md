# 인벤토리 창 UI 전면 개선 — 작업 명세

| 항목 | 내용 |
| --- | --- |
| 대상 | `InventoryPanel` 인벤토리 창 |
| 목표 | 최근 시설 건설창과 새 HUD·퀘스트 UI·우측 메뉴에 어울리는 인벤토리 UI |
| 성격 | 정보 구조와 시각 표현 개선; 기존 인벤토리 기능 유지 |
| 기준 | 실제 작업 브랜치의 최신 파일을 우선 확인 |

## 1. 작업 목표

- 현재 인벤토리 창의 정보 배치와 시각적 완성도를 다시 점검한다.
- 자원 목록과 보유량, 현재 화물 중량/최대 적재량, 미정산 가치를 한눈에 읽게 만든다.
- 기존 레이아웃은 유지할 필요가 없으며 내부 구조와 패널 비율을 재설계해도 된다.
- 시설 건설창의 개선 방향을 참고하되 인벤토리의 조회 목적에 맞게 별도 구성한다.

## 2. 작업 전 확인

1. **`init/rule.md`를 먼저 읽고** `CLAUDE.md`의 적용 규칙을 확인한다.
2. 실제 작업 브랜치의 `init/prompt-B.md`에서 **B-112가 있으면 그 부분만** 읽는다.
3. `InventoryPanel.prefab`의 Hierarchy, 버튼·텍스트 참조, 앵커와 표시 영역을 조사한다.
4. `InventoryPanelPrefabBuilder` 및 다른 인벤토리 관련 빌더의 생성·재적용 범위를 확인한다.
5. `InventoryPanelView`·`Presenter`·`Binder`·행 View와 창 열기/닫기 연결을 확인한다.
6. 최근 수정된 **실제 작업 브랜치의** 시설 건설창과 HUD·퀘스트 UI·우측 메뉴를 Game View에서 비교한다.
7. 변경 전 `git status`와 수정 예정 파일을 기록한다.

> 확인한 `MVP2-fix39` 스냅샷의 `init/prompt-B.md`는 109번까지였다. B-112의 내용이나 구현 상태를 추측하지 말고 작업 브랜치에서 다시 확인한다.

## 3. 기존 연결에서 지킬 점

- 현재 코드는 `InventoryService` 스냅샷을 Presenter가 읽어 View에 전달한다.
- 자원 수량과 중량·적재량·미정산 가치의 원본은 기존 데이터 및 서비스다.
- Presenter의 `InventoryChanged` 구독·해제 및 데이터 갱신 흐름을 유지한다.
- 현재 View는 `PanelRoot`와 닫기 버튼의 표시를 제어하며 루트 활성 상태에 주의한다.
- 인벤토리 창의 토글 입력과 단축키는 현재 연결된 컨트롤러를 먼저 조사한다.
- 기존의 빈 목록, 0개 자원, 최대 적재 상태도 새 화면에서 올바르게 표현한다.

## 4. 재설계 허용 범위

- 창 크기, 구획, 자원 행 배열, 정보 계층, 여백, 아이콘과 텍스트 배치를 바꿀 수 있다.
- 현재 중량/최대 적재량의 관계를 숫자와 시각 요소로 함께 보여 줄 수 있다.
- 미정산 가치와 자원별 수량을 구별되는 영역으로 구성할 수 있다.
- 선택·Hover 효과가 실제 상호작용과 맞을 때만 해당 강조를 추가한다.
- 기존 에셋과 Unity UGUI·TextMeshPro로 패널, 구분선, 아이콘, 상태 표시를 만든다.
- 이미지 생성 없이 구현할 수 있으며 새 이미지는 작업의 전제 조건이 아니다.
- 긴 이름과 큰 수치, 자원 종류 증가 시 잘림·겹침이 없는지 고려한다.

## 5. 시각적 방향

- HUD·퀘스트 UI·우측 메뉴의 청록색 SF/산업적 분위기와 조화를 맞춘다.
- 시설 건설창의 색·두께·발광 강도 등을 참고하되 패널 구조를 그대로 복제하지 않는다.
- 장식보다 **자원 식별, 수량 비교, 적재 여유**의 읽기 쉬움을 우선한다.
- 부족·가득 참 같은 상태는 색상만으로 표현하지 않고 문구·수치도 함께 사용한다.

## 6. 반드시 유지할 동작

- 현재 인벤토리 기능, 자원 데이터 바인딩과 수량 표시를 유지한다.
- 인벤토리 열기/닫기, 닫기 버튼, 기존 단축키와 입력 우선순위를 유지한다.
- 채굴·보상 등으로 자원이 바뀌면 열린 창과 다시 연 창 모두 최신 값을 표시한다.
- 중량 계산, 최대 적재량, 미정산 가치 계산 및 관련 게임 로직을 변경하지 않는다.
- UI는 서비스의 스냅샷을 표시하고 인벤토리 State를 직접 쓰지 않는다.

## 7. 파일 범위와 복구 가능성

- 기본 대상: `sub-terra/Assets/_Project/Prefabs/UI/InventoryPanel.prefab`.
- 필요한 전용 코드만 `Scripts/App/UI/Inventory/`와 관련 Editor 빌더에서 수정한다.
- Scene 변경은 바인딩에 꼭 필요할 때만 수행하고 변경 이유를 보고한다.
- 시설 건설창은 참고용이다. 이번 작업에서 그 파일을 다시 수정하지 않는다.
- 다른 UI·공용 폰트/TMP·공용 에셋, `ProjectSettings/*`, `Packages/*`를 수정하지 않는다.
- Unity Editor/전용 빌더로 Prefab을 다루고 YAML 수동 수정과 `.meta` GUID 훼손을 피한다.
- 새 파일은 인벤토리 전용 경로에 한정하여 대상 변경만 쉽게 되돌릴 수 있게 한다.

## 8. 검증 및 완료 기준

1. `Bootstrap → 새 게임 → 탐사` 경로로 실행하여 실제 Game View에서 확인한다.
2. 목록·아이콘·보유량·현재/최대 적재량·미정산 가치의 가독성을 확인한다.
3. 자원 0개, 여러 종류, 값 변경, 적재량 근접/도달 상태를 확인한다.
4. 열기/닫기 버튼, 단축키, 다른 창과의 표시 상태, 재진입을 확인한다.
5. 대표 해상도에서 글자 잘림, 창 밖 넘침, HUD 및 다른 패널과 충돌을 확인한다.
6. 기존 관련 EditMode/PlayMode 검증 중 변경 위험에 맞는 범위를 실행한다.
7. `git status`와 `git diff --stat`로 관련 없는 변경이 없는지 확인한다.

## 9. 결과 보고

- Game View 최종 화면과 변경한 정보 구조·디자인 의도를 짧게 설명한다.
- 변경 파일 목록, 기능·해상도 검증 결과 및 남은 문제를 적는다.
- 실제 작업 브랜치의 B-112 확인 결과와 적용한 요구사항을 명시한다.
- 범위 밖 파일의 변경 여부와 되돌릴 수 있는 대상 파일 목록을 보고한다.
