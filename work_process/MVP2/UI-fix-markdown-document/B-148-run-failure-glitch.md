# B-148 런 실패 창 글리치 연출 + 잃은 자원 목록 (#119)

## 목표
체력을 모두 잃거나 가스로 쓰러졌을 때 뜨는 런 실패 창을 새로 만든다.
글리치와 함께 창이 뜨고, 잃은 자원을 하나씩 보여 준다. 확인 버튼을 누르면 암전 → 심한 글리치 → TV 켜짐 연출로 깨어나는 장면까지 이어진다.
지금은 창이 몇 초 떴다가 저절로 넘어가는데, 확인 버튼을 누를 때까지 기다리도록 바꾼다.

## 먼저 읽을 코드
- App/Integration/RunFailureRuntimeController.cs (실패 흐름, failureDisplaySeconds 대기, 조작 잠금, 깨어날 위치로 이동)
- App/Run/RunFailureService.cs (화물 손실 계산, 드론 구조 보존 비율)
- App/UI/RunFailure/RunFailurePanelView.cs (현재 창)
- Shared/DTO/RunFailureDtos.cs (PlayerRescueResultDto: cause, lostCargo, preservationRatio, usedCheckpoint)
- Tests/EditMode/App/Run/RunFailureServiceTests.cs, Tests/EditMode/App/Integration/PhaseLRunFailureStaticTests.cs
- Tests/PlayMode/Integration/RunFailure/RunFailureRuntimePlayModeTests.cs
- 참고 패턴: ResourceSellTimeline (DOTween 없는 순수 계산 타임라인), 골드 팝업의 숫자 올라가는 연출
- 가스 경고 화면 연출(B-146) 색감: 초록 계열 기준

## 1. 창 등장
- 체력 0 또는 가스 노출로 실패가 시작되면 조작을 잠그고 창을 띄운다 (기존 잠금 경로 유지).
- 창은 글리치와 함께 나타난다: 가로로 찢어지는 줄, 색이 어긋나는 효과(RGB 분리), 짧은 깜박임. 약 0.3초 뒤 또렷해진다.
- 글리치 색
  - 가스로 쓰러짐: 초록 계열 섞기
  - 그 외(체력 소진, 낙석 등): 빨강 계열 섞기
  - 원인은 PlayerRescueResultDto.cause로 판단한다. 가스 원인 값이 무엇인지 확인해서 보고한다.
- 제목에 쓰러진 원인을 짧게 적는다 (예: "체력 소진", "가스 중독").

## 2. 잃은 자원 목록
- 항목: 자원 아이콘 + 이름 + 잃은 개수.
- 항목은 위에서부터 하나씩 순서대로 올라온다 (항목 사이 간격 약 0.12초).
- 각 항목의 숫자는 0에서 잃은 개수까지 0.3~0.5초 만에 빠르게 차오른다 (끝에서 느려지는 곡선).
- 목록 아래에 드론 구조로 지킨 비율을 한 줄로 표시한다 (예: "드론 구조: 화물 60% 보존").
- 잃은 자원이 하나도 없으면 목록 자리에 "잃은 자원 없음"을 띄운다.
- 항목이 많으면 목록 영역 안에서 스크롤되게 하고, 창 크기는 넘치지 않게 한다.
- 연출 중 확인 버튼이나 아무 키를 누르면 목록 연출을 즉시 끝 상태로 건너뛴다. 끝 상태에서 확인을 다시 눌러야 다음으로 넘어간다.

## 3. 확인 후 전환 연출
확인 버튼(Enter/Space/E 포함)을 누르면 아래 순서로 진행한다. 전체 2초 이내.
1) 창이 꺼지면서 화면이 어두워진다 (약 0.4초).
2) 어두운 화면에서 화면 전체에 심한 글리치가 터진다 (0.5~0.7초). 색은 1번과 같은 원인별 색.
   - 이 구간에서 플레이어를 깨어날 위치(전진기지 / 엘리베이터 앞)로 옮긴다. 플레이어가 순간이동하는 모습은 보이지 않아야 한다.
3) TV가 켜지듯 화면이 켜진다 (약 0.4초): 가운데 가로선이 번쩍 → 위아래로 펼쳐지며 게임 화면이 보인다.
4) 연출이 끝나면 조작 잠금을 푼다.
- 지상 기지로 돌아가는 경우(깨어날 곳이 없을 때)는 2)까지 진행한 뒤 기존처럼 씬을 넘긴다. 씬 로드 후 3) TV 켜짐을 보여 줄 수 있으면 넣고, 어려우면 보고한다.

## 4. 흐름 변경
- failureDisplaySeconds로 자동으로 넘어가던 대기를 확인 버튼 대기로 바꾼다.
- 화물 손실, 저장(AutoSaveReason.RunFailure), 깨어날 위치 결정, 실패 토큰 처리 순서는 바꾸지 않는다.
- 확인을 누르기 전에 게임이 저장·종료되어도 손실이 중복되거나 사라지지 않아야 한다 (기존 토큰 규칙 유지).
- 엘리베이터 앞 부활 시 전력을 엘리베이터 비용만큼 채워 주는 코드가 있는데, 엘리베이터 비용이 이제 0이라 사실상 아무 일도 안 한다. 지워도 되는지 확인하고, 안전하면 지운 뒤 보고한다.

## 구현 방향
- 연출 계산은 순수 클래스로 분리한다 (예: RunFailureRevealTimeline: 창 글리치, 항목 순서, 숫자 차오름 / RunFailureTransitionTimeline: 암전·글리치·TV 켜짐). View는 계산된 값만 적용한다.
- 글리치는 UGUI 오버레이로 만든다 (가스 화면 연출과 같은 방식). 셰이더가 필요하면 써도 되지만 HUD 렌더 순서를 깨지 않는다.
- 숫자 차오름은 골드 팝업 쪽 계산이 재사용 가능하면 재사용한다.
- 이미지(글리치 텍스처, 스캔라인 등)가 필요하면 다른 에이전트에게 생성을 맡겨도 된다.
- 씬·프리팹 연결은 기존 Builder 패턴(Editor/DataValidation, PhaseLRunFailureBuilder)을 따른다.
- 시간·색 값은 인스펙터에서 조정할 수 있게 둔다.
