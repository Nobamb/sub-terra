# 시작 브리핑 UI 개편 — 작업 명세

| 항목 | 내용 |
| --- | --- |
| 기준 | 사용자가 제공한 시작 브리핑 개편 프롬프트 |
| 대상 | 시작 브리핑의 레이아웃·등장·지속 글리치·닫기 연출과 관련 입력·일시정지 처리 |
| 목표 | 불안정한 단말이 연결되어 임무를 전달하는 Sub-Terra식 브리핑 |
| 우선 규칙 | `CLAUDE.md`, `init/rule.md` 및 안내된 세부 규칙을 작업 전에 확인한다. |

## 1. 현재 문제와 작업 목표

- 기존의 작은 반투명 안내 상자 느낌에서 벗어나 존재감 있는 시작 브리핑으로 개편한다.
- 개선된 퀘스트 완료창 등 다른 팝업의 프레임·색상·폰트·버튼·간격과 시각적 방향을 맞춘다.
- 눈에 띄는 등장 연출과 읽는 동안의 약한 신호 간섭을 구분하고 본문 가독성을 우선한다.
- 기존 브리핑 노출 조건·저장 상태와 닫기 이후 플레이 진행 흐름은 유지한다.

## 2. 작업 전 조사

1. 관련 Prefab·Builder·Script, 실제 Scene 배치와 기존 UGUI/TMP 구현 방식을 확인한다.
2. 브리핑 최초 표시 조건, 확인 완료 상태의 저장·복원과 재표시 조건을 추적한다.
3. 확인 버튼·기존 닫기 단축키와 종료 콜백, 플레이 시작 시점을 확인한다.
4. 배경 입력 차단·일시정지 소유권과 광산 초기화 타이머의 시간 기준을 확인한다.
5. 비교할 팝업의 스타일과 변경 전 실제 Game View를 기록하고 필요한 파일 범위를 정한다.

## 3. 레이아웃과 확정 본문

- 화면 중앙에 어두운 금속 패널과 각진 청록색 프레임을 배치한다.
- 본문은 충분한 글자 크기·줄 간격·여백을 확보하고 화면 비율 변화에 대응한다.
- 확인 버튼 문구는 **작업 시작**으로 하며 기존 브리핑 종료·플레이 시작 동작에 연결한다.
- 아래 본문과 줄 구분을 그대로 사용한다. 문장 수정이나 새로운 세계관·슬로건 추가는 금지한다.

```text
지상에는 더 이상 캘 것이 남지 않았습니다.
배양시설에는 인류의 유전 정보가 보존되어 있습니다.
유전자 개량에 성공하면, 인류를 다시 태어나게 할 수 있습니다.
시설을 가동할 자원은 이제 땅 아래에 있습니다.

내려가십시오. 캐고, 버티고, 살아서 돌아오십시오.
```

## 4. 등장 애니메이션

- 첫 브리핑 표시 시 가로 노이즈와 화면 일부의 순간적 어긋남으로 짧은 화면 글리치를 **2~3번** 보여 준다.
- 화면 중앙에 청록색 신호가 모이고 가로로 퍼진 뒤, 프레임이 위아래로 확장되며 완성되게 한다.
- 프레임이 열리는 순간에도 가장자리에 짧은 글리치를 넣어 단말 신호가 잡히는 느낌을 만든다.
- 프레임 안정 후 본문과 버튼을 짧게 페이드인한다. 글자별 타이핑 대신 전체 문장을 빠르게 보여 준다.
- 등장 전체는 **약 1~1.5초**로 조정하여 효과가 분명하면서도 시작을 오래 지연하지 않게 한다.

## 5. 표시 중 지속 글리치

- 브리핑이 떠 있는 동안 외곽 프레임과 장식 주변에 약한 노이즈를 계속 유지한다.
- 테두리 일부의 짧은 어긋남과 청록빛 깜빡임을 간헐적으로 섞어 불규칙한 신호 간섭을 표현한다.
- 등장 시 강하게, 본문을 읽는 동안 낮은 강도로 유지하며 일정한 단순 점멸 패턴을 피한다.
- 지속 상태에서는 화면 전체를 반복적으로 흔들지 않는다.
- 본문에는 위치 흔들림·색 분리·왜곡·가림을 적용하지 않고 텍스트와 버튼을 안정적으로 유지한다.
- 글리치는 별도 레이어로 분리하여 프레임·주변 장식에만 적용하고 버튼 입력을 가로막지 않게 한다.

## 6. 닫기 연출과 입력 처리

- **작업 시작**을 누르면 즉시 비활성화하지 않고 **약 0.3~0.5초** 동안 닫기 연출을 진행한다.
- 글리치 강도·발생 빈도를 점차 낮추며 본문·버튼을 페이드아웃하고 프레임의 청록빛을 끈다.
- 연출 완료 후 기존 브리핑 종료 처리를 **한 번만** 실행하고 플레이 진행을 재개한다.
- 버튼·기존 닫기 단축키를 동일한 종료 경로로 연결하고 연속 클릭·중복 호출을 차단한다.
- 등장·표시·닫기 동안 배경 채굴·이동·메뉴 조작을 차단하고 광산 초기화 타이머도 정지한다.
- UI 연출은 일시정지 중에도 정상 재생되도록 비스케일 시간을 사용한다.
- 타이머가 실시간·비스케일 시간으로 동작한다면 기존 일시정지와 연동되는지 별도로 확인한다.
- 닫을 때에는 **브리핑이 적용한 일시정지만** 해제하고 다른 시스템의 일시정지 상태를 보존한다.

## 7. 저장 상태와 연출 수명주기

- 기존 노출 조건과 확인 완료 저장 상태를 유지하여 이미 확인한 브리핑이 로드 때 불필요하게 재생되지 않게 한다.
- 화면 전환·UI 비활성화 시 실행 중인 연출과 임시 효과를 정리한다.
- 정상적으로 다시 열릴 경우 위치·크기·색상·알파·입력 상태를 초기화하여 이전 연출이 누적되지 않게 한다.
- 닫기 도중 중복 입력이나 화면 전환이 발생해도 기존 종료·저장·플레이 시작 처리가 중복되지 않게 한다.

## 8. 구현 방식과 변경 범위

- 기존 Unity UGUI/TMP와 프로젝트 구현 방식을 활용하고 프레임·장식·본문·버튼·효과 레이어를 분리한다.
- 노이즈·프레임 변형·발광은 기존 에셋과 UI 요소를 우선 활용하여 구현한다.
- 화면 비율 변화 시 프레임과 효과가 같은 기준으로 정렬되도록 RectTransform·앵커를 구성한다.
- 변경은 브리핑 UI·관련 Builder와 필요한 입력·일시정지 연결에 한정하여 되돌리기 쉽게 유지한다.
- 관계없는 UI·게임 규칙·공용 에셋과 `ProjectSettings`·`Packages`는 수정하지 않는다.
- Scene·Prefab 처리와 에셋 변경은 프로젝트 규칙을 따르고 기존 참조·GUID를 보존한다.

## 9. Game View 검증과 결과 보고

1. 실제 게임 화면에서 등장 → 지속 글리치 → 닫기 순서와 각 연출 시간을 확인한다.
2. 본문 원문·줄 구분·가독성, 텍스트·버튼 안정성과 효과 레이어의 입력 방해 여부를 확인한다.
3. 버튼·단축키·연속 클릭 시 종료 처리가 한 번만 실행되고 닫기 완료 후 진행되는지 확인한다.
4. 배경 채굴·이동·메뉴 차단, 타이머 정지·재개와 다른 일시정지 상태 보존을 확인한다.
5. 새 게임·기존 세이브 로드의 노출 조건과 정상 재개방 시 연출·입력 상태 초기화를 확인한다.
6. 다른 화면 비율, 연출 중 화면 전환·UI 비활성화 시 정리 및 관련 회귀를 점검한다.
- 변경 파일, 디자인 의도, 연출 구현 방식, 검증 결과와 남은 문제를 정리한다.
- 실제 Game View 결과를 제시하고 가능하면 등장·지속·닫기를 담은 짧은 실행 영상을 제공한다.
