# 시설 건설창 UI 전면 개선 — 작업 명세

| 항목 | 내용 |
| --- | --- |
| 기준 | `Nobamb/sub-terra`의 `MVP2-fix39` 브랜치에서 확인한 구조 |
| 대상 | 게임 내 시설 건설창 `BuildingMenu` |
| 목표 | 새 HUD·퀘스트 UI·우측 메뉴와 어울리는 건설 인터페이스 |
| 성격 | UI/UX 개선; 기존 시설 건설 기능 유지 |

## 1. 현재 문제와 목표

- 시설 건설창은 오래된 임시 UI처럼 보여 새 UI들과 시각적 완성도가 맞지 않는다.
- 시설 목록·상세 정보·비용·건설 가능 여부의 정보 구조도 효율적이지 않다.
- 새 HUD와 퀘스트 UI의 청록색 SF·산업적 분위기를 참고하되 그대로 복제하지 않는다.
- 건설 흐름에 맞는 **정보 밀도와 명확한 선택 상태**를 갖춘 UI로 재구성한다.

## 2. 시작 전 조사

1. **`init/rule.md`를 가장 먼저 읽고** `AGENTS.md`의 적용 규칙도 확인한다.
2. 현재 `BuildingMenu.prefab`의 Hierarchy·Anchor·Canvas 연결·버튼 이벤트를 조사한다.
3. `BuildingMenuView`, `BuildingMenuPresenter`, `BuildingMenuBinder`와 시설 선택 입력 경로를 확인한다.
4. `BuildingMenuEntryButton` 및 관련 빌더·Integration Scene 인스턴스의 참조를 확인한다.
5. 현행 HUD·퀘스트 UI·우측 메뉴를 실제 Game View에서 살펴 디자인 기준을 잡는다.
6. 변경 대상 파일을 적고 현재 `git status`를 기록한 다음 수정한다.

## 3. 재설계 허용 범위

- 기존 레이아웃은 유지할 필요가 없다.
- 시설 목록, 선택된 시설의 이름·설명·전력, 보유량 대비 비용, 설치 가능 여부의 정보 계층을 재설계한다.
- 버튼 배열, 패널 구획, 구분선, 아이콘, 선택 강조, 상태·오류 메시지의 배치도 바꿀 수 있다.
- 시설을 고르고 비용과 설치 조건을 읽은 뒤 다음 행동을 이해할 수 있게 구성한다.
- 다양한 길이의 이름·설명과 여러 비용 항목이 겹치거나 잘리지 않도록 한다.
- 기존 프로젝트 에셋과 **Unity UGUI·TextMeshPro**로 제작한다. 이미지 생성은 필수가 아니다.
- 새 시각 요소가 필요하면 패널·선·색·상태 효과를 Unity UI로 만든다.

## 4. 반드시 유지할 기능

- 기존 시설 목록, 시설 선택과 선택 해제, 설치 Preview 및 실제 건설 흐름을 유지한다.
- 건설창 열기·닫기, 기존 단축키, 마우스 입력과 게임 플레이 간 입력 연결을 유지한다.
- 기존 시설 ID, 데이터 카탈로그, 설명·아이콘·전력·비용 값의 출처를 유지한다.
- 보유 자원·설치 위치·건설 조건에 따른 가능/불가 판정과 실패 이유를 그대로 반영한다.
- 비용 차감, 자원 갱신, 건설 성공·실패 처리 및 저장 흐름을 UI 변경 때문에 다시 작성하지 않는다.
- 목록과 상세 정보는 기존 Presenter의 읽기 모델을 활용하고, UI가 판정을 임의로 만들지 않는다.

## 5. 디자인 기준

- 청록색 강조, 짙은 금속·광산 계열 바탕, 선명한 경계와 절제된 발광을 참고한다.
- 선택 중인 시설과 클릭 가능한 항목을 크기·명암·윤곽으로 명확히 구별한다.
- 자원 부족과 위치 문제는 색상만으로 구별하지 말고 **문구와 아이콘**도 함께 제공한다.
- 장식보다 시설 이름, 용도, 보유량/필요량, 설치 가능 여부가 먼저 읽히게 한다.
- 새 HUD·퀘스트창·우측 메뉴와 어울리면서도 건설창만의 구조를 갖춘다.

## 6. 파일 범위와 되돌리기

- 기본 작업 대상: `sub-terra/Assets/_Project/Prefabs/UI/BuildingMenu.prefab`.
- 필요한 경우 `Scripts/App/UI/Building/`의 View·전용 UI 코드와 **해당** Editor 빌더만 수정한다.
- Integration Scene 변경은 현재 바인딩에 꼭 필요한 경우에만 수행하고 그 이유를 보고한다.
- 다른 UI Prefab·Scene, 공용 폰트/TMP·공용 에셋은 임의로 수정하지 않는다.
- `ProjectSettings/*`, `Packages/manifest.json`, `Packages/packages-lock.json` 및 Unity 버전을 변경하지 않는다.
- 새 에셋·스크립트는 건설창 전용 경로에 한정하고 기존 `.meta` GUID를 보존한다.
- 작업 범위를 좁혀 결과가 마음에 들지 않으면 대상 파일만 쉽게 되돌릴 수 있게 한다.
- 씬·Prefab YAML 직접 편집 대신 Unity Editor 또는 대상 경로가 한정된 빌더를 사용한다.

## 7. 구현 순서

1. 현행 화면·연결 구조를 기록하고 디자인의 정보 계층을 정한다.
2. 기존 기능 바인딩을 보존한 채 건설창 레이아웃과 시각 요소를 적용한다.
3. 시설 변경·보유 자원 변경·설치 결과에 따라 표시가 갱신되는지 확인한다.
4. `Bootstrap → 새 게임 → 탐사`로 진입해 실제 Game View에서 동작과 디자인을 점검한다.
5. `git status`와 `git diff --stat`로 변경 파일이 요청 범위 안에 있는지 확인한다.

## 8. 완료 기준

- 시설 목록, 선택 강조, 상세 정보, 비용의 보유량/필요량, 가능/불가 이유가 바로 읽힌다.
- 시설별 선택, Preview, 설치 성공·실패, 취소, 창 닫기, 기존 단축키가 정상 동작한다.
- 비용이나 설치 조건이 바뀌면 새 상태가 UI에 반영된다.
- 실제 Game View에서 대표 해상도의 글자 잘림·버튼 겹침·HUD 충돌을 확인한다.
- 기존 퀘스트·우측 메뉴·다른 HUD의 기능 및 레이아웃에 회귀가 없다.

## 9. 결과 보고

- Game View의 변경 전·후 화면 또는 최종 화면 캡처를 제공한다.
- 바꾼 정보 구조와 시각 디자인의 의도를 간단히 설명한다.
- 변경 파일 목록, 기능 검증 결과, 남은 문제를 보고한다.
- `git status`·`git diff --stat` 결과와 범위 밖 변경 여부를 함께 적는다.
