# 골드 획득 연출 개선 — Prompt-B 114 작업 명세

| 항목 | 내용 |
| --- | --- |
| 기준 | `Nobamb/sub-terra` / `MVP2-fix42`의 `init/prompt-B.md` 114번 |
| 대상 | 골드 획득 직후 월드 공간 이펙트와 선택적인 Gold HUD 반응 |
| 목표 | 획득량을 즉시 읽을 수 있는 짧고 절제된 Sub-Terra식 연출 |
| 우선 규칙 | 구현 전에 `init/rule.md`와 `AGENTS.md`를 확인한다. |

## 1. 현재 상태와 작업 목표

- 현재는 획득 금액과 보너스를 TMP 한 줄로 표시해 정보는 전달되지만 임시 UI처럼 보인다.
- 기존 코드에는 채굴 칸에서 솟구치는 금화 연출과 플레이어 머리 위의 월드 공간 문구가 있다.
- 새 이미지보다 기존 효과·에셋을 활용하여 움직임, 글자 계층과 마무리 반응을 개선한다.
- 화려한 폭발보다 광산에서 가치 있는 자원을 발견한 느낌을 짧고 명확하게 전달한다.

## 2. 작업 전 조사

1. `init/rule.md`를 가장 먼저 읽고 변경 가능한 파일과 Scene·Prefab 소유권을 확인한다.
2. 골드 지급 이벤트, 기본 획득량과 보너스 확정 경로 및 HUD Gold 갱신 시점을 추적한다.
3. `GoldPickupPresentation`·`GoldPickupVfx`의 글자·금화 생성과 수명주기를 확인한다.
4. `PromptB1001GoldPickupBuilder`, 관련 테스트, `HUDCanvas.prefab` 배선을 확인한다.
5. 실제 Game View에서 일반 획득·보너스 획득·빠른 연속 획득의 현재 화면을 기록한다.
6. HUD Gold 텍스트의 실제 Transform과 금색/주황색 팔레트 및 아이콘을 확인한다.

## 3. 연출 요구사항

- **획득 위치**에서 작은 금빛 입자 또는 광물 파편이 잠깐 나타나게 한다.
- 기존 `gold_coin_01.png`와 현재 금화 연출은 적합한 부분을 재사용·조정할 수 있다.
- 보이는 입자와 금화의 크기·개수·지속시간은 게임 화면에서 과하지 않게 맞춘다.
- 획득량은 플레이어 또는 획득 위치 주변에 `+20G` 형식으로 표시한다.
- 글자는 등장 시 살짝 커졌다 원래 크기로 돌아오고, 천천히 위로 이동하며 사라진다.
- 단순한 전체 알파 변화만으로 끝내지 않고 짧은 크기·위치 변화를 함께 사용한다.

## 4. 보너스 골드 표시

- 보너스가 있으면 기본 금액과 분리하여 다음처럼 표시한다.

```text
+20G
BONUS +15G
```

- 기본 금액이 가장 먼저 읽혀야 하며 `BONUS` 줄은 더 작게 보여도 된다.
- 표시값은 실제 확정된 기본 획득량·보너스 값으로 만든다. 보너스를 다시 계산하지 않는다.
- Gold HUD·골드 아이콘에 쓰인 금색/주황색 계열로 Cyan UI와 구분한다.
- 한글 또는 `BONUS` 문자 추가 시 기존 TMP 폰트에 글리프가 있는지 확인한다.

## 5. 선택적 HUD 연계 효과

- 구현이 자연스러우면 종료 직전에 **작은 금빛 입자 2~4개**를 Gold HUD 쪽으로 보낸다.
- HUD에 닿는 순간 Gold 숫자 또는 해당 영역을 `1.0 → 약 1.05~1.1 → 1.0`으로 짧게 Pulse한다.
- 실제 골드 데이터와 HUD 숫자는 기존 이벤트 시점에 **즉시 갱신**한다.
- 입자 이동·Pulse가 지급, 표시값 갱신 또는 저장을 기다리게 만들어서는 안 된다.
- 월드 위치에서 HUD Canvas 좌표로 변환할 때 화면 크기·카메라 변화에 대응한다.
- 이 선택 효과가 UI 바인딩을 크게 넓혀야 한다면 우선 본 연출을 완성하고 사유를 보고한다.

## 6. 연속 획득 처리

- 연달아 획득해도 동일 위치에 문구가 완전히 포개져 수치를 읽지 못하는 일이 없어야 한다.
- 현재 `GoldPickupVfx.SpawnText`는 새 문구가 뜰 때 이전 문구를 지우므로 이를 확인한다.
- 현재 구조에 맞춰 기존 효과 재사용, 작은 위치 차이, 짧은 시간 합산 중 한 방식을 선택한다.
- 어느 방식을 택해도 개별 획득 이벤트와 실제 골드 합계는 누락·중복되지 않아야 한다.
- 장면 전환, 오브젝트 비활성화, 중단 후에도 입자와 텍스트가 남지 않게 정리한다.

## 7. 구현 방식과 변경 범위

- Unity Particle System, TMP, 기존 Sprite와 작은 코드 애니메이션을 우선 사용한다.
- 외부 Tween 패키지, 새 Package 및 새 이미지 에셋은 추가하지 않는다.
- 주된 변경은 골드 표시용 `Scripts/App/Integration/GoldPickup*`와 해당 빌더에 한정한다.
- HUD Pulse가 필요하면 Gold 표시의 해당 컴포넌트·참조만 최소 변경한다.
- `HUDCanvas.prefab`이나 Integration Scene 저장이 필요하면 대상 경로만 Editor 빌더로 처리한다.
- 공용 TMP 폰트·HUD 전체 레이아웃·다른 UI Prefab을 재생성하거나 변경하지 않는다.
- 기존 `.meta` GUID, 입력과 Canvas 정렬, 효과의 raycast 비활성 상태를 보존한다.

## 8. 변경하지 않을 것

- 실제 골드 지급량·지급 시점·보너스 계산식·골드 관련 데이터 흐름
- 세이브 데이터, 채굴 판정, HUD 전체 레이아웃, 관계없는 UI와 게임 로직
- `ProjectSettings/*`, `Packages/*`, Unity/패키지 버전
- 시각 효과를 위해 골드 지급을 애니메이션 종료 시점까지 지연하는 동작

## 9. 구현 및 Game View 검증

1. 기존 연출을 기록한 뒤 글자 계층·입자·타임라인을 작은 변경으로 구현한다.
2. `Bootstrap → 새 게임 → 탐사`로 실행하여 일반 골드 획득을 확인한다.
3. 보너스 획득 시 두 줄의 실제 수치와 HUD의 즉시 반영을 확인한다.
4. 연속 획득 시 문구 가독성, 이펙트 정리 및 최종 골드 합계의 일치를 확인한다.
5. 최소 한 가지 다른 해상도에서 월드 문구와 선택적 HUD 입자 경로를 점검한다.
6. 관련 EditMode/PlayMode 테스트 및 `git status`·`git diff --stat`로 회귀와 변경 범위를 확인한다.

## 10. 결과 보고

- 실제 Game View의 일반·보너스·연속 획득 화면과 연출 변경 이유를 보여 준다.
- 사용·재사용한 에셋, 변경 파일 목록, 골드 지급 시점 검증 결과를 적는다.
- HUD 입자/Pulse 적용 여부, 미적용 이유 또는 남은 가독성 문제를 보고한다.
- 요청 범위 밖 Scene·Prefab·설정 파일의 변경이 없는지 명시한다.
