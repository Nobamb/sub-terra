## 0. 한 줄 결론

기존 18개 퀘스트의 썸네일을 작은 상세창에서도 읽히도록 밝기와 대비를 개선하고, **드릴 속도 업그레이드·지상으로 이동·광산 탐사 재개·심층 구역 해금** 네 장면은 기존 게임 에셋을 바탕으로 상황을 보여 주는 독립적인 컷으로 재구성한다. 진행 상태에 따른 밝기 차이는 실제 퀘스트 상태를 읽어 표시한다.

---

# 1. 작업 범위

수정 대상은 상세 퀘스트창의 썸네일 이미지와 그 이미지의 상태별 표시다. 조명 관련 썸네일에는 별도의 명암 연출을 적용한다. 현재 상세창의 프레임, 썸네일 영역 크기와 위치, 탐색 버튼, 상태 문구, 보상 영역, 기본 퀘스트 카드 및 다른 HUD는 유지한다.

새로운 퀘스트나 퀘스트 순서를 만들지 않는다. 완료 판정, 진행 조건, 보상, 세이브 구조를 변경하지 않는다.

# 2. 작업 전 필수 조사

1. `init/rule.md`, `quest-menu-UI.md` 및 기존 107-2 썸네일 작업을 확인한다.
2. `DemoObjectiveIds.Ordered`의 18개 ID와 현재 PNG의 매핑을 확인한다.
3. `QuestThumbnailView.Show`, `DemoObjectiveView.ApplyQuestDetailsVisual`, `DemoObjectivePresenter.RenderDetails`의 데이터 흐름과 현재 이미지 tint·alpha·상위 CanvasGroup·오버레이를 조사한다.
4. 실제 Game View에서 이미지 자체가 어두운지, UI tint 또는 반투명 레이어가 어둡게 만드는지 구분한다. 같은 암부를 이미지와 UI에 중복 적용하지 않는다.
5. 광부, 드론, 드릴, 엘리베이터, 조명, 사다리, 버팀목, 광산 타일 등 실제 에셋의 외형과 사용 권한을 확인한다.
6. 현재 썸네일의 해상도·비율·알파·압축·프레임 안쪽 가시 영역을 확인한다.

실제 이미지의 최종 명도와 구도는 이 조사 및 Game View 비교 후 확정한다. 이 문서는 임의의 확정 RGB값이나 노출 수치를 지정하지 않는다.

# 3. 기준 자료와 기존 연결

`quest-menu-UI.md`는 상세 퀘스트창 레이아웃의 기준이다. 기존 썸네일 PNG는 개선할 원본이며, 게임 에셋과 실제 플레이 화면은 캐릭터 형태, 팔레트, 광원 및 배경을 맞추는 기준이다. 최종 이미지는 상세창 안에 실제로 표시한 크기에서 판단한다.

현재 브랜치에서는 `QuestThumbnailView`가 퀘스트 ID별 `primary` 스프라이트를 표시한다. `PromptB1072QuestThumbnailBuilder`는 `demo.quest.` 접두사를 제거한 파일명으로 `Thumbnails/<id>.png`를 찾아 18개 항목에 연결한다. `DemoObjectivePresenter.RenderDetails`에는 이미 `isCleared`와 `isCurrent`가 있으며, `DemoObjectiveView.ApplyQuestDetailsVisual`을 거쳐 썸네일 표시로 전달할 수 있다.

**기존 파일명·영구 ID·순서·참조를 우선 유지한다.** 파일을 새로 만들거나 옮겨야 한다면 Unity `.meta` GUID 및 씬 참조를 함께 확인한다.

# 4. 상태별 밝기 규칙

| 실제 퀘스트 상태 | 썸네일 표시 | 기준 |
| --- | --- | --- |
| 현재 클리어해야 할 퀘스트 | 기본 게임 플레이 화면 수준의 밝기 | 인물·시설·행동을 한눈에 알아볼 수 있게 표시 |
| 이미 클리어한 퀘스트 | 현재 썸네일보다 **약간** 어둡게 | 지금 이미지보다는 밝게 개선하고 핵심 피사체를 유지 |
| 앞으로 클리어할 퀘스트 | 현재 썸네일보다 **약간** 어둡게 | 클리어 상태와 동일한 밝기 원칙 적용 |

완료와 예정 상태의 차이는 기존 상태 문구와 아이콘이 담당한다. 두 상태를 밝기만으로 구별하려고 별도 강한 암전 효과를 추가하지 않는다.

현재 브랜치에서 상태 판정은 `viewedIndex < completed`이면 클리어, `viewedIndex == completed`이면 진행 중, 나머지는 예정 상태다. 데모 전체 완료 시에는 마지막 퀘스트를 포함하여 완료 상태로 표시한다. 인덱스만으로 이미지 파일을 추측하지 않고 **퀘스트 ID로 이미지를 찾고, 실제 상태로 표시 밝기를 결정**한다.

선택한 퀘스트를 이전·다음 버튼으로 바꾸거나 진행도가 변경될 때 이미지를 다시 표시하고 상태별 밝기도 함께 갱신한다. 상세창을 닫고 다시 열거나 세이브를 불러온 뒤에도 동일하게 동작해야 한다.

# 5. 밝기 구현 원칙

먼저 기존 PNG의 지나치게 어두운 부분을 보정하여 **기본 이미지 자체의 피사체가 식별 가능**하게 만든다. 현재 진행 중 퀘스트는 추가 암전 없이 보정된 이미지를 보여 준다. 완료·예정 상태에는 이미지 위의 약한 반투명 암부 또는 해당 `Image`의 상태별 tint 중 기존 UI와 잘 맞는 한 가지 방법으로 미세한 차이를 준다.

- 암부는 썸네일 이미지 영역에만 적용한다. 프레임, 문구, 보상, 상태 아이콘과 버튼은 어둡게 하지 않는다.
- 이미 어두운 원본에 추가 암부를 여러 겹 씌우지 않는다. 감쇠 값은 Game View에서 비교하여 최소한으로 조정한다.
- 새 화면 밝기 설정이나 Save 필드를 만들지 않는다. 필요한 경우 `QuestThumbnailView`의 표시 인자와 작은 UI 내부 처리만 확장한다.
- 퀘스트 상태가 바뀌어도 원본 PNG를 런타임에 다시 생성하지 않는다. 하나의 퀘스트 이미지를 상태에 맞춰 표현한다.
- `Image.preserveAspect`와 기존 여백, 프레임 위계 및 raycast 동작을 유지한다.

# 6. 조명 퀘스트의 예외 연출

`demo.quest.place_light_at_depth` / `place_light_at_depth.png`는 광산 전체를 균일하게 밝히지 않는다.

- 조명 범위 바깥의 광산은 어둡게 남긴다.
- 조명 안쪽의 광부, 지형, 시설 또는 이동 경로는 분명히 밝게 보인다.
- 밝은 영역과 어두운 영역의 경계를 통해 **조명 설치의 효과**가 작은 썸네일에서도 즉시 전달돼야 한다.
- 완료·예정 상태의 약한 UI 암부를 적용해도 밝은 영역의 정보가 사라지지 않아야 한다.

이는 조명 장면의 **이미지 내부 조명 연출**에 대한 예외다. 4절의 퀘스트 상태별 표시 규칙도 함께 적용한다.

# 7. 제작 방식과 시각적 일관성

기존 광부·드론·엘리베이터·시설·광산 배경 에셋과 게임의 색감, 실루엣, 스케일을 참고한다. 네 지정 장면은 정면 플레이 화면의 단순 복제보다 **해당 상황을 겪는 애니메이션의 한 프레임 같은 구도**로 만든다. 인물의 행동과 시선, 화면의 진행 방향, 한 가지 핵심 순간을 선명하게 잡는다.

실제 캡처가 연출에 적합한 퀘스트는 Game View 캡처를 개선해서 써도 된다. 새 구도가 필요한 장면은 기존 에셋을 조합하거나 이를 근거로 이미지를 제작한다. 어느 방식이든 새 캐릭터 디자인, 다른 시대의 장비, 게임에 없는 UI·시설·색감을 임의로 도입하지 않는다. 원본 에셋이 표현하지 않는 표정이나 동작은 게임의 캐릭터 형태를 유지하면서 해당 컷에 필요한 범위에서만 제작한다.

핵심 피사체는 썸네일 프레임에 들어간 최종 크기에서 확인한다. 원본 화면에서만 보이는 작은 얼굴 표정이나 모션 표현에 의존하지 않는다. 문자와 퀘스트 제목은 PNG에 굽지 않는다.

# 9. 나머지 썸네일 처리

기존 18개 PNG를 모두 상세창에서 점검한다. 위 네 장과 조명 장면 외의 썸네일은 **상태별 밝기 규칙과 가독성 개선**을 적용한다. 피사체가 보이지 않거나 퀘스트의 행동이 불명확한 이미지에 한해 원본을 보정하거나 게임 에셋 기반 컷으로 교체한다. 각 장면을 일괄적으로 새 그림으로 바꾸지는 않는다.

기존 이미지가 적합하면 파일과 참조를 유지한다. 누락 이미지는 기존 Placeholder 동작을 유지하고 어떤 ID가 누락되었는지 결과 보고에 기록한다.

# 10. Asset 배치와 Import

현재 폴더와 기존 파일명을 우선 사용한다.

```text
sub-terra/Assets/_Project/Art/UI/Gameplay/Quest/Thumbnails/
  upgrade_drill_speed.png
  travel_to_surface.png
  return_to_mine.png
  unlock_deep_zone.png
  place_light_at_depth.png
  ... 나머지 기존 퀘스트 이미지
```

기존 `PromptB1072QuestThumbnailBuilder`의 ID → 파일명 매핑과 Sprite 참조를 보존한다. PNG 교체 시 투명도와 색상 가장자리를 확인하고, 기존 Sprite Import 정책(`Sprite (2D and UI)`, `Single`, `Full Rect`, 비활성 mipmap 등)을 비교한다. 압축 때문에 어두운 부분이 뭉개지거나 얇은 조명이 사라진다면 **대상 이미지에 한하여** 설정을 조정하고 Game View에서 확인한다. 다른 공용 UI 에셋의 Import 설정은 건드리지 않는다.

기존 PNG와 `.meta`를 불필요하게 삭제 후 재생성하지 않는다. Unity의 연결 상태가 이미 유효하다면 씬 전체를 다시 저장하지 않고 이미지 교체와 필요한 UI 코드만 적용한다.

---

# 11. 상태 전달과 갱신 경로

권장 데이터 흐름:

```text
DemoObjectivePresenter.RenderDetails
  ├─ 퀘스트 ID
  ├─ isCleared / isCurrent
  └─ DemoObjectiveView.ApplyQuestDetailsVisual
       └─ QuestThumbnailView: 해당 Sprite + 상태별 밝기
```

`ApplyQuestDetailsVisual`에는 두 상태값이 이미 전달된다. 이를 재사용하여 `QuestThumbnailView`에 필요한 상태만 전달한다. 완료도 현재도 아닌 경우는 예정으로 해석한다. 퀘스트 이미지 목록을 새로 복제하거나 전역 상태를 추가하지 않는다.

첫 열기, 이전·다음 탐색, 퀘스트 완료 직후 상세창이 열린 상태, 재진입, 세이브 복원 및 데모 전체 완료를 확인한다. 상태 갱신 시 보상·진행도·탐색 버튼의 기존 갱신 경로가 끊기지 않아야 한다.

# 12. 기존 시스템 보존 및 변경 금지

- 기존 상세창 레이아웃, 버튼과 프레임을 재설계하지 않는다.
- 퀘스트 조건, 완료 순서, 보상 지급, ID, Save DTO를 변경하지 않는다.
- 관계없는 Main Menu, Surface Base, 설정창, 인벤토리, 우측 메뉴 및 공용 TMP·폰트 에셋을 변경하지 않는다.
- `ProjectSettings/*`, `Packages/manifest.json`, `Packages/packages-lock.json` 또는 Unity 버전을 변경하지 않는다.
- 기존 Gameplay Scene을 썸네일 캡처용으로 영구 수정하지 않는다. 필요한 컷은 별도 안전한 촬영 환경 또는 편집 방식으로 제작한다.
- 씬·프리팹 YAML을 직접 편집하지 않는다. 참조 변경이 꼭 필요하면 Unity Editor와 기존 전용 빌더 방식을 사용한다.

# 13. 구현 순서

## Phase 1 — 기준 확인

18개 PNG를 실제 상세창에 띄워 현재 상태별 밝기를 비교한다. 원본 이미지와 UI 표시 효과 각각의 원인을 기록한다. 기존 게임 에셋과 네 장면의 레퍼런스를 정한다.

## Phase 2 — 이미지 개선

기존 이미지의 어둠과 대비를 교정한다. 조명 컷의 안팎 명암을 정리하고 네 지정 장면을 개별 제작한다. 가독성이 부족한 기타 컷만 추가 보정한다.

## Phase 3 — 상태별 표시

기존 `isCleared`·`isCurrent`를 썸네일 View에 전달하고 현재·완료·예정 상태의 밝기를 연결한다. 프레임 및 다른 UI에 암부가 퍼지지 않도록 한다.

## Phase 4 — 통합 확인

Unity에서 Sprite 참조와 인덱스 경계를 확인한다. `Bootstrap → 새 게임 → 탐사` 경로에서 상세창을 열고 탐색하며 상태 변화와 화면 결과를 점검한다.

# 16. 실패 조건

다음 중 하나라도 있으면 완료로 보지 않는다.

- 현재 퀘스트 이미지가 여전히 지나치게 어둡거나 완료·예정 이미지의 핵심 요소가 보이지 않는다.
- 조명 범위 안팎의 차이가 없어 조명의 역할이 전달되지 않는다.
- 네 지정 장면 중 요구된 인물·드론·환경 또는 동작이 빠진다.
- 드릴의 모션 블러가 인물이나 장면 전체의 식별성을 해친다.
- 지상 이동과 탐사 재개가 같은 순간처럼 보인다.
- 퀘스트 탐색·완료 후 Sprite는 바뀌는데 밝기 상태가 이전 퀘스트에 남는다.
- 썸네일 변경 때문에 UI 레이아웃, 퀘스트 데이터, 보상 또는 다른 HUD가 달라진다.
- PNG 참조 또는 `.meta` GUID가 끊겨 빈 이미지가 표시된다.

# 19. 최종 구현 판단 원칙

**썸네일의 상태는 기존 퀘스트 데이터가 결정하고, 이미지 자체는 해당 퀘스트의 상황을 읽히게 해야 한다.** 진행 중 퀘스트를 선명하게, 완료·예정 퀘스트를 살짝 어둡게 보여 주되 어느 상태에서도 어둠 때문에 장면 정보가 사라지지 않도록 한다. 네 지정 장면은 게임의 캐릭터와 에셋을 기반으로 개별 사건의 한순간을 표현한다. 기존 상세 UI의 연결과 게임 흐름은 유지한다.
