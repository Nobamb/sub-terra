# Sub-Terra — 조작 방식 선택 UI·입체 홀로그램 키보드 개편

Claude Sonnet 5.5가 조사·설계·구현·검증을 직접 수행해줘. 다른 Agent에 위임하지 마.
첨부한 현재 조작 UI와 연결선 참고 이미지를 확인하고 아래 요구사항을 적용해줘.
이번 작업은 기존 조작 방식 선택 UI의 개선이며 새로운 자유 키 리바인딩 시스템을 만드는 작업이 아니야.
PlayMode 테스트 코드는 필요한 만큼 추가·수정하되 이번에는 실행하지 마.
작업 중·완료 후 Editor PlayMode 진입, batchmode PlayMode 실행, 수동 플레이를 하지 마.
컴파일·관련 EditMode 테스트는 실행하고 PlayMode 테스트는 컴파일·정적 검토까지만 수행해줘.
자동 검증 메뉴가 PlayMode까지 실행하지 않는지 확인해줘. 커밋은 사용자 확인 없이 하지 마.

## 1. Context와 조사 범위

CLAUDE.md, init/rule.md와 실제 라우팅에 해당하는 UI·코드·테스트·에셋 규칙을 먼저 읽어줘.
저장소 루트와 Unity 프로젝트 루트(sub-terra/로 알려져 있음)를 실제 구조로 확인해줘.
git status로 사용자 기존 변경을 파악하고 작업 범위 밖 변경은 보존해줘.
전체 프로젝트를 무작정 훑지 말고 다음 문구·관련 설정/입력 코드부터 검색해줘.
- '키 조작 방식', '키보드 · 이동 / 채굴', '선택 후 돌아가기', 조작 방식 1/3.
- 이전/다음 선택, 현재 조작 프리셋, 변경 즉시 저장, 저장 후 복원.
- 현재 키보드 View·Builder·Prefab·관련 테스트·모달 입력 차단.
실제 3개 조작 방식과 각 키/마우스 기능을 확인하고 현재 화면 설명과 실제 바인딩을 대조해줘.
프레임·폰트·청록색·버튼은 현재 개선된 HUD·시설 이름표·다른 설정 팝업을 참고해줘.
발견한 경로·저장/입력 계약·재사용 API를 짧게 정리한 뒤 구현하고 존재하지 않는 파일명을 가정하지 마.

## 2. 목표와 유지할 계약

평평한 키보드 안내창을 '홀로그램 프레임이 조립되고 입체 키보드가 착지하는 조작 단말'로 바꿔줘.
키 호버 시 실제로 눌린 듯한 연출과 연결선·작은 기능 시연 화면을 제공해줘.
기존 3가지 조작 방식의 선택·이전/다음 이동·즉시 저장·복원·돌아가기 동작을 유지해줘.
페이지의 순환/끝 처리와 실제 적용 시점은 기존 코드 계약을 따라줘.
애니메이션 완료를 기다렸다가 설정을 적용하지 말고 기존 시점에 즉시 적용·저장해줘.
호버·자동 시연·영상 재생은 표시 효과이며 실제 이동·점프·채굴·저장을 호출하지 않아.
실제 입력 바인딩·게임플레이·채굴 판정·저장 형식·전역 설정 체계는 변경하지 마.
현재 창이 모달이라면 기존 게임 입력 차단·일시정지·포커스·닫기 계약을 유지해줘.

## 3. 전체 레이아웃과 홀로그램 디자인

기존 중앙 팝업 구조를 바탕으로 상단 제목/페이지, 중앙 키보드, 측면 시연 화면, 하단 설명/버튼을 배치해줘.
제목은 '키 조작 방식 1 / 3' 형식을 유지하고 실제 현재 선택에 맞춰 갱신해줘.
프레임은 어두운 남색 반투명 패널·얇은 흰색/청록색 선·각진 모서리 브래킷으로 구성해줘.
조립 순간에는 흰빛을 강조하고 정착 후에는 기존 프로젝트의 청록색 톤으로 안정시켜줘.
외곽 발광은 절제하고 작은 장식 점/선은 읽기 쉬운 수준만 사용해줘.
키보드를 크게 기울이는 원근 표현은 피하고 키 이름이 선명한 정면 기반의 얕은 입체감으로 해줘.
이전/다음 버튼은 같은 프레임 언어로 통일하고 클릭 영역·키보드/패드 탐색 정책을 유지해줘.
하단에는 현재 조작 방식의 짧은 설명, '변경 즉시 저장' 안내, '선택 후 돌아가기' 버튼을 정리해줘.
장문의 중복 설명은 줄여도 되지만 기능·적용 방식에 관한 기존 의미를 누락하지 마.
시연 화면은 키보드 옆의 고정 영역에 두고 키·페이지 버튼·돌아가기 버튼을 가리지 않게 해줘.
해상도·CanvasScaler·안전 여백을 고려해 전체가 화면 안에 들어가고 설명이 잘리지 않게 해줘.

## 4. 입체 키캡과 기능 색상

키캡은 윗면·아래 옆면·상단 하이라이트·바닥 그림자를 분리해 얕게 튀어나온 느낌으로 만들어줘.
윗면은 진남색, 옆면은 더 어둡게, 위쪽 모서리는 가는 흰빛으로 표현해줘.
정착 상태의 옆면 깊이는 약 3~5 디자인 px를 기준으로 실제 크기에 맞춰 조정해줘.
현재 페이지에서 사용되는 이동 키/방향키는 청록색, 채굴 키/마우스 버튼은 금색·주황색으로 강조해줘.
점프 키는 읽기 쉬운 별도 밝기/청록 계열로 구분하고 의미 없는 추가 색상은 늘리지 마.
사용하지 않는 키는 어둡게 유지하고 기능 미리보기를 만들지 마.
Space·Enter·방향키 등은 현재 안내 배열과 식별성을 유지하고 필요 없는 전체 키보드를 추가하지 마.
키 문자·기호·설명은 윗면의 자식으로 배치해 윗면과 함께 움직이게 해줘.
마우스 클릭의 큰 설명 상자는 작은 홀로그램 마우스와 왼쪽 버튼 강조로 개선해줘.
키캡과 마우스의 기능 표시는 현재 프리셋의 실제 바인딩 데이터에서 가져와줘.

## 5. 최초 등장 — 프레임 조립·낙하·착지

전체 약 0.80초를 기준으로 아래 순서를 겹쳐서 자연스럽게 구성해줘.
- 0.00~0.18초: 주변에서 작은 흰색 사각 윤곽·ㄱ자 조각이 부분적으로 나타남.
- 0.12~0.32초: 조각이 모서리·테두리로 이동해 사각 프레임을 완성함.
- 0.25~0.48초: 프레임 내부 위쪽에서 키보드가 아래로 빠르게 내려오며 드러남.
- 0.48~0.65초: 키보드가 한 번 짧게 바운스하고 개별 키캡이 눌렸다 복귀함.
- 0.60~0.80초: 제목·기능 설명·하단 요소가 점등하며 정착함.
프레임 조각은 소수의 재사용 그래픽으로 구성하고 화면 전체에 많은 파티클을 뿌리지 마.
키보드 낙하는 마스크 밖에서 시작하고 표시 영역에 들어오며 드러나게 해줘.
낙하·착지는 약 20~30px 이동, 3~6px overshoot를 시작값으로 화면 크기에 맞춰 조정해줘.
키캡은 줄별 약 0.02초 시차로 짧게 눌렸다 복귀하고 Space는 약간 늦게 정착하게 해줘.
착지 순간 키보드 아래에 얇은 청록빛이 한 번 퍼지게 하고 반복 바운스는 넣지 마.
마지막에는 모든 위치·scale·알파가 정확히 기준값으로 복원되게 해줘.
등장 중 돌아가기·페이지 전환 요청은 기존 UX에 따라 처리하고 전체 0.8초 입력 잠금을 강제하지 마.

## 6. 키 호버 눌림 — 반드시 함께 구현

기능 키 호버 진입 시 약 0.08초 동안 윗면을 2~3 디자인 px 내려 눌린 상태로 만들어줘.
옆면 깊이와 그림자 간격을 함께 줄이고 키 테두리/기능 색을 살짝 밝히게 해줘.
글자·기호도 윗면과 함께 이동하고 키 전체가 통째로 떠다니는 느낌을 피하도록 해줘.
호버 유지 중에는 눌린 상태를 유지하며 반복해서 들썩이지 마.
호버 해제 시 약 0.12초로 복귀하고 아주 약한 탄성 한 번만 주며 정확한 기준 위치에 정착해줘.
빠르게 키 사이를 이동하면 이전 키는 복귀하고 새 키만 눌리게 해줘.
시각 자식만 움직이고 호버 판정 Rect는 고정해 눌림 때문에 enter/exit가 반복되지 않게 해줘.
호버는 안내 표시이며 조작 방식 선택·저장·실제 게임 입력을 발생시키지 마.
기존 키 클릭 기능이 있으면 보존하고 새로운 키 리바인딩/게임플레이 클릭 기능은 만들지 마.

## 7. 연결선·영상창 켜짐·호버 전환

호버 눌림은 즉시 시작하고 같은 키에 약 0.15초 머물렀을 때 연결선과 시연을 시작해줘.
키 모서리의 작은 흰색/청록색 점에서 얇은 선이 약 0.10~0.14초에 걸쳐 뻗어나가게 해줘.
선은 한두 번 꺾이는 각진 형태로 고정된 시연 화면까지 연결하고 다른 키의 문자를 가리지 않게 해줘.
연결선 시작점은 키 윗면의 움직임을 따라가고 화면 끝점은 시연 영역에 고정해줘.
선 끝에 수평 빛 → 위아래로 펼쳐지는 직사각형 → 짧은 스캔 효과 → 영상 재생 순서를 적용해줘.
화면 켜짐은 약 0.15초, 영상 아래에는 '왼쪽 이동' 같은 짧은 기능명을 한 줄만 표시해줘.
영상창은 한 번에 하나만 활성화하고 키마다 별도 창/재생기를 생성하지 마.
다른 기능 키로 이동하면 기존 창은 유지하고 새 키의 호버 확인 후 선과 콘텐츠만 짧게 교체해줘.
새 후보 키의 0.15초 대기 중에는 이전 영상이 다른 키의 설명처럼 보이지 않도록 흐리거나 일시정지해줘.
후보가 바뀌면 이전 지연 요청을 취소하고 마지막 호버 대상만 표시해줘.
기능 키 전체에서 벗어나면 짧은 약 0.10초 유예 후 영상창을 수평선으로 접고 선을 키 쪽으로 회수해줘.
키에서 다른 키로 빠르게 이동할 때 전체 TV 켜짐을 매번 재시작하지 마.
시연 패널·연결선은 raycastTarget=false로 하고 화면 위를 지나도 호버를 가로채지 않게 해줘.
페이지 전환·닫힘·disable 시에는 호버 대상·지연·선·영상 상태를 즉시 정리해줘.

## 8. 짧은 기능 시연 콘텐츠

GIF는 '짧은 동작을 반복하는 기능 영상'이라는 의미야. 파일 형식은 프로젝트에 적합한 기존 방식으로 구현해줘.
기존 캐릭터·광산·시설 스프라이트/애니메이션을 활용한 격리된 UI 시연 또는 기존 짧은 영상 에셋을 사용해줘.
화면에는 실제 게임과 같은 캐릭터·블록·사다리 모습이 보이게 하고 임의의 다른 게임 영상을 넣지 마.
PlayMode 촬영이 금지된 이번 작업에서 시연 영상을 얻으려고 PlayMode에 진입하지 마.
새 런타임 GIF 디코더·외부 패키지·별도 게임 씬/실시간 게임 카메라는 추가하지 마.
현재 기능 데이터에서 시연 종류를 결정하고 같은 기능의 여러 키는 콘텐츠를 재사용해줘.
- A/D 또는 대응 키: 캐릭터의 왼쪽/오른쪽 이동.
- W/S 또는 대응 키: 실제 계약에 맞는 사다리 위/아래 이동.
- Space 또는 대응 키: 한 번 점프.
- Enter 또는 대응 키: 바라보는 방향의 블록 채굴.
- 마우스 왼쪽 버튼: 선택한 블록 강조 후 해당 블록 채굴.
위 목록은 현재 화면 기준 예시이며 다른 프리셋은 실제 바인딩을 따라 정확히 보정해줘.
시연은 약 1~2초 한 동작과 짧은 휴지 구간으로 반복하고 화면 비율은 약 16:9로 유지해줘.
실제 플레이어·월드·Economy·Input 이벤트를 호출하지 않는 표시 전용 애니메이션이어야 해.
동작 시작/끝의 연결을 자연스럽게 하고 화면이 바뀌면 이전 콘텐츠를 정지·초기화해줘.
리소스 부족으로 특정 동작을 구현하지 못하면 완성된 영상인 것처럼 보고하지 말고 부족한 에셋·대체 구현을 명시해줘.

## 9. 자동 시연·페이지 교체·퇴장

최초 등장 후 잠시 유휴 상태면 기능 키를 한 개씩 짧게 눌러 조작 예시를 보여줘.
기능별 시연 사이에 쉬는 시간을 두고 여러 키·영상창을 동시에 움직이지 마.
자동 시연은 키 눌림/점등 중심으로 절제하고 호버 영상창을 강제로 열지 마.
호버·버튼 포커스가 생기면 자동 시연을 멈추고 해당 안내가 끝난 뒤 유휴 시간을 다시 계산해줘.
페이지 변경 시 외곽 프레임은 유지하고 내부 키보드/강조/설명만 약 0.18~0.25초로 교체해줘.
페이지별로 실제 키 배열이 같으면 배열을 재생성하지 않고 바인딩·강조만 갱신해줘.
빠른 연타에서는 마지막 선택 프리셋을 정확히 표시하며 오래된 시연이 새 페이지에 나타나지 않게 해줘.
돌아가기 시 약 0.18초로 키보드·콘텐츠가 소등되고 프레임이 작은 조각으로 짧게 분해되며 사라지게 해줘.
정상 닫기 연출과 즉시 강제 종료를 구분하고 설정 저장은 퇴장 완료에 의존하지 않게 해줘.

## 10. 구조·성능·변경 범위

기존 UGUI/TMP·공유 폰트·기본 그래픽·기존 에셋을 활용하고 생성 이미지에 UI 구현을 의존하지 마.
키보드 배열/기능 데이터, 순수 Timeline 계산, 표시 State, 얇은 View를 프로젝트 방식에 맞춰 분리해줘.
등장·페이지 전환·키 눌림·자동 시연의 우선순위를 정해 위치/알파를 서로 덮어쓰지 않게 해줘.
unscaled 시간 기준으로 동작하고 일시정지 상태에서도 기존 설정창과 일관되게 반응하게 해줘.
Frame/Keycap/Connector/Preview의 그래픽을 재사용하고 매 프레임 오브젝트·머티리얼·로그를 만들지 마.
키 이름·기능명은 바인딩/대상 변경 시만 갱신하고 표시 중 불필요한 Layout 재빌드를 줄여줘.
장식은 raycastTarget=false, 기능 키의 안정된 호버 영역과 기존 버튼만 필요한 입력을 받게 해줘.
영상 재생은 활성 창 하나로 제한하고 숨김/닫힘에서 재생·코루틴·이벤트 구독을 정리해줘.
새 패키지·DOTween·URP 후처리·ProjectSettings/Packages 변경은 금지해줘.
UnityEngine.Object는 명시적 null 비교, 주석은 짧은 한국어로 작성해줘.
변경은 조작 UI 코드·전용 Builder/Prefab·표시 에셋·관련 테스트·필요한 배선으로 제한해줘.
폰트 글리프는 기존 절차에 따라 최소 추가하고 범위 밖 Scene·Prefab·폰트 dirty 저장을 막아줘.
필요한 Builder만 실행하고 사용자 기존 변경을 보존하며 자신의 의도하지 않은 변경만 정리해줘.

## 11. 테스트 작성·검증·완료 보고

EditMode로 프리셋→기능 매핑·문구·현재 페이지·선택/저장 계약과 순수 상태/타임라인을 검증해줘.
등장 정착·키 눌림/복귀·시차·연결선 기준점·호버 대기/취소·빠른 대상 교체를 검증해줘.
자동 시연 중단/재개·페이지 변경 후 이전 영상 차단·단일 창·정리/재열기 상태를 검증해줘.
관련 PlayMode 테스트도 추가·수정해 View 배선·호버 영역·저장/복원·입력 차단·라이프사이클을 다뤄줘.
컴파일·관련 EditMode만 실행하고 PlayMode 테스트는 컴파일·정적 검토까지만 수행해줘.
실행할 수 없는 항목은 시도·원인·미수행 범위를 보고하고 실행하지 않은 테스트를 통과로 쓰지 마.
마지막에 git status, git diff --stat와 실제 diff를 검토해줘.
변경 파일·기존 계약 보존·최종 타이밍·입체/호버 구현·시연 콘텐츠 제작 방식과 재사용 에셋을 보고해줘.
컴파일·EditMode 결과, PlayMode 테스트 작성/수정·컴파일 여부, 범위 밖 변경·남은 위험을 구분해줘.
PlayMode 실행·수동 플레이·실제 화면/호버 가독성·Profiler 검증은 미수행으로 명시해줘.
PlayMode가 필요한 GIF·실플레이 캡처를 만들거나 시연 콘텐츠를 실플레이 검증 영상으로 보고하지 마.
