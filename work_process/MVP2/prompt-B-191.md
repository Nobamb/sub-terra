## A. 목록 정렬
- 큰 목록 창의 검색창(`시설명 검색`) 옆에 드롭다운을 둔다. 항목은 4개:
  `기본 순`(지금 레일·목록 순서) / `기본 역순` / `가나다순`(시설 표시 이름) / `가나다 역순`.
- 기본값 `기본 순`. 수량·무게·희귀도 같은 자원 전용 정렬은 넣지 않는다.
- 검색으로 걸러진 결과를 정렬한다. 정렬을 바꿔도 검색어는 유지한다.
- 건설 모드를 닫았다 다시 열면 검색어는 비우고 정렬은 `기본 순`으로 돌아간다.
- 드롭다운이 열려 있을 때 B/C/이동 키가 월드로 새지 않게 검색창과 같은 `UiPauseGate` 규칙을 따른다. 드롭다운 목록은 큰 창 위에 보이고 잘리지 않아야 한다.

## B. 큰 목록·상세 TV 켜짐
- `>>`로 큰 목록 창이 나타날 때 기존 `TerminalWindowOpenMotion`(가로줄 → 위아래로 펼침)을 재생한다.
- 목록에서 시설을 골라 상세가 나타날 때도 같은 연출을 쓴다. 다만 큰 창이 이미 열려 있으면 창 전체를 다시 켜지 말고 **상세 페이지에만** 짧고 가볍게 적용한다.
- 상세에서 `시설 목록`으로 돌아갈 때는 연출을 다시 하지 않는다.
- `<<`로 접을 때는 거꾸로 접히면 좋고, 바로 닫혀도 된다.
- 연출 중에도 입력은 막지 않는다. `>>`/`<<`/B를 빠르게 연타해도 창이 반쯤 남거나 꼬이면 안 된다.
- 레일 자체는 지금의 왼쪽 슬라이드(`BuildingModeSlideMotion`)를 유지한다. 레일에 TV 켜짐을 씌우지 않는다.
- 모션 감소(`AccessibilityPreferences.ReduceMotion`)가 켜져 있으면 인벤토리·설정과 같은 규칙을 따른다.

## C. 호버 깜빡임 방지
- 지금: 레일 시설 버튼을 호버하다 다른 버튼으로 옮기면, 버튼 사이를 지나는 순간 `hintChip`이 다시 켜졌다 꺼진다.
- 바꿀 것: 시설 버튼에서 마우스가 떠나도 안내 창을 바로 켜지 않는다. **`HintReshowDelay = 0.3f`★** 동안 다른 시설 버튼을 호버하지 않았을 때만 그 뒤에 켠다.
- 그 사이 다른 버튼을 호버하면 대기를 취소하고 안내 창은 숨긴 채 새 이름표로 바로 넘어간다.
- 대기 시간은 인스펙터에서 바꿀 수 있는 `[SerializeField]` 값으로 둔다(기본 0.3초). 시간 계산은 `Time.unscaledDeltaTime` 기준으로 한다.
- 시설을 클릭해 고르면 지금처럼 바로 카드가 뜬다. 건설 모드를 닫거나 `>>`로 펼치면 대기를 즉시 취소한다.
- 안내 창이 다시 뜰 때 새 연출·효과음은 넣지 않는다.

## C2. 검색 즉시 반영 + 초성 검색
- 지금은 한 글자(단어)가 완성된 뒤에야 걸러지고, `ㅅ`·`ㅅㄷ`처럼 자음만 치면 아무것도 안 걸린다.
- 시설명에서 초성 문자열을 만들어(가~힣은 `(code-0xAC00)/588`로 초성 인덱스) 비교한다. 검색어의 각 글자가 자음(ㄱ~ㅎ)이면 이름의 초성과, 완성 글자면 그 글자 그대로와 맞춰서, 이름 안 어딘가에 **이어서** 맞으면 통과. 예: `ㅅㄷ`·`사ㄷ`·`사다` → `사다리`.
- 쌍자음 초성(ㄲ·ㄸ·ㅃ·ㅆ·ㅉ)도 그대로 맞춘다. 공백·대소문자 무시는 유지한다.
- 짧은 용도 설명은 지금처럼 일반 글자 포함 검색만 유지한다(초성은 시설명만).
- **조합 중 글자도 반영**: 검색창이 포커스일 때 `searchField.text` + IME 조합 문자열(`Input.compositionString`, 프로젝트가 새 Input System이면 그에 맞는 조합 문자열 API)을 합쳐 검색어로 쓴다. 조합 문자열이 바뀌면 매 프레임 한 번만 다시 거른다(같으면 다시 계산하지 않음).
- 판정 로직은 순수 함수로 `BuildingMenuDisplayFormatter`(또는 공용 `KoreanSearch` 헬퍼)에 두고 EditMode 테스트를 추가한다: `ㅅ`, `ㅅㄷ`, `사ㄷ`, `사다`, 맞지 않는 `ㄷㅅ`, 빈 검색어, 공백 섞인 검색어.
- 결과가 없으면 지금 빈 결과 안내를 쓰고, A 정렬과 함께 동작한다.

## C3. 취소·설치 완료 문구 제거
- `CancelSelection()`의 취소 문구, `OnPlacementChanged()`의 `Placed` 설치 완료 문구를 둘 다 `SetStatusMessage(string.Empty)`로 바꾼다. 상태 칸이 사라지고 기본 시설 선택 안내(C의 지연 규칙 따름)로 돌아가야 한다.
- Preview 취소·이동 취소·B-181 취소음, 설치 동작·설치음은 그대로 둔다.
- 설치 불가 이유(`자원이 부족합니다`, 위치 불가 등) 문구는 바꾸지 않는다. 두 문구를 확인하는 기존 테스트가 있으면 "문구 없음"으로 고친다.

## C4. 건설 UI를 드론 말풍선 위로
- 지금 건설창은 자체 Canvas가 없어 `HUDCanvas`(0)를 따르고, 말풍선(30_000)에 레일·카드·큰 창·오른쪽 위 안내가 가려진다.
- `BuildingMenu` 루트(또는 `PanelRoot`)에 Canvas + `GraphicRaycaster`를 붙이고 `overrideSorting = true`, `sortingOrder`를 **`DroneDialogueSocket.OverlaySortingOrder + 100`**(지금 기준 30_100)★으로 둔다. 숫자를 직접 박지 말고 상수를 참조한다(#287에서 말풍선 값이 바뀔 예정).
- 퀘스트 팝업(30_500)·긴급 구출(31_000)·일반 팝업(32_100~)·설정창(32_760)보다는 아래여야 한다. EditMode 테스트로 이 순서를 확인한다.
- 오른쪽 위 시설 선택 안내가 `BuildingMenu` 밖에 있으면 같은 Canvas 아래로 옮기거나 같은 값을 준다. 위치는 보고서에 적는다.
- `HUDCanvas` 전체의 `sortingOrder`는 올리지 않는다. 빌더 `PromptB188BuildingModeBuilder`에서 Canvas와 값을 맞춘다.
- 버튼·검색창·드롭다운 클릭과 창 밖 월드 클릭이 전과 같이 동작해야 한다.

7. 정렬 드롭다운에서 4가지를 바꿔 보고 순서가 맞는지 본다. 검색어를 넣은 채 정렬을 바꿔도 검색어가 남는지 본다.
8. 검색창에 `ㅅ` 한 자만 쳐도 바로 걸러지는지, `ㅅㄷ`·`사ㄷ`로 `사다리`가 나오는지 본다. 한 글자를 조합하는 중에도 키를 누를 때마다 목록이 바뀌는지 본다.
9. 시설을 골랐다가 취소해 본다. `건설 선택을 취소했습니다`가 뜨지 않고 기본 안내로 돌아가는지, 취소음은 그대로 나는지 본다.
10. 시설을 하나 설치해 본다. `시설 설치가 완료되었습니다`가 뜨지 않고 기본 안내로 돌아가는지, 설치음은 그대로 나는지 본다. 자원이 모자랄 때 `자원이 부족합니다`는 그대로 뜨는지 본다.
11. 건설 모드를 연 채 드론이 말하게 한다(드론 근처로 가거나 퀘스트 진행). 레일·작은 카드·`>>` 큰 창·오른쪽 위 안내가 말풍선보다 앞에 보이는지 본다.
12. 그 상태에서 설정창을 열면 설정창이 건설 UI보다 앞에 보이는지 본다.
13. 정렬을 바꿔도 왼쪽 레일 아이콘 위치는 그대로인지 본다.
14. 목록에서 시설을 고르면 상세가 TV 켜지듯 나타나고, 뒤로가기로 목록에 돌아올 때는 연출이 다시 나오지 않는지 본다.
15. `>>`/`<<`/B를 빠르게 연타해도 창이 반쯤 남지 않는지 본다.
16. 드롭다운·검색창에 있는 동안 B/C/이동 키가 게임으로 새지 않는지 본다.
17. 창 밖 칸을 캐고, 시설을 골라 설치까지 해 본다.
18. 닫았다 다시 열면 검색어가 비고 정렬이 `기본 순`인지 본다.
19. 새 효과음이 없고, Unity Console에 새 빨간 오류·노란 경고가 없는지 본다.
