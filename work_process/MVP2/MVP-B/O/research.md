# Phase O — 데모 동선·UI·밸런스·접근성

## 1. 개요

시스템을 개별 통과시키는 것과 처음 플레이하는 사람이 40m 데모를 막힘없이 이해하는 것은 다르다. 실제 입력 신호만으로 목표가 진행되고 위험/건설/귀환 선택이 읽히도록 다듬는다.

## 2. 작업 목표

- 상층 채굴→수직 이동→구조 위험→가스→전진기지→심층 신호→귀환→업그레이드 흐름을 완주한다.
- 목표 UI가 Debug 신호가 아닌 실제 성공 이벤트에만 반응한다.
- 건설/위험/드론/상호작용 UI 우선순위와 레이아웃을 정리한다.
- 채굴 시간, 전력, 분포, 비용, 경고 빈도를 플레이 테스트로 조정한다.

## 3. 구현 범위

- 실제 월드 목표 배치와 안전/위험 경로
- 조작 안내, 목표, 상호작용 prompt와 실패 이유
- UI safe area, 해상도, 폰트 크기, 색상 외 구분
- 기본 SFX/particle/screen feedback와 음량 설정
- 튜토리얼 skip/replay 또는 방해 최소화 정책
- 밸런스 데이터와 플레이 테스트 기록

## 4. 권장 구현 방향

1. 기존 DemoObjective 시스템을 실제 Gameplay/App 성공 이벤트에만 연결한다.
2. 긴급 위험 UI가 튜토리얼/일반 대사를 가리도록 priority를 고정한다.
3. 수치는 코드가 아닌 데이터에서 조정하고 변경 이유를 기록한다.
4. 최소 3회 내부 완주와 처음 플레이 사용자 관찰을 분리한다.
5. 정식 아트보다 정보 계층, 실루엣, 입력 피드백을 우선한다.

## 5. 보안 및 안정성 기준

- Development debug 도구는 QA/Release에서 비활성화한다.
- 목표 강제 진행 경로가 일반 입력으로 노출되지 않는다.
- 해상도 변경이 UI 참조나 저장 상태를 바꾸지 않는다.
- 경고음/점멸/화면 흔들림에 음량·모션 감소 옵션을 제공한다.

## 6. 완료 기준

- 실제 입력만으로 최종 완주 시나리오를 수행할 수 있다.
- 목표가 순서 밖/실패 이벤트로 진행되지 않는다.
- 지원 해상도에서 핵심 HUD와 팝업이 겹치거나 잘리지 않는다.
- 밸런스 질문(탐사/귀환 고민, 위험의 전략성, 기지 효용, 드론 도움)에 플레이 기록으로 답할 수 있다.
