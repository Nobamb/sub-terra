# Phase G — 균열·부분 붕괴·피해 전 단계

## 1. 개요

현재 구조 시스템은 위험을 계산하고 임계 시 일부 타일을 제거하지만, 플레이어가 이해할 균열 예고와 낙석 위험, 붕괴 후 상태 변화가 부족하다.

## 2. 작업 목표

- 안정/주의/위험/붕괴 임박 단계를 시각·음향으로 구분한다.
- 위험 셀 주변에 균열 타일/overlay를 표시한다.
- Seed와 변경 상태가 같으면 같은 셀이 붕괴하게 한다.
- 붕괴가 Player 피해/행동불능 시스템에 전달될 이벤트를 제공한다.

## 3. 구현 범위

- 구조 점수 데이터와 단계 임계치
- Crack overlay/particle/screen shake/audio hook
- 결정론적 collapse candidate 선택
- 낙석 또는 타일 변경 표현과 충돌 갱신
- Support 설치/파괴 후 국소 재계산
- Collapse snapshot과 Gameplay event

## 4. 권장 구현 방향

1. 전체 Tilemap이 아니라 변경 cell 주변만 계산한다.
2. 균열 표현은 원본 타일 데이터와 분리된 Hazard/Overlay Tilemap을 사용한다.
3. 후보 정렬은 좌표와 Seed를 사용해 재현 가능하게 한다.
4. Collapse event는 cell 목록과 severity만 전달하고 App UI가 결과를 재계산하지 않는다.
5. 실제 Run 실패 판정은 L 단계가 소유한다.

## 5. 보안 및 안정성 기준

- 경계 암석과 전진기지 필수 코어를 붕괴 대상으로 선택하지 않는다.
- Support 영향 셀은 동일 계산에서 일관되게 제외/감점한다.
- Collider 갱신 전 Player를 타일 내부에 가두지 않는다.
- 화면 흔들림과 경고는 광과민/모션 감소 설정을 고려한다.

## 6. 완료 기준

- 넓게 채굴하면 단계적으로 균열이 증가한다.
- Support 설치 시 경고와 균열이 국소적으로 완화된다.
- 같은 Seed/변경 순서에서 붕괴 cell이 동일하다.
- 붕괴가 실제 타일/충돌/이벤트/Snapshot에 반영된다.
