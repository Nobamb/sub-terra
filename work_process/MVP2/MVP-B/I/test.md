# Phase I Agent Test

## 1. 정적 검증 항목

| ID | 테스트 항목 | 검증 방법 | 예상 결과 |
| :-- | :-- | :-- | :-- |
| I-S01 | 시설별 Prefab | BuildingData 참조 검사 | 공용 placeholder 0 |
| I-S02 | 필수 컴포넌트 | Prefab 검사 | BuildingInstance/기능 컴포넌트 존재 |
| I-S03 | 전력 데이터 | 카탈로그 검사 | 공급·소비·우선순위 유효 |
| I-S04 | UI 참조 | Outpost Panel 검사 | 상태/실패 이유 필드 연결 |
| I-S05 | 파생 상태 저장 금지 | DTO 검사 | isPowered 미저장 또는 무시 |

## 2. 기능 테스트 항목

### I-F01: 전력 연결과 우선순위

- **준비:** 공급보다 수요가 큰 네트워크
- **실행:** 코어와 여러 시설을 케이블로 연결한다.
- **예상 결과:** 우선순위와 ID 순서대로 결정론적으로 활성화된다.

### I-F02: 조명과 충전

- **준비:** 전력 연결된/끊긴 조명과 충전기
- **실행:** 시설을 사용한다.
- **예상 결과:** 연결된 시설만 시야/전력을 변경한다.

### I-F03: 보관함 왕복

- **준비:** Player Inventory와 빈 보관함
- **실행:** 입고 후 출고한다.
- **예상 결과:** 총 수량이 보존되고 이벤트가 요청당 한 번 발생한다.

### I-F04: 정산 멱등성

- **준비:** 광물이 든 보관함과 고정 request ID
- **실행:** 같은 정산 요청을 두 번 보낸다.
- **예상 결과:** 골드 지급과 광물 제거가 한 번만 발생한다.

### I-F05: 복원 후 재계산

- **준비:** 시설/케이블 설치 후 저장
- **실행:** 새 Runtime에 복원한다.
- **예상 결과:** topology로 전력이 재계산되고 UI가 일치한다.

## 3. 테스트 절차

1. Edit Mode에서 그래프와 멱등 거래를 검증한다.
2. Play Mode에서 각 실제 Runtime Prefab을 설치·상호작용한다.
3. 전력망 변경 시 rebuild 횟수를 기록해 프레임 폴링이 없는지 확인한다.

## 4. 검증 결과 요약

- **상태:** 미실행
- **모든 항목 통과 시:** Phase I 완료
- **실패 항목 존재 시:** topology, 공급/수요, 시설별 powered 상태를 기록한다.
