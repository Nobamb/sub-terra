# Phase J — 귀환·체크포인트·Run 수명주기

## 1. 개요

전진기지 App 서비스와 UI는 존재하지만, Mine에서 지상 또는 전진기지로 귀환하고 한 Run을 정산·종료하는 실제 상태 전이가 완결되어야 한다.

## 2. 작업 목표

- 탐사 시작, 활성 Run, 정상 귀환, 정산, 다음 탐사 상태를 명확히 한다.
- 시작 엘리베이터로 지상 귀환하고 전진기지 체크포인트를 사용할 수 있게 한다.
- 전진기지 상호작용 거리와 전력 상태를 실제 Runtime에서 검증한다.
- 귀환 시 자동 저장과 결과 UI를 한 번만 발생시킨다.

## 3. 구현 범위

- `RunLifecycleService` 또는 기존 State의 명시적 전이 API
- Current/Maximum Depth 업데이트
- Surface/Elevator/Outpost return target
- 체크포인트 활성화와 안전 spawn validation
- 정상 귀환 결과, 미정산/정산 화물 처리
- Scene transition 및 AutoSave 이유

## 4. 권장 구현 방향

1. Run 상태 전이는 App Service 한 곳에서 수행한다.
2. Gameplay는 도착/상호작용/거리 이벤트를 Shared DTO로 발행한다.
3. 귀환 대상은 실제 활성·접근 가능·안전 spawn이 확인된 경우만 선택한다.
4. Scene 전환 전 State 수집과 저장 요청 순서를 고정한다.
5. 실패 귀환은 L 단계의 별도 전이로 구분한다.

## 5. 보안 및 안정성 기준

- 중복 상호작용으로 정산·저장·Scene 전환이 두 번 발생하지 않는다.
- 체크포인트가 파괴/비활성/막힘 상태면 지상 안전 지점으로 폴백한다.
- 전환 실패 시 기존 Run과 Inventory가 손상되지 않는다.
- UI는 Run 결과를 표시만 하고 State를 직접 완료 처리하지 않는다.

## 6. 완료 기준

- 지상→Mine→지상 정상 귀환이 실제 입력으로 동작한다.
- 전진기지 체크포인트 활성/귀환/재진입이 동작한다.
- Depth, Inventory, 정산 결과, 자동 저장 이유가 일치한다.
- 중복 요청과 Scene 로드 실패가 원자적으로 처리된다.
