# Phase C Agent Test

## 1. 정적 검증 항목

| ID | 테스트 항목 | 검증 방법 | 예상 결과 |
| :-- | :-- | :-- | :-- |
| C-S01 | 입력 정의 | Input Action 검사 | 상호작용/수직 이동 binding 존재 |
| C-S02 | 상태 머신 | Elevator 공개 상태 검사 | 명시적 상태와 단일 전환 경로 |
| C-S03 | Runtime Prefab | Elevator/Ladder 참조 검사 | Collider와 필수 컴포넌트 존재 |
| C-S04 | 저장 필드 | 체크포인트 DTO 검사 | Unity Object 없음 |

## 2. 기능 테스트 항목

### C-F01: 지상과 Mine 왕복

- **준비:** 새 게임 Surface Base
- **실행:** 엘리베이터를 호출해 Mine에 진입한 뒤 다시 귀환한다.
- **예상 결과:** 올바른 안전 위치에 도착하고 입력이 복원된다.

### C-F02: 사다리 이동

- **준비:** 6칸 깊이의 수직 shaft
- **실행:** 사다리를 오르내린다.
- **예상 결과:** 중력 떨림 없이 이동하며 끝에서 정상 이동 모드로 복귀한다.

### C-F03: 이동 중 중복 입력

- **준비:** 엘리베이터 Moving 상태
- **실행:** 호출/상호작용을 반복 입력한다.
- **예상 결과:** 이동·전력 차감·Scene 전환이 한 번만 발생한다.

### C-F04: 막힌 출구

- **준비:** 도착 지점을 타일로 막는다.
- **실행:** 엘리베이터 이동을 요청한다.
- **예상 결과:** 안전하게 거부되고 Player가 타일 내부로 이동하지 않는다.

### C-F05: 수직 구조물 저장

- **준비:** 사다리/발판 설치 후 저장
- **실행:** 프로세스 재구성 뒤 로드한다.
- **예상 결과:** 동일 좌표와 기능 상태로 복원된다.

## 3. 테스트 절차

1. Edit Mode에서 상태 전환과 비용 멱등성을 검증한다.
2. Play Mode에서 Rigidbody/Collider와 Scene 왕복을 검증한다.
3. 키보드와 게임패드 확장 가능 binding 충돌을 확인한다.

## 4. 검증 결과 요약

- **상태:** 미실행
- **모든 항목 통과 시:** Phase C 완료
- **실패 항목 존재 시:** Player 상태, Elevator 상태, 정거장 좌표를 함께 기록한다.
