# MVP2-B 미완성 범위 보강 계획

`init/prompt-B.md` 18번, `init/PRD.md`, `init/rule.md`와 현재 Unity 프로젝트를 대조해 1차 MVP에서 “코드나 UI는 있으나 실제 플레이 흐름으로 닫히지 않은 부분”을 다시 작업 단위로 나눈 문서다.

각 단계는 `research.md`의 구현 범위를 따른 뒤 같은 폴더의 `test.md`로 완료를 증명한다. 클래스·Prefab·단위 테스트의 존재만으로 완료 처리하지 않는다.

## 1. 감사 기준

다음 네 단계의 증거가 모두 있어야 해당 기능을 완료로 본다.

1. **정의:** PRD 요구와 영구 ID·데이터가 존재한다.
2. **Runtime:** 실제 Scene/Prefab에서 입력과 상태 변화가 연결된다.
3. **복원:** 저장 대상 기능은 프로세스 재실행 뒤 같은 상태로 복원된다.
4. **플레이:** `Bootstrap → MainMenu → SurfaceBase → Mine → 귀환/실패 → 저장 → 이어하기` 경로에서 사용자가 기능을 경험할 수 있다.

자동 테스트는 해당 범위를 실제로 검증할 때만 증거로 인정한다. 대역만 사용한 테스트는 실제 Runtime Prefab 통합 검증을 대신하지 않는다.

## 5. 공통 구현 원칙

1. 현재 Unity `6000.5.4f1`과 패키지 버전을 유지한다.
2. Gameplay 소유 기능은 독립 Test Scene과 Runtime Prefab에서 먼저 구현한다.
3. App 소유 기능은 State/Service/UI를 분리하고 UI가 State를 직접 수정하지 않게 한다.
4. Shared 계약 변경은 계약 테스트 → Producer → Consumer → Integration 순서로 적용한다.
5. 수치와 분포는 ScriptableObject 또는 명시적인 정적 데이터로 관리하고 코드에 흩어 놓지 않는다.
6. Seed가 같은 월드의 생성·붕괴·자원 배치는 재현 가능해야 한다.
7. 건설은 위치와 비용을 모두 검증하고 Prefab 생성 성공 뒤에만 비용을 차감한다.
8. 저장에는 Unity Object가 아닌 ID·좌표·수치·상태만 기록한다.
9. Scene/Prefab은 Unity Editor 또는 Editor API로 수정하고 YAML을 직접 손대지 않는다.
10. 기존 `MVP/MVP-B` 기능을 복제하지 않고, 확인된 통합 누락과 실제 플레이 결함만 보강한다.

B 작업자는 A 소유 코드나 Runtime Prefab을 직접 보정하지 않는다. A 기능이 독립 Test Scene에서도 실패하면 기능명, 위치, 재현 절차, 현재/기대 결과와 필요한 계약을 기록해 A 작업으로 분리한다. Shared 변경은 계약 테스트를 먼저 확정한 뒤 Producer→Consumer→Integration 순서로 적용한다.

## 7. 공통 테스트 규칙

- 순수 계산·Seed 분포·비용·손실 계산은 Edit Mode에서 검증한다.
- 입력, Rigidbody2D, Tilemap, Camera, World Space UI, 시설 상호작용은 Play Mode에서 검증한다.
- Scene 정적 검사는 참조 누락을 찾는 보조 증거이며 실제 플레이 테스트를 대체하지 않는다.
- 저장 테스트는 Capture 직후 비교로 끝내지 않고 새 프로세스에 준하는 재구성 뒤 Restore를 검증한다.
- 각 단계 `test.md`의 “검증 결과 요약”은 구현 전에는 `미실행`으로 유지한다.
- 실패 항목은 증상, 재현 절차, 기대 결과, 소유 영역과 차단되는 후속 단계를 기록한다.

## 8. 필수 최종 완주 시나리오

1. Bootstrap에서 새 게임을 만들고 Surface Base에 진입한다.
2. 시작 엘리베이터로 Mine에 내려간다.
3. 상층 구리 맥을 채굴하고 전력·화물 변화를 확인한다.
4. 수직 굴착 뒤 사다리/발판으로 복귀 가능 경로를 만든다.
5. 넓게 채굴해 균열 경고를 발생시키고 버팀목을 설치한다.
6. 중층 철/가스 구역에서 가스 효과와 드론 경고를 경험한다.
7. 조명·충전기·보관함·정산기·전진기지 코어를 설치하고 전력망을 연결한다.
8. 전진기지에서 충전/보관/정산/체크포인트를 사용한다.
9. 심층 리튬과 잠긴 신호를 확인한다.
10. 정상 귀환 또는 구조 실패 중 하나를 거쳐 Surface Base로 복귀한다.
11. 판매와 업그레이드 후 저장하고 게임 프로세스를 종료한다.
12. 이어하기로 월드 변경, 시설, 진행도, 인벤토리와 체크포인트를 복원한다.

## 9. MVP 필수 범위와 후순위 범위

필수 게이트:

- 규칙 기반 드론 대사와 템플릿 폴백
- 천층/중층/심층 예고까지의 유한 40m 월드
- 그레이박스 시각과 기본 SFX/경고 피드백
- 로컬 저장, Windows x64 QA 빌드

후순위이며 P 완료를 막지 않는 항목:

- 선택적 클라우드 생성형 대사
- 정식 캐릭터/타일 아트와 완성형 애니메이션
- 계약, 희귀 이벤트, 추가 지역
- 자동 배포, 서버 DB, 멀티플레이

## 10. 최종 완료 판정

P 단계에서 다음 증거가 모두 있어야 MVP2-B 완료다.

- A~P의 필수 자동 테스트 통과 기록
- Integration Scene Missing Script/필수 참조 누락 0
- 최종 완주 시나리오 실제 입력 기록
- 저장 후 프로세스 재실행/이어하기 성공
- Development/QA/Release Profile 구분
- Windows x64 패키지와 다른 PC 스모크 결과
- 치명적 Console Error 0, 알려진 제한 목록
