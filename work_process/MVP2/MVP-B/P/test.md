## 2. 기능 테스트 항목

### P-F01: 빌드 전 게이트

- **준비:** O 완료 후보 commit/state
- **실행:** 전체 Edit Mode/Play Mode/Integration 테스트를 실행한다.
- **예상 결과:** 필수 테스트 실패 0, Console Error 0

### P-F02: Development/QA/Release 차이

- **준비:** 세 Profile
- **실행:** 각 빌드를 실행한다.
- **예상 결과:** debug 도구와 로그가 정의된 Profile에서만 보인다.

### P-F03: Windows 전체 완주

- **준비:** 빈 세이브의 QA 빌드
- **실행:** 최종 완주 시나리오를 수행한다.
- **예상 결과:** Editor와 같은 결과로 데모를 완료한다.

### P-F04: 프로세스 재실행

- **준비:** 심층/시설/진행이 저장된 빌드
- **실행:** 프로세스를 완전히 종료하고 이어하기한다.
- **예상 결과:** 월드와 진행 상태가 복원된다.

### P-F05: 다른 PC 스모크

- **준비:** 해시가 기록된 Release ZIP
- **실행:** 개발 환경이 없는 Windows x64 PC에서 압축 해제 후 실행한다.
- **예상 결과:** 필수 DLL 누락 없이 새 게임/이어하기가 동작한다.

### P-F06: 성능 예산

- **준비:** 40m 전체 월드와 최대 예상 시설/가스
- **실행:** 생성, 채굴, 붕괴, 저장, UI 상태를 Profiler로 측정한다.
- **예상 결과:** 합의한 프레임/메모리/저장 시간 예산을 만족한다.

## 3. 테스트 절차

1. 전체 자동 테스트 결과와 Unity 버전을 보존한다.
2. 동일 source state로 세 Profile을 빌드한다.
3. 개발 PC와 다른 PC에서 체크리스트를 실행한다.
4. 로그, 성능, 패키지 해시, 알려진 제한을 QA 기록에 남긴다.

## 4. 검증 결과 요약

- **상태:** 미실행
- **모든 항목 통과 시:** Phase P 및 MVP2-B 완료
- **실패 항목 존재 시:** 빌드 버전, Profile, 재현 절차와 차단 심각도를 기록하고 배포하지 않는다.
