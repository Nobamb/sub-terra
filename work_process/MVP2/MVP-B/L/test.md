# Phase L Agent Test

## 1. 정적 검증 항목

| ID | 테스트 항목 | 검증 방법 | 예상 결과 |
| :-- | :-- | :-- | :-- |
| L-S01 | 실패 원인 | enum/이벤트 검사 | 전력/붕괴/가스 구분 |
| L-S02 | 손실 계산 | 순수 타입 검사 | Unity 의존 없음 |
| L-S03 | 업그레이드 경계 | 호출 검사 | Shared provider 사용 |
| L-S04 | 입력 잠금 | Integration 참조 검사 | 모든 Gameplay 입력 포함 |

## 2. 기능 테스트 항목

### L-F01: 원인별 실패

- **준비:** 전력 0, 붕괴 충돌, 가스 장기 노출 상태
- **실행:** 각각 실패 조건을 만든다.
- **예상 결과:** 원인이 기록되고 실패 흐름이 한 번 시작된다.

### L-F02: 화물 손실

- **준비:** 복수 광물과 고정 손실 비율
- **실행:** 구조 실패를 처리한다.
- **예상 결과:** 정책 범위만 손실되고 골드/정산 자원은 보존된다.

### L-F03: 구조 업그레이드

- **준비:** 동일 화물, 업그레이드 전/후
- **실행:** 같은 실패를 처리한다.
- **예상 결과:** 정의된 보존율만큼 더 많은 화물이 남는다.

### L-F04: 중복 실패

- **준비:** 같은 프레임의 복수 damage event
- **실행:** 실패 이벤트를 중복 발행한다.
- **예상 결과:** 손실/저장/전환이 한 번만 실행된다.

### L-F05: 체크포인트 폴백

- **준비:** 유효/무효 체크포인트
- **실행:** 구조 복귀를 수행한다.
- **예상 결과:** 유효하면 기지, 아니면 Surface 안전 지점으로 복귀한다.

## 3. 테스트 절차

1. Edit Mode에서 손실·보호 계산을 경계값까지 검증한다.
2. Play Mode에서 실제 위험 입력과 UI/Scene 전환을 검증한다.
3. 실패 직후 저장과 이어하기 상태를 M에서 재검증한다.

## 4. 검증 결과 요약

- **상태:** 완료 (2026-08-04)
- **Phase L Edit Mode:** 10 통과 / 0 실패 / 0 스킵
- **Phase L Play Mode:** 3 통과 / 0 실패 / 0 스킵
- **전체 App Edit Mode 회귀:** 299 통과 / 0 실패 / 0 스킵
- **전체 App Play Mode 회귀:** 29 통과 / 0 실패 / 0 스킵
- **Unity Editor 연결 검증:** `Mine_Demo_Integration`에 생존 상태, 실패 Orchestrator,
  전체 화면 실패 입력 차단 UI와 이동·채굴·건설·엘리베이터 입력 잠금 참조를 연결했다.
- **확인된 결과:** 세 실패 원인이 같은 서비스로 진입하고, 고정 토큰 중복은 거부되며,
  기본 화물 손실 40%와 드론 구조 보존 효과가 결정론적으로 적용된다. 활성 체크포인트가
  없으면 Surface Base를 사용하고 Scene 전환 실패 시 Mine 안전 지점으로 폴백한다.
