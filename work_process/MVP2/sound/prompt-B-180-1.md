## A. 메인 메뉴 호버 무음 — 우선 수정

### 사용자가 확인한 문제

새 게임·이어하기·설정·종료 버튼에 마우스를 올려도 호버 효과음이 들리지 않는다.

### 기대 동작

- 클릭 가능한 네 버튼에 마우스가 들어갈 때 기존 `UiHover(2)`가 한 번 들린다.
- 마우스를 버튼 안에 멈춰 두는 동안 반복 재생하지 않는다. 나갔다가 다시 들어오면 다시 한 번 난다.
- 마우스 호버로 저장칸 선택·새 게임 시작·이어하기·설정 열기·종료가 실행되지 않는다.
- 키보드 포커스 이동 때문에 마우스 호버음이 추가로 나지 않는다.
- 실제로 비활성인 버튼, 입력이 차단된 전환 중에는 불필요한 소리가 나지 않는다.
- 설정에서 정한 효과음 음량과 음소거가 적용된다.

### 확인된 코드 사실과 조사 순서

`sub-terra/Assets/_Project/` 기준:

1. `Scripts/App/UI/MainMenu/MainMenuView.cs`의 `OnEnable → AttachButtonSfx`는 이미 네 버튼 모두에 `UiSfx.Attach(button, SfxId.None, hover: true)`를 호출한다. **연결 줄을 다시 추가하는 것만으로 해결됐다고 판단하지 않는다.**
2. `Scripts/App/Audio/UiSfx.cs`의 `UiSfxButton.OnPointerEnter`는 호버가 켜져 있고 버튼이 클릭 가능한 경우에 `SfxPlayer.Play(SfxId.UiHover)`를 호출한다.
3. `Resources/SfxLibrary.asset`의 2번 칸은 음원이 연결되어 있고 음량은 0.7이다. 파일에 값이 있다는 사실은 실제 출력 성공의 증거가 아니다.
4. 실제 메인 메뉴에서 버튼 참조가 화면에 보이는 버튼과 같은지, `UiSfxButton`이 붙어 활성화되어 있는지, 포인터가 어느 UI에 닿는지 확인한다.
5. 입력이 버튼까지 도착하는지, `UiHover` 요청이 발생하는지, 음소거·재생 제한·오디오 출력 중 어디에서 끊기는지 차례로 구분한다.
6. 재현한 원인에 맞는 최소 수정만 한다. 공통 `UiSfx`나 다른 화면에 추측성 변경을 퍼뜨리지 않는다.

### 검증

- 실제 `Bootstrap → 메인 메뉴`에서 네 버튼을 각각 확인한다. 저장이 있는 경우와 빈 저장칸인 경우를 구분한다.
- 각 버튼에 진입·정지·이탈·재진입하고 소리 횟수를 확인한다.
- 설정창을 열었다 닫고 다시 확인한다. 소리가 두 번씩 겹치지 않아야 한다.
- 음소거와 효과음 음량 0에서는 무음이어야 하며, 정상 음량으로 되돌리면 다시 들려야 한다.
- 기존 새 게임·이어하기 클릭 확인음과 종료 확인창 소리는 유지한다.
- 실행 중 실제 연결이 끊기는 지점을 재현하는 좁은 회귀 검사를 작성한다. `hover == true`만 검사하고 해결됐다고 판단하지 않는다.

## B. 잠긴 업그레이드 클릭 — 별도 개선 이슈

### 요청 동작

- 잠긴 기능 업그레이드를 클릭하면 해당 자물쇠가 함께 짧게 흔들리고 쇠가 흔들리는 소리가 한 번 난다.
- 자물쇠가 풀리거나 부서지는 연출로 보이면 안 된다. 잠긴 상태와 기존 해금 조건 안내를 유지한다.
- 기존 UI가 노드나 카드를 흔든다면 자물쇠 연출과 충돌하거나 두 번 움직이지 않도록 확인한다.
- 골드·자원이 차감되거나 업그레이드가 구매되지 않는다.
- 연타로 흔들림이 계속 누적되거나 창이 닫힌 후 소리가 남지 않도록 한다.
- 창 등장·닫힘·해금 연출 중 무시된 입력에서는 새 금속음을 내지 않는다.

### 참고 코드와 음원

- `Scripts/App/UI/Progression/UpgradeTreeNodeView.cs`: 잠긴 노드를 클릭했을 때의 선택 차단·흔들림 경로.
- `UpgradeTreeView.cs`: 구매 실패 때의 흔들림·실패음은 별도 경로다. 잠긴 노드 클릭과 혼동하지 않는다.
- `UnlockRevealTimeline.cs`: 기존 **해금 성공** 연출과 소리가 있으므로 재생 시점을 공유해 중복시키지 않는다.
- 기존 `SfxId.UnlockRattle(76)`, `Audio/SFX/UI/unlock_rattle.wav`를 금속음 후보로 먼저 확인한다. 기존 음원으로 요구를 충족할 수 있는지 실제로 들어보고 결정한다. 새 음원이나 새 번호는 자동으로 추가하지 않는다.
- [#188 업그레이드 해금 연출](https://github.com/Nobamb/sub-terra/issues/188)은 해금 성공이 대상이다. 이번 요청은 **잠긴 상태를 클릭했을 때의 반응**이므로 별도로 관리한다.
- B-180 당시의 '잠긴 항목 선택 클릭음 없음'은 기존 동작이다. 이번 요청은 그 동작에 잠금 상태를 알려 주는 금속음을 추가하는 개선이다.

### 사용자가 확인할 것

업그레이드 창을 완전히 연 뒤 잠긴 항목을 누른다. 자물쇠와 금속음이 함께 한 번 반응하고 잠금은 유지되어야 한다. 여러 번 눌렀다 창을 닫고 다시 열어도 위치나 크기가 틀어지지 않아야 한다.

## C. 퀘스트 완료음과 닫힘 글리치음 — 별도 개선 이슈

### 사용자가 확인한 현재 동작

퀘스트 완료 창을 닫을 때 완료 효과음이 난다.

### 원하는 순서

1. 퀘스트 완료 창이 열린다.
2. **체크 아이콘이 나타나기 시작하는 시점에** 기존 퀘스트 완료음 `QuestReward(87)`가 한 번 난다.
3. 확인 버튼·닫기 버튼·기존에 지원하는 닫기 키로 닫으면 **생존자 브리핑 종료에 사용하는 기존 글리치 효과음**이 한 번 난다.
4. 닫을 때 완료음은 다시 나지 않는다. 보상 지급과 다음 퀘스트 진행은 기존 규칙을 유지한다.

단순히 창을 활성화한 프레임에 완료음을 재생하지 않는다. 프레임 등장과 체크 아이콘 등장 사이의 기존 연출을 기준으로 맞춘다.

### 확인된 연결과 구현 주의점

- `Scripts/App/UI/Tutorial/QuestClearPopupMotion.cs`의 `Enter()`는 `transition.IsShown` 이후 `ScaleCheck(0f, 1.1f, 0.2f)`로 체크 아이콘을 나타낸다. 실제 소리가 맞아야 할 시점은 이 체크 등장 시작이다.
- `DemoObjectivePresenter.cs`는 현재 보상 처리 성공 경로에서 `SfxPlayer.Play(SfxId.QuestReward)`를 호출한다. 소리 위치만 분리하고 실제 보상 지급 시점을 옮기지 않는다.
- `StartBriefingPopupMotion.cs`의 생존자 브리핑 `RequestClose` 경로는 `SfxId.BriefingClose(41)`를 사용한다. 기존 음원은 `Audio/SFX/UI/briefing_close.wav`다. **이 기존 브리핑 종료 소리를 재사용하는 것이 사용자 요청이다.**
- 작은 창은 현재 `CompactCloseSfx = GlitchPopupClose(89)`를 별도로 사용한다. 기존 작은 창 닫힘음과 새로 연결할 브리핑 종료음이 동시에 겹치지 않도록 퀘스트용 선택 지점만 바꾼다.
- 작은 창 공용 상수를 무조건 바꾸어 심층 해금·다른 팝업 소리까지 바꾸지 않는다. 브리핑 자체의 기존 소리도 유지한다.
- 창을 열자마자 닫아 체크가 나타나지 않았으면 뒤늦게 완료음이 나지 않는다.
- 같은 완료 창의 중복 `Open`, 연속 완료, 닫는 중 재열기, 비활성화 때 예약 소리가 남지 않도록 한다. 실제로 새 완료를 표시할 때는 다시 한 번 난다.
- 일반 퀘스트 상세창을 열기만 한 경우에는 완료음이 나지 않는다.
- 최초 피드백은 '퀘스트 완료 또는 새 구역 개방 알림' 안내에 대한 답변이었지만, 구체적으로 지정한 체크 아이콘·완료음 이동은 퀘스트 완료 창이다. 심층 해금 창의 독자적인 재생 시점이나 보상 규칙까지 확대 변경하지 않고 회귀 확인 대상으로 둔다.

### 사용자가 확인할 것

퀘스트 하나를 완료하고, 체크 표시가 생길 때 완료음이 나는지 듣는다. 닫을 때는 브리핑 종료와 같은 글리치음만 나야 한다. 같은 창의 확인 버튼·X 버튼·기존 닫기 키를 각각 확인하고, 보상이 정확히 한 번 지급되는지 확인한다. 다음 퀘스트 완료에서도 같은 순서여야 한다.

## 검증과 결과 제출

- 새 Unity 빌드나 원본 Editor 재시작을 준비의 기본 단계로 삼지 않는다. 실제 수정 범위에 필요한 가장 좁은 검사를 우선한다.
- 실행 환경이 준비되면 해당 화면과 소리를 직접 확인한다. 준비·컴파일·정적 검사는 실제 청취 검증과 구분해서 기록한다.
- 결과 문서에는 수정 파일, 재현 원인, 이슈 링크, 소리 연결 지점, 실행한 검사, 실제로 확인한 화면·소리, 미검증 항목과 그 이유를 남긴다.
- 작업 전후 `git status --short`와 관련 diff를 확인한다. 원본·무관한 에셋·공용 설정에 변경이 없어야 한다.
- GitHub 이슈 등록은 완료했다. Unity MCP의 직전 조회는 `Unity not detected (no fresh discovery files found)`로 실행되지 않았으며, PlayMode·씬 변경·소리 재생 명령은 실행하지 않았다. Editor를 연 뒤 연결과 실제 실행 원인을 다시 확인해야 한다.
