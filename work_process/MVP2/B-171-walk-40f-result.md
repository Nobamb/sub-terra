## 그림과 재생

- 원본: `work_process/images/player-walk-40f-20261028/source/1.png`~`40.png`, 960×960 RGBA 40장.
- 변환: `python work_process/tools/prepare_walk_40f.py`.
- 모든 프레임에 공통 배율 **296/960 = 0.3083333333**, 공통 위치 **(-26, -21)px** 적용. 원본 좌상단을 기준으로 296×296으로 축소한 뒤 256×256 캔버스에 배치한다.
- RGBa premultiplied Lanczos 축소 후 RGBA로 복원한다. 원본 알파 254 이상은 255로 올린다. 프레임별 변형·위치 보정·부위 수정은 없다.
- 알파 32 기준 결과: 키 **223~232px**, 발 아래 여백 **15~18px**. 자연스러운 흔들림 유지, 좌우 잘림 없음. 아래 표의 발은 아래쪽 여백, 중심은 가로 bbox 중심이다.
- 40장·40fps·1.0초 반복. `Shared/PlayerWalkCycle.cs`에서 결정값을 한 번 정의하고 Gameplay와 App 가이드가 함께 참조한다. App↔Gameplay 직접 참조는 추가하지 않았다.
- 40→1 직결, 정지 후 재시작은 1번부터. 기존 `PlayerFacing` 반전과 이동·점프·사다리 및 다른 상태의 재생 규칙은 유지했다.
- 발소리는 착지 전후 40/1/2/3 및 20/21/22/23 비교 후 문서 권장 **{1, 21}(0기준, 그림 2·22)** 사용. 기본값과 프리팹이 같다. 소리·음량·교대 피치는 유지한다.
- 기존 걷기 1~40 `.meta` GUID 유지. 41~47 PNG·meta는 Unity AssetDatabase로 삭제했고, Assets 안에 삭제 GUID 참조가 남지 않았음을 검색했다.
- Sprite Single, PPU 256, 중앙 피벗, Bilinear, 밉맵 없음, 기본 압축 없음 유지. 프리팹·클립·GameGuideSkin은 기존 Editor 빌더로 저장했다.

## 직접 확인 / 미검증

아래 체크 항목은 격리 프리팹 Play Mode와 렌더·재생 기록에서 확인한 범위다. 체크하지 않은 통합 플레이·화면·청감 항목은 미검증이다.

- [x] 오른쪽으로 걸으면 새 40장 걷기가 부드럽게 반복되고, 40번에서 1번으로 넘어갈 때 튀지 않는다.
- [x] 왼쪽으로 걸으면 같은 동작이 좌우만 뒤집혀 나오고, 방향을 바꿀 때 몸이 옆으로 튀지 않는다.
- [ ] 캐릭터 크기와 발 높이가 대기·점프·사다리 그림과 비슷해서 상태가 바뀔 때 커지거나 떠 보이지 않는다.
- [x] 걷다가 멈추면 바로 대기 그림이 되고, 다시 걸으면 처음부터 걷는다.
- [ ] 걷다가 점프, 사다리 타기, 채굴로 바뀌어도 지금처럼 바뀐다.
- [ ] 발소리가 발이 땅에 닿는 순간에 한 걸음에 한 번 난다.
- [ ] 화물을 많이 싣거나 가스 등으로 느려질 때 걸음이 너무 빨라 보이는지 적는다(PM 판단용).
- [ ] 게임 가이드·관제 터미널 데모의 걷기도 새 그림으로 나온다.
- [ ] 캐릭터 가장자리에 검은 테두리나 깨진 픽셀이 없다(밝은 지상, 어두운 광산 둘 다).
- [x] Console에 새 경고·오류가 없다.

## 후속: 실제 광산에서 걷기 중간 끊김 수정

- 사용자 실제 플레이를 읽기 전용으로 40초 관찰해 원인을 재현했다. 프레임레이트 저하나 40→1 원화 연결 문제가 아니라, 타일 경계에서 접지가 약 한 물리 틱 빠지는 동안 `Walk → jump_01 → walk_01`로 바뀌어 걷기 타이머가 초기화되는 문제였다.
- 기록 예: 21.59962초 `jump_01` → 21.61835초 `walk_01`(18.73ms), 22.12008초 → 22.13798초(17.90ms), 24.25924초 → 24.28013초(20.89ms). 입력을 계속 누르고 가로 속도가 6인 상태였다. 로컬 전체 기록: `sub-terra/Temp/B171-stutter/live.tsv`.
- `PlayerAnimationController`에 **걷기 표시 전용 0.06초 접지 유예**를 추가했다. 현재 Walk이고 이동 입력이 유지되며 실제 점프가 아닐 때만 같은 Walk 상태와 타이머를 유지한다. 점프 입력으로 뜬 경우는 즉시 Jump, 실제 낙하는 유예가 끝나면 Jump로 바뀐다. 이동·충돌·점프 물리·사다리·그림·40fps는 수정하지 않았다.
- 재현 검사: 수정 전 좌우 2개 모두 실패(`walk_14` 예상, `jump_01` 실제). 수정 후 걷기 7개 + 기존 전환 8개 = **EditMode 15/15 통과**(4.32초). 접지 누락 동안 타이머 보존, 실제 낙하, 실제 점프 즉시 전환, 정지를 검사한다.
- PlayMode: 실제 Collider2D 바닥을 한 물리 틱 끈 뒤 다시 켜는 새 회귀 검사 통과. 접지 false인데 Walk 그림 유지, 접지 회복 뒤 연속 Walk, 점프 요청 직후 Jump를 확인했다.
- 관련 `PlayerMovementPlayModeTests` 전체는 **35개 중 34 통과 / 1 실패**(5.84초). 기존 `LadderAnimation_ActiveTriggerContact_PrioritizesLadderFrames`가 `ExitLadderMode(bool)`를 인자 없이 reflection 호출해 `TargetParameterCountException`으로 실패했다. HEAD에도 같은 호출이 있으며, 이동 메서드나 이 사다리 검사는 이번에 수정하지 않았다.
- 후속 로컬 결과: `sub-terra/Temp/B171-stutter/red`, `green`, `play`. 범위 밖 설정 변경은 복구한다.
- 이전 평지 격리 확인만으로는 실제 광산의 경계 조건을 검증하지 못했다. 수정 후 실제 지상·광산 전체 동선과 사용자의 체감 재확인은 미검증이다. 수동 재확인: 같은 지상 통로를 좌우로 길게 걷기, 타일 경계 통과, 정지 후 재시작, 점프, 절벽에서 낙하, 사다리 진입.
- 재발 방지 기록은 최신 AGENTS 지시에 따라 `init/rules/lessons.md`에 한 줄 추가했다. 최초 main 병합 시의 교훈 충돌 해결과 구분되는 이번 회귀 기록이다.
