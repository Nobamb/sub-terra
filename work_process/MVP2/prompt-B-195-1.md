# B-195-1 포탈 창 불투명·구출 글리치 워프·포탈 블랙홀 (#151)

## 목표
긴급 탈출 포탈 창을 프레임 안에서 불투명하게 보이게 한다. B-195의 검은 화면·간단 글리치·화면 켜짐·카메라 이동 워프는 **비상 탈출(전력 고갈 구출)** 로 옮긴다. 포탈로 빠져나올 때는 같은 카메라 이동을 쓰되, 플레이어가 제자리 블랙홀에 빨려 들어갔다가 목적지 블랙홀에서 나오게 한다.
기준: https://github.com/Nobamb/sub-terra/issues/151. 구출·포탈의 비용·목적지·실패 안내는 그대로다. 창 열기·닫기 웜홀은 건드리지 않는다.

## 브랜치
1. `git fetch` 후 **같은 브랜치 `MVP2-fix139`** 에서 B-195에 이어 작업한다. 새 번호 브랜치를 만들지 않는다.
2. 이 문서를 쓸 때 원격에 `MVP2-fix139`은 아직 없었다(최신 `origin/main`은 `6c9743a506e61166e15efe93f0ae5a7977c6f4ac`, 원격 `MVP2-fix*` 최댓값 138). fetch 뒤에 브랜치가 있으면 그 실제 코드를 읽는다. 없으면 main `6c9743a5`에서 `MVP2-fix139`을 만들고 **B-195를 먼저 반영한 뒤** 이 항목을 한다. 포탈에 넣은 암전·글리치는 아래 블랙홀로 **교체**한다. 최종적으로 포탈 탈출에 글리치가 남아 있으면 안 된다.
3. 보고서 맨 위에 기준 커밋(main 또는 `MVP2-fix139` head)과 B-195 반영 여부를 적는다.

6. 시각 연출이 골드·전력·광물 차감 시점이나 수량을 다시 바꾸면 안 된다. 포탈은 `EmergencyEscapeService.TrySpend`, 구출은 `EmergencyRescueService.TryRescue`를 성공 확인 직후 한 번만.

## 현재 상태
- **포탈 창이 비치는 이유(B-195 이후).** `Window/Frame`(`mine-reset-frame.png`)은 테두리만 있고 가운데 알파는 0이다. B-195는 프레임 밖으로 새던 검은 네모(`Window/Panel`, `mine-reset-panel.png`, 빌더가 16px만 안쪽으로 넣음)를 숨긴다. 그러면 프레임 안이 뚫려 광산이 비친다. 같은 크기로 겹치면 패널 채움이 프레임 안쪽 구멍보다 바깥까지 나간다(프레임 구멍은 대략 가로 2.4%·세로 3.0% 안쪽, 모서리 깎임 포함). 16px 여백으로는 모서리에서 검은 도형이 다시 보인다. `InputShield`는 `Color(0,0,0,0)`·`raycastTarget = true`인 투명 클릭 차단막이라 보이면 안 된다. 열린 뒤 `WindowAlpha`는 1이다. 육각 무늬·CCTV·목록은 유지하되, 그것들만으로 창 안을 가리지 않는다.
- **구출(비상 탈출) 지금 워프.** `EmergencyRescueRuntimeController.TryRescue` ~238. 창이 안정(`IsStable`)일 때만, 표시 비용과 `GetCurrentCost()`가 같으면 `EmergencyRescueService.TryRescue`로 **즉시** 결제한다(골드 `min(250, 보유)`, 미정산 광물 80%). 성공 시 `SfxId.PortalWarp`(`RescueWarpSfx`)를 내고 `MoveToResolvedElevator` ~305가 플레이어와 `Rigidbody2D`를 엘리베이터 `BoardingAnchor`(없으면 `elevator.transform`)로 **즉시** 옮긴다. 이어 `HideAll()`·`SaveCurrent`. 카메라는 `PlayerCameraFollow`의 `teleportDistance` 자동 스냅으로 붙는다. 목적지는 엘리베이터뿐이다. 실패는 `SfxId.UiCancelFail`과 안내만. 체력 0 `RunFailure`는 타지 않는다.
- **포탈 지금 워프(B-195 예정/구현).** 결제 즉시, 암전+간단 글리치 → 화면 켜짐 → 카메라 이동(기본 0.7s) → 도착 시 `TeleportPlayer`. 이 글리치는 구출로 옮기고 포탈에서는 뺀다.
- **재사용할 블랙홀 그림.** `EscapeWormholeArt`(`Swirl` 바깥·안쪽 청록 나선, `Core` 검은 사건 지평선+청록 고리), `EscapeWormholeParticleField`/`EscapeWormholeParticleGraphic`. 회전·크기는 `EscapePortalOpenTimeline`(`SpinSpeedMax` 210, 닫기에서 창이 0.5s 동안 줄어들며 빨려 들어감). 창에 붙은 열기·닫기 웜홀은 그대로 두고, 같은 그림을 **플레이어 위치의 월드/화면 연출**에 재사용한다.

## 할 일
### A. 포탈 창을 불투명하게
- 프레임 **안쪽 구멍(깎인 모서리 포함)** 을 불투명한 어두운 면으로 채운다. 광산이 창 가운데로 비치면 안 된다. 예전 16px `Window/Panel`을 그대로 다시 켜지 않는다. 검은 네모가 프레임 밖으로 나가면 안 된다.
- `mine-reset-panel.png`나 단색을 쓰되, 마스크·클리핑·크기로 프레임 안쪽에만 두게 한다. 공유 PNG 원본은 수정하지 않는다. `PromptB147` 빌더를 다시 돌려도 바깥 검은 네모가 되살아나거나 안쪽 채움이 사라지면 안 된다.
- **`InputShield`는 지우지 말고** 알파 0 + `raycastTarget` true를 유지한다. `Frame`, 웜홀, 목록·CCTV·버튼·육각 무늬는 유지한다. 다른 팝업은 그대로 둔다.

### B. 글리치 워프를 구출(비상 탈출)로
- 성공 시 결제는 지금처럼 `TryRescue` 한 번만 즉시. `MoveToResolvedElevator`는 연출이 끝날 때까지 미룬다. `HideAll()`은 전환이 시작될 때(또는 창을 가린 뒤) 해서 글리치가 게임 화면 위에 보이게 한다.
- 순서(unscaled, 워프가 끝날 때까지 일시정지 유지): 검은 화면 + **간단한** 글리치 → 화면 켜짐 → 카메라가 엘리베이터로 **이동**(스냅 금지) → 도착 시 플레이어를 옮기고 추적을 재개. B-195가 `PlayerCameraFollow`와 `RunFailureGlitchArt`를 짧게 쓰도록 만든 API를 재사용한다. 색은 사망용 적색/녹색이 아니라 약한 청록. 권장 시간은 B-195와 같다(암전 0.25s, 간단 글리치 0.25s, 켜짐 0.3s, 카메라 0.7s). 모두 검사기.
- 모션 감소: 글리치·카메라 이동 없이 페이드 → 워프+`SnapToTarget` → 페이드 인.
- 효과음: 성공 시 기존 `SfxId.PortalWarp`만. 실패는 `UiCancelFail`과 안내만, 연출 없음. 닫기·취소(구출 버튼이 아님)는 워프 없음. `SaveCurrent`는 워프 이후.
- 체력 0 `RunFailure`는 호출하지 않는다.

### C. 포탈 탈출은 블랙홀 + 같은 카메라 이동
- 카메라 이동은 구출과 **같은 코드·같은 검사기 기본값**(0.7s). 경로만 다르면 안 된다. 목적지는 엘리베이터 또는 전진기지(지금 포탈과 동일).
- 암전·글리치 대신: 플레이어 자리에 어두운 소용돌이가 생기고, 캐릭터가 줄어들며 회전해 빨려 들어간다(권장 0.5s) → 카메라 이동(0.7s) → 목적지에서 같은 블랙홀이 열리고 캐릭터가 다시 나온다(권장 0.4s). 시간은 검사기. 결제는 즉시 한 번, 텔레포트는 카메라 도착 시점.
- `EscapeWormholeArt`·입자·타임라인 회전을 재사용한다. 새 아트 파일은 만들지 않는 쪽을 우선한다. 창의 열기·닫기 웜홀과 섞이거나 그 연출을 바꾸면 안 된다.
- 모션 감소: 빨려 들어감·회전 없이 페이드 → 스냅 워프 → 페이드 인(구출과 같은 규칙).
- 효과음: 성공 시 기존 `SfxId.PortalWarp`만. `PortalClose`·`EscapeArrive`는 성공 워프에서 내지 않는다. 실패·취소는 연출 없음.

## 테스트 (EditMode 추가, 필요하면 PlayMode)
- 구출: 결제 즉시 1회, 좌표 변경은 카메라 이동이 끝날 때 1회. 골드·광물 수량은 연출 중 다시 줄지 않음. 목적지는 엘리베이터.
- 포탈: 결제 즉시 1회, 워프는 블랙홀→카메라 이동 도착 시. 글리치 없음. 카메라 시간과 코드는 구출과 동일.
- 모션 감소: 두 흐름 모두 페이드+스냅만.
- 포탈 창: 프레임 안은 불투명, 프레임 밖·주변에 검은 네모 없음. `InputShield`는 알파 0·레이캐스트 켜짐. 빌더 재적용 후에도 유지.
- 취소·실패는 워프 없음. 창 열기·닫기 웜홀 유지. 체력 0 `RunFailure` 검사 새 실패 없음.
- 즉시 워프를 가정한 구출·포탈 검사는 새 순서에 맞게 고친다.

## 사용자 테스트 가이드 (직접 플레이)
1. 광산에서 긴급 탈출 포탈을 연다. 창이 예전처럼 웜홀과 함께 열리고, 프레임 안은 불투명해야 한다. 광산이 창 가운데로 비치거나, 프레임 밖으로 검은 네모가 나가면 안 된다. 목록·CCTV·테두리는 그대로다. 창 밖을 클릭해도 채굴·이동이 되면 안 된다.
2. Esc나 ×로 닫는다. 창이 예전처럼 웜홀로 빨려 들어가고, 캐릭터는 포탈 앞에 그대로인지 본다.
3. 다시 열어 엘리베이터로 이동한다. 캐릭터가 제자리 블랙홀에 줄어들며 빨려 들어가고, 카메라가 엘리베이터로 움직인 뒤, 그곳 블랙홀에서 나와야 한다. 화면이 검어지며 글리치가 나면 안 된다.
4. 전진기지가 있으면 그곳으로도 3을 반복한다.
5. 전력이 0이 되어 비상 탈출 창(「전력이 바닥났습니다」)을 연다. 「구출 요청」을 누르면 화면이 검어지며 짧은 글리치가 나고, 다시 켜진 뒤 카메라가 엘리베이터로 움직이고 그 자리에 와 있는지 본다. 창만 닫히며 갑자기 옮겨지면 안 된다. 비용은 예전과 같다.
6. 구출·포탈 모두, 골드나 자원이 부족하거나 취소하면 안내만 있고 워프가 없는지 본다.
7. 설정에서 모션 감소를 켜고 3과 5를 다시 본다. 블랙홀 빨림·글리치·카메라 이동 없이 페이드 후 목적지에 나타나야 한다.
8. 체력 0 구조 연출이 예전과 같은지, 수량이 연출 때문에 더 깎이지 않는지, Unity Console에 새 빨간 오류·노란 경고가 없는지 본다.
