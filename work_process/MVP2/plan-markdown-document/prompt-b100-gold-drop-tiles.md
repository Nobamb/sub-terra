## 0. 한 줄 결론

원안 숫자는 **운 좋은 발견(lucky find)** 으로 맞다. 지금 빌드에서 골드는 광물 판매가 본수입이고, 싱크는 긴급 탈출 100G / 새 광산 500G(유료 초기화마다 2배)뿐이다. 골드 블록은 그 싱크를 가끔 채워 주는 현금이지, 광물 경제를 대체하면 안 된다.

원안 확률·지급량을 1차 가설로 유지한다. 화물 무게를 안 먹는 즉시 골드라서 같은 가치의 광물보다 강하다. 그 강함은 이미 낮은 확률(1% / 5% / 10%)이 상쇄한다.

판정 문장:

> “암석을 팠더니 금이 박힌 칸이 나와 20G가 바로 들어왔다. 드론 스캔은 노란 빛으로 그 칸을 가리켰고, 인벤 무게는 그대로였다.”

이 문장을 못 만들면 기능이 아직 완결되지 않은 것이다.

## 1. 원안

prompt-B 100 원문 그대로.

- 모든 깊이에, 낮은 확률로 골드를 드롭하는 블록을 추가한다.
- **제외**: 엘리베이터를 지탱하는 검은 블록(`tile.elevator.protected`). 좌우/바닥 경계 암석(`tile.rock.boundary`)과 봉인 신호(`tile.locked.signal`)도 캘 수 없으므로 제외.
- **대상**: 일반 암석, 가스 포켓, 구리, 철, 리튬 — 캘 수 있는 모든 블록.
- 골드 등장 블록은 **별도 에셋**. 기존 블록 위에 금이 박힌 모습만 더한다. 타일 전체를 금색으로 칠하지 않는다.
- 드론 감지에서는 기존 흰색 광 대신 **노란 빛**으로 강조한다.

| 기반 타일 | 등장 확률 | 획득 골드 |
| --- | ---: | --- |
| 일반 암석 | 1% | 20G |
| 가스 포켓 | 10% | 50G |
| 자원 블록 (구리/철/리튬) | 5% | 해당 광물 판매 단가 × 5 |

현재 단가 기준 자원 골드:

| 광물 | 단가 | ×5 |
| --- | ---: | ---: |
| 구리 | 10G | 50G |
| 철 | 15G | 75G |
| 리튬 | 40G | 200G |

의도: 지층을 파다 보면 가끔 현금을 줍는다. 가스는 위험 프리미엄, 광석은 판매액의 배수, 암석은 소액 복권.

## 2. 설계 원칙

구현·수치 조정 때 이 여덟 줄을 유지한다. 깨려면 이유를 §11에 적는다.

1. 골드 블록은 **새 광맥 종류가 아니다.** 기존 암석/가스/광석 칸 위에 얹는 변형이다. 내용물 비율 10%를 건드리지 않는다.
2. 배치 난수는 **월드 시드 + 좌표**로 칸마다 독립한다. 기존 `LocalRandom` 스트림을 이어서 쓰면 광맥이 섞인다. `generatorVersion`도 올리지 않는다.
3. 지급은 **채굴 커밋 성공 시 `PlayerState.Gold`에 즉시 가산**한다. 인벤 슬롯·화물 무게를 쓰지 않는다. 광물 아이템으로 넣지 않는다.
4. 광석 골드량은 **카탈로그 단가 × 배수**로 계산한다. 50/75/200을 타일에 하드코딩하지 않는다. 단가가 바뀌면 골드량도 따라간다.
5. 기반 타일의 채굴 규칙(드릴 레벨, 전력, 가스 분출, 구조 영향, 광물 수량)은 그대로다. 골드 변형은 스프라이트·스캔색·골드 지급만 더한다.
6. 인벤이 가득 차 광석 채굴이 실패하면 **골드도 지급하지 않는다.** 타일은 남는다. 암석·가스처럼 광물이 없는 칸은 인벤과 무관하게 골드만 준다.
7. 구세이브는 시드로 월드를 다시 만든 뒤 채굴 변경점을 입힌다. 아직 안 캔 칸에 골드 변형이 생기는 것은 허용한다. 이미 캔 칸은 비어 있다.
8. 드론 노란 빛은 **골드 변형만**. 일반 광석은 기존 흰 빛, 일반 가스는 기존 빨간 빛.

골드 본수입은 여전히 **광물 판매**다. 골드 블록은 그 위에 얹는 현금이다.

### 3-3. 채굴 커밋

현재 `IMiningTransaction.TryCommitMining(mineralId, quantity, energyCost)`는 광물+전력만 처리한다.

- 암석: `mineralId` 빈 값, `quantity` 0 → 전력만 차감.
- 광석: 기본분 exact, 수확 보너스 partial (`MiningYieldCommit`).
- 가스: `containsGas == true`이면 `MiningGasBridge`가 구역을 켠다. 타일 ID 문자열이 아니라 이 플래그를 본다.

골드 지급은 이 커밋에 붙인다. Gameplay가 `GameState.AddGold`를 직접 호출하지 않는다.

## 5. 밸런스 검토

### 5-1. 이 블록이 실제로 바꾸는 것

골드 블록은 광물 개수를 늘리지 않는다. 바꾸는 것은 **탐사를 중단하지 않고 쓸 수 있는 현금**이다.

| 비교 | 광물 판매 | 골드 블록 |
| --- | --- | --- |
| 화물 무게 | 차지함 | 안 차지함 |
| 지상 정산 | 필요 | 불필요 |
| 만재와 충돌 | 있음 | 암석·가스는 없음. 광석은 인벤 실패 시 둘 다 실패 |
| 용도 | 업글/건물 재료 + 판매 골드 | 탈출 100G, 새 광산 500G |

그래서 구리 골드 50G는 “구리 5개”가 아니다. 구리 5개는 무게 7.5이고 들고 올라가야 한다. 50G는 그 자리에서 탈출비 절반이다.

### 5-2. 광산 전체 기댓값 (전부 캤을 때)

원안 확률을 3-1 규모에 곱하면:

| 기반 | 기대 칸 | 칸당 골드 | 합 |
| --- | ---: | ---: | ---: |
| 암석 1% | ~28 | 20 | ~560G |
| 가스 10% | ~5 | 50 | ~250G |
| 구리 5% | ~6 | 50 | ~300G |
| 철 5% | ~6 | 75 | ~450G |
| 리튬 5% | ~2 | 200 | ~400G |
| **합계** | **~47** |  | **~1,960G** |

같은 광산을 전부 캐서 광물을 팔면 대략 4,000G대다. 골드 블록은 풀 클리어 기준 **약 +45%** 현금이다. 풀 클리어는 데모 한 판이 아니라 여러 왕복이다.

### 5-3. 실제 플레이에서 강한가

**기댓값은 약하다. 한 방이 눈에 띈다.** 그게 원안의 맛이다.

데모 동선(암석 300 + 광석 수십 + 가스 몇 칸) 기댓값:

| 구간 | 대략 |
| ---: | --- |
| 암석 | 300 × 1% × 20 = 60G |
| 가스 | 5 × 10% × 50 = 25G |
| 구리·철 | 약 70G |
| 리튬 1~2칸 잭팟 여부 | 0 또는 200G |
| **합** | **약 150~250G** |

긴급 탈출 1~2회, 또는 새 광산 500G의 30~50%. 광물 판매를 대체하지 않는다. 탈출/초기화 싱크를 가끔 채워 준다.

왕복 한 번 (만재 구리 33칸 + 가는 길 암석 40칸):

- 구리 골드 기대: 33 × 5% × 50 = 82.5G
- 암석 골드 기대: 40 × 1% × 20 = 8G
- 판매 330G 대비 골드 블록은 **약 +27%**

체감은 “만재 팔고 나니 보너스가 조금 더 있었다” 쪽이다. 리튬 한 칸 200G만 예외적으로 탈출 2회분이다. 심층 희귀 칸의 잭팟으로 둔다.

### 5-4. 암석만 갈아 골드를 파밍할 수 있는가

할 수는 있다. 이득이 없다.

- 암석 전력 1, 최대 전력 100 → 한 번에 100칸.
- 기대 골드: 100 × 1% × 20 = **20G / 전력바**.
- 같은 전력으로 구리를 캐면 칸당 판매 10G + 골드 기대 2.5G ≈ **12.5G / 칸**.

암석 파밍은 구리 채굴보다 에너지 대비 약 60배 나쁘다. 확률을 더 내릴 필요는 없다.

가스 10%는 위험 프리미엄이다. 가스를 일부러 여는 대가가 50G 기대(칸당 5G)라서, 가스 파밍이 주 루트가 되지는 않는다.

### 5-5. 원안을 지금 깎아야 하는가

**아니오. 1차 가설은 원안 유지.**

깎아야 할 신호가 들어오면 §11 노브만 돌린다.

| 플레이테스트에서 보이면 | 돌릴 노브 |
| --- | --- |
| 첫 탐사에 탈출비 100G가 항상 모인다 | 암석 20G → 10~15, 또는 1% → 0.5% |
| 리튬 한 칸으로 새 광산이 반값 | 리튬 배수 5 → 3 (120G) |
| 골드가 안 보여 기능 자체를 모름 | 확률은 유지, 에셋 가독성·노란 빛만 강화 |
| 스캔 업글 후 노란 빛만 따라다니며 산다 | 의도된 시너지. 바로 너프하지 않음 |

올리면 안 되는 것:

- 암석 확률을 5% 이상으로. 화물 없는 현금 농장이 된다.
- 광석 배수를 10으로. 만재 구리 한 번에 기대 골드가 판매액과 맞먹는다.
- 골드를 인벤 아이템으로. 무게·판매 루프가 이중으로 돈다.
- 인벤 풀이어도 골드만 지급. 광석 칸을 무게 없이 현금 창구로 쓴다.

### 5-6. 퀘스트 골드와의 합

`quest-reward-proposal.md`가 들어가면 데모 18개에서 골드가 추가로 나온다. 그 골드와 이 블록 골드는 **출처가 다르다.**

- 퀘스트 골드: 숙제를 끝낸 진행 완충.
- 블록 골드: 월드 탐색 운.

둘 다 싱크가 탈출/새 광산뿐이라, 퀘스트 보상안이 실제로 들어간 뒤에는 합산 현금을 한 번 더 본다. 이 문서의 1차 수치는 퀘스트 골드와 독립적으로 유지한다. 합산이 넘치면 퀘스트 표의 골드 칸을 먼저 줄인다. 월드 드롭 확률은 탐사의 재미라서 나중에 건드린다.

### 5-7. 판정

| 질문 | 답 |
| --- | --- |
| 원안 구조를 쓰는가 | 예. 기존 타일 변형 + 즉시 골드 |
| 원안 숫자를 쓰는가 | 예. 1차 가설. 플레이테스트 전 확정값 아님 |
| 지금 빌드를 깨는가 | 광맥 RNG를 분리하고 화물 무게를 안 건드리면 아님 |
| 암석 파밍이 되는가 | 전력 대비 이득이 없어서 아님 |
| 지금 바로 확률을 내리라고 하는가 | 아니오. §11 노브만 열어 둔다 |

## 6. 데이터 모델

골드 변형을 `MineLayerCellKind`에 넣지 않는다. 넣으면 광맥 가중치·보호 경로·가스 안전 판정이 전부 흔들린다.

### 6-1. `MiningTileDto.goldDrop`

```csharp
public int goldDrop; // 0이면 일반 타일. 양수면 채굴 성공 시 지급 골드
```

생성자 마지막에 `int goldDrop = 0`을 추가한다. 기존 호출은 그대로 0이다.

기반 타일 DTO를 복사한 뒤 `tileId`와 `goldDrop`만 바꾼다.

| 필드 | 암석 골드 | 가스 골드 | 구리 골드 |
| --- | --- | --- | --- |
| `tileId` | `tile.rock.normal.gold` | `tile.gas-pocket.gold` | `tile.copper.gold` |
| `mineralId` | `""` | `""` | `mineral.copper` |
| `quantity` | 0 | 0 | 1 |
| `containsGas` | false | **true** | false |
| `requiredDrillLevel` | 기반과 동일 | 1 | 0 |
| `energyCost` | 기반과 동일 | 2 | 1 |
| `goldDrop` | 20 | 50 | 단가×5 |

가스는 `containsGas`를 유지해야 `MiningGasBridge`가 그대로 작동한다. 타일 ID가 `.gold`로 끝나도 가스 로직은 플래그만 본다.

### 6-2. `IMiningTransaction`

```csharp
MiningCommitResult TryCommitMining(
    string mineralId,
    int quantity,
    int energyCost,
    int goldGrant);
```

네 번째 인자를 추가한다. 구현체:

- `IntegrationRuntimeBinder`
- PlayMode `MiningSystemPlayModeTests` 스텁

`goldGrant < 0`이면 0으로 클램프. 커밋 실패 시 골드·광물·전력 모두 불변.

오버로드를 남겨 기존 세 인자 호출이 컴파일되게 하지 않는다. 호출부를 한 번에 맞춘다. 숨은 경로에서 골드가 빠지는 것을 막기 위함이다.

### 6-3. `GoldDropSettings`

월드 생성기만 이 SO를 읽는다. 채굴 커밋은 DTO의 `goldDrop`만 본다.

검증:

- 확률 0~100 정수.
- `rockGold` / `gasGold` ≥ 1.
- `orePriceMultiplier` ≥ 1.
- 구리·철·리튬 카탈로그 단가가 있어야 광석 골드량을 계산할 수 있다.

에디터 메뉴 `SubTerra/Data/Build MVP Data Assets` 또는 Phase B 지층 셋업에서 에셋을 만든다. YAML을 손으로 고치지 않는다.

### 6-4. 타일 ID 헬퍼

```csharp
public static bool IsGoldDrop(string tileId)
public static string BaseTileId(string tileId) // ".gold" 접미사 제거
```

퀘스트 `PurifyGasWithOutpost`는 지금 `entityId == "tile.gas-pocket"`만 본다. 골드 가스를 캐도 카운트되게 `BaseTileId` 또는 `entityId` 두 값을 허용한다. 구리/철/리튬 퀘스트는 `reasonId`(광물 ID)를 보므로 그대로 통과한다.

`MiningTileResolver.TryFindTileById`는 골드 ID와 기반 ID를 **다른 TileBase**로 구분해야 한다. 같은 `tileId`에 두 스프라이트를 넣으면 복원 때 일반 타일이 골드 칸을 덮는다.

## 7. 월드 생성

### 7-1. 순서

`MineLayerTilemapGenerator.Regenerate` 현재 순서에 골드만 끼운다.

1. `MineLayerGenerator.Generate` — **기존 그대로**. 광맥 RNG 불변.
2. 각 셀 `ResolveTile(kind)` 후, 골드 대상이면 골드 TileBase로 교체.
3. 표면 좌우 경계 연장.
4. `PlaceElevatorProtectedBlocks` — 검은 블록이 골드를 덮어 쓴다.
5. (에디터) `RestoreAuthoredDemoMarkers` — 튜토리얼 구리/철/리튬/가스는 **골드 없이** 고정. 첫 퀘스트 칸이 잭팟이 되면 안 된다.
6. Resolver에 기반 타일 + 골드 타일 DTO 등록.

### 7-2. 칸 단위 해시 (광맥 RNG와 분리)

기존 `LocalRandom(seed, generatorVersion)`을 이어서 `Next()` 하면 광맥 클러스터가 바뀐다. 금지.

```text
h = Hash(worldSeed, cellX, depth, channelSalt)
gold = (h % 100) < chancePercent
```

- `channelSalt`는 골드 전용 상수. 광맥 시드와 섞지 않는다.
- 같은 시드 + 같은 좌표 = 항상 같은 골드 여부.
- `generatorVersion`을 올리지 않는다. 구세이브 복원(`generatorVersion` 불일치 시 `Regenerate` 실패)을 깨지 않기 위함이다.

대상 판정:

```text
kind ∈ { Rock, GasPocket, Copper, Iron, Lithium }
AND 셀이 경계/신호/엘리베이터 보호가 아님
```

보호 하강 경로(엘리베이터 아래 세로 암석)는 캘 수 있으므로 골드가 나와도 된다.

### 7-3. 저장·복원

새 Save 필드 없음. `saveVersion` 올리지 않는다.

복원 경로:

1. 시드로 지층 재생성 (골드 해시 포함).
2. 채굴 변경점으로 이미 캔 칸 제거.
3. 남은 골드 칸은 다시 노란 스캔 대상.

한 칸은 한 번만 돈을 준다. 캔 칸은 스냅샷에 비어 있다.

### 7-4. 하지 않는 것

- 골드 전용 광맥(2~5칸 클러스터). 원안은 칸마다 독립 확률이다.
- 깊이별 확률 곡선. 모든 깊이 동일.
- 채굴 중에 골드가 뒤늦게 붙는 것. 생성 시점에 스프라이트가 이미 금이 박혀 있어야 한다.

## 8. 채굴 커밋

### 8-1. 소유권

| 층 | 책임 |
| --- | --- |
| Gameplay `MiningSystem` | DTO의 `mineralId` / `quantity` / `energyCost` / `goldDrop`을 커밋에 넘긴다. `GameState`를 모른다. |
| Shared `IMiningTransaction` | 광물·골드·전력을 한 번에 확정. |
| App `MiningYieldCommit` | 기존 수확 보너스 규칙 + `goldGrant` 가산. |
| App `PlayerState.AddGold` | 실제 잔액 변경. HUD 골드 이벤트는 기존 구독. |

### 8-2. `MiningYieldCommit.TryCommit` 순서

1. 의존성·전력 검사. 실패 시 월드·인벤·골드·전력 그대로.
2. `goldGrant < 0`이면 0.
3. 광물 기본분 exact. 실패(`InventoryFull` 등)면 **골드 지급 없이** 실패.
4. 수확 보너스 partial (기존).
5. `goldGrant > 0`이면 `state.AddGold(goldGrant)`. overflow는 기존 판매와 같이 `int.MaxValue`에서 막는다.
6. 전력 차감.
7. 성공.

암석 골드: 3번은 수량 0이라 통과, 5번에서 20G.

구리 골드 + 인벤 풀: 3번 실패, 타일 유지, 골드 0. 자리를 비운 뒤 다시 캐면 그때 광물+골드를 받는다.

### 8-3. HUD 피드백

`MiningProgressHud.SetPendingYieldFeedback` 문자열을 확장한다.

| 경우 | 문구 예 |
| --- | --- |
| 암석 골드 | `골드 +20G` |
| 구리 골드 | `구리 +1  골드 +50G` |
| 구리 골드 + 수확 보너스 | `구리 +1 (+1 수확)  골드 +50G` |
| 일반 구리 | 기존 `구리 +1` |

월드 플로팅 텍스트를 새로 만들지 않는다. 기존 채굴 완료 HUD만 쓴다. 좌상단 골드 숫자는 `AddGold` 이벤트로 이미 갱신된다.

### 8-4. 적용하지 않는 경로

| 경로 | 이유 |
| --- | --- |
| `EconomyService.TrySellMineral` | 판매할 아이템이 아님 |
| 퀘스트 보상 | 별도 표 |
| 보관함 이동 | 인벤에 안 들어감 |
| 월드 드롭 폴백 (`SpawnResourceDrop`) | 골드 코인 오브젝트를 만들지 않음. 커밋 성공 시에만 잔액 반영 |
| 구조 붕괴로 타일이 사라짐 | 플레이어가 캔 것이 아님. 골드 없음 |

구현 때 원본 PNG를 참조로 `image_edit` 한다. 새 타일을 처음부터 그리지 않는다.

프롬프트에 넣을 제약:

- 기반 타일의 돌 형태·색·균열을 유지한다.
- 돌과 돌 사이, 균열, 표면 홈에만 **금속 금 알갱이/얇은 금맥**을 넣는다. 알갱이 3~8개.

- 가스 골드는 초록 독성 균열을 남기고 그 위에 금 알갱이만 올린다.
- 리튬 골드는 청록 결정을 남기고 결정 뿌리/암석 틈에만 금을 넣는다.
- 카메라가 타일을 한 칸으로 볼 때도 금이 읽혀야 한다. 점이 너무 작으면 실패.

플레이 줌에서 일반 암석과 1초 안에 구분되면 통과다. 구분 안 되면 알갱이를 키우거나 가장자리에 금 테를 조금 더한다. 확률을 올려 가독성을 대체하지 않는다.

엘리베이터 보호 블록(`ProtectedElevatorBlock.png`, 거의 검은 암석)에는 금을 넣지 않는다.

## 10. 드론 스캔

현재 `DroneScanTargetKind`는 `Mineral`(거의 흰 빛)과 `GasHazard`(빨간 빛)뿐이다. `CollectPulseTargets`는 `mineralId`가 있는 칸만 광석으로 넣는다. **암석 골드는 `mineralId`가 비어 스캔에서 빠진다.** 이 빈칸을 채우는 것이 노란 빛의 핵심이다.

### 10-1. 종류

```csharp
public enum DroneScanTargetKind
{
    Mineral = 0,
    GasHazard = 1,
    GoldDrop = 2
}
```

`DroneScanPulseView.goldColor = (1.0, 0.82, 0.18)` 부근. 흰색·가스 빨강과 겹치지 않게 채도를 높인다.

### 10-2. 우선순위

한 칸에 마커는 하나다.

1. `goldDrop > 0` → **노란 빛**. 구리 골드도 흰 빛 대신 노란 빛 (원문: 흰색 대신 노란 빛).
2. 그 외 활성 가스 셀 (스캔 반경 ≥ 7) → 빨간 빛.
3. 그 외 `mineralId` 있는 칸 → 흰 빛.

골드 가스를 캐면 가스 구역은 기존처럼 활성화된다. 스캔 색만 노랗다. “위험인데 현금이 박혀 있다”는 노란 빛 + 가스 오버레이로 읽힌다.

스캔 업글이 없으면 반경 0이라 펄스가 안 뜬다. 그때는 에셋의 금 알갱이만 단서다. 스캔 업글의 가치가 “노란 빛을 따라가면 현금”으로 늘어난다. 의도된 시너지.

### 10-3. 미니맵

1차에서는 미니맵에 골드 전용 색을 넣지 않는다. 남은 블록 도트 규칙(`prompt-B 96`)을 유지한다. 노란 미니맵 점은 골드가 너무 안 보일 때만 §11 후속으로 연다.

## 11. 조절 노브

플레이테스트 후 숫자만 바꿀 때 여기만 고친다. `GoldDropSettings` 필드와 대응한다.

| 노브 | 기본 | 올리면 | 내리면 |
| --- | ---: | --- | --- |
| 암석 확률 | 1% | 기능이 안 보이면 2%까지. 그 이상은 농장 | 0.5%. 에셋이 안 보여서가 아니면 비권장 |

| 광석 확률 | 5% | 광석 골드가 안 나오면 8% | 3% |
| 암석 골드 | 20 | 25~30. 탈출 100과 맞춰 5칸 | 10~15. 첫 탐사 현금이 넘칠 때 |
| 가스 골드 | 50 | 75 | 30 |
| 광석 배수 | 5 | 금지에 가깝다. 6 이상은 판매와 경합 | 리튬만 3으로 내리는 것이 안전 |
| 스캔 노란 빛 | 켜짐 | — | 끄면 원문 위반 |

건드리지 말 것:

- 골드 아이템화, 무게 0 광물 5개 지급.
- 광맥 생성 RNG.
- `generatorVersion`.
- 엘리베이터 보호 블록.

## 13. 구현 순서

한 작업 단위로 이 순서를 지킨다. 에셋만 넣고 커밋에 골드를 안 붙이면 “금이 보이는데 돈은 안 들어오는 가짜 블록”이 된다.

### 13-1. 데이터

1. `MiningTileDto.goldDrop` + 생성자 기본 0.
2. `GoldDropSettings` SO + 빌더로 에셋 생성.
3. 타일 ID 상수 (`MineLayerTileIds` 또는 `DataIds.Tiles`).
4. `IsGoldDrop` / `BaseTileId` 헬퍼.

### 13-2. 에셋

1. 원본 5장을 참조로 골드 박힌 PNG 5장 생성.
2. 임포트 설정 복사 (256 PPU).
3. `Tilemaps/DemoWorld/*Gold.asset` 생성, sprite 연결.
4. `MineLayerTilemapGenerator`에 골드 TileBase 5개 필드.
5. `PhaseBMineLayerSetup` / Resolver 엔트리 / `PhaseEMiningSetup` 전력·드릴 레벨을 기반 타일과 동일하게.

### 13-3. 생성

1. 칸 해시 롤. 기존 `LocalRandom` 스트림 금지.
2. 경계·신호·엘리베이터 보호 제외.
3. 시드 고정 테스트: 같은 시드 → 같은 골드 좌표. 광맥 해시(`ComputeStableHash`)는 골드 전후 동일.

### 13-4. 커밋

1. `IMiningTransaction` 시그니처 + 구현체 + 테스트 스텁.
2. `MiningYieldCommit`에 `goldGrant`. 인벤 실패 시 골드 0.
3. `MiningSystem.CompleteMining`이 `activeTile.goldDrop`을 넘김.
4. HUD 문구 확장.

### 13-5. 드론

1. `DroneScanTargetKind.GoldDrop`.
2. `CollectPulseTargets`가 `goldDrop > 0`을 1순위로 넣음. 암석 골드 포함.
3. `ApplyKind` 노란 색.

### 13-6. 가이드·퀘스트

1. 게임 가이드 한 줄.
2. 가스 퀘스트가 골드 가스 ID를 인식.

### 13-7. 검증 후 손대지 않을 것

- 광맥 크기 2~5, 내용 비율 10%.
- 드릴 레벨·심층 해금.
- 타일 기본 광물 수량 1.
- 수확량 업글 규칙 (`prompt-b97-mining-yield-upgrade.md`).
- 새 광산 500G / 3시간 타이머.

## 14. 테스트

자동 테스트가 생성·커밋·스캔 경로를 실제로 타야 완료다. PNG 존재만으로 완료하지 않는다.

### EditMode

| ID | 내용 |
| --- | --- |
| G-D01 | 같은 seed+좌표는 항상 같은 골드 여부. 다른 채널 솔트는 광맥 레이아웃을 바꾸지 않음 |
| G-D02 | `ComputeStableHash`가 골드 오버레이 전후 동일 |
| G-D03 | 경계 / 신호 / 엘리베이터 보호는 확률 100%여도 골드 없음 |
| G-D04 | 구리 골드량은 `unitPrice × 5`. 단가 10 → 50 |
| G-D05 | 가스 골드 DTO는 `containsGas == true`, `goldDrop == 50` |
| G-D06 | `BaseTileId("tile.gas-pocket.gold") == "tile.gas-pocket"` |

### 커밋

| ID | 내용 |
| --- | --- |
| G-C01 | 암석 골드 → 골드 +20, 인벤 불변, 전력 차감, 타일 제거 |
| G-C02 | 구리 골드 → 구리 +1(및 수확 보너스 기존 규칙) + 골드 +50 |
| G-C03 | 구리 골드 + 인벤 풀 → 실패. 골드 0, 타일 유지, 전력 유지 |
| G-C04 | 일반 암석 `goldDrop == 0` → 골드 0 |
| G-C05 | 커밋 취소/전력 부족 → 골드 0 |
| G-C06 | 퀘스트 지급·판매 경로는 `goldDrop`을 읽지 않음 |

### PlayMode / 통합

| ID | 내용 |
| --- | --- |
| G-P01 | 통합 Scene에서 골드 암석 1칸을 캐면 HUD 골드가 20 증가하고 피드백에 `골드 +20G` |
| G-P02 | 드론 스캔 반경 안에서 골드 칸만 노란 빛. 일반 구리는 흰 빛 |
| G-P03 | 골드 가스를 캐면 가스 구역이 활성화되고 골드 50이 들어옴 |
| G-P04 | 저장 후 이어하기: 캔 골드 칸은 비어 있고 잔액은 유지. 안 캔 골드 칸은 다시 금 스프라이트 |
| G-P05 | 튜토리얼 마커 구리 `(-7,-3)`는 골드 타일이 아님 |

## 15. 작업 체크리스트

구현 에이전트는 이 순서로 닫는다.

1. [ ] `MiningTileDto.goldDrop` + `GoldDropSettings` + 타일 ID 헬퍼
2. [ ] 원본 5장 기준 골드 박힌 PNG 5장 + Tile 에셋 + 256 PPU
3. [ ] 생성기 칸 해시 오버레이. 광맥 RNG / `generatorVersion` 불변
4. [ ] Resolver·Phase B/E 셋업에 골드 타일 등록 (드릴/전력은 기반과 동일)
5. [ ] `TryCommitMining` 골드 인자 + `MiningYieldCommit` + HUD 문구
6. [ ] 드론 `GoldDrop` 노란 빛 (암석 골드 포함, 광석 골드는 흰 빛 대체)
7. [ ] 게임 가이드 한 줄 + 가스 퀘스트 ID 허용
8. [ ] EditMode G-D*, G-C* 통과
9. [ ] PlayMode G-P* 또는 통합 Scene에서 골드 칸 채굴 1회 + 스캔 1회 기록
