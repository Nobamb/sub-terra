# 심층 구역 해금 전 36~40m 진입 차단

| 항목 | 내용 |
| --- | --- |
| **문서 제제** | Deep Zone Entry Lock (36~40m) |
| **날짜** | 2026-08-18 |
| **상태** | Draft |
| **관련 코드** | `Gameplay/Mining/MiningSystem`, `Gameplay/DemoWorld/MineLayer*`, `App/Progression/ProgressionService`, `App/Save/SaveRuntimeController`, `Shared/IDeepZoneAccessProvider`, `App/Integration/GameplayDepthStatusBridge` |
| **전제** | 월드 생성 알고리즘·광맥 분포·해금 조건(`DeepZoneUnlockRule.Mvp`)은 바꾸지 않는다. 해금 전후 체감은 **진입 가능 여부**로 만든다. |

---

## 0. 한 줄 결론

해금 전에는 플레이어가 **36m 경계에서 막혀야** 한다.  
해금 후에만 36~40m(리튬 층·봉인 신호)에 들어가 캐고 신호를 확인할 수 있다.

지금 해금은 `zone.deep` 기록 + UI 문구 + 봉인 신호 상호작용만 바꾼다. 깊이 진입은 막지 않는다. 이 문서의 작업은 그 빈 칸을 채운다.

플레이어가 해금 전후에 말할 수 있어야 하는 문장:

> “36m 아래는 봉인돼 있어서 못 내려갔다. 해금하니까 그 아래 리튬이 열렸다.”

이 문장을 못 만들면 해금이 아직 완결되지 않은 것이다.

---

## 1. 문제

플레이 체감과 카피가 어긋나 있다.

| 플레이어가 기대한 것 | 실제 |
| --- | --- |
| 해금 전 36~40m 진입 불가 | 첫 탐사부터 40m까지 이동·낙하 가능 |
| 해금 전 심층 자원 접근 불가 | 드릴 레벨만 맞으면 36~40m 리튬을 그대로 채굴 |
| 해금 후 “더 깊은 곳”이 열린다 | 팝업·탭 문구·봉인 신호 클릭만 바뀜 |

원인: 심층 해금이 **월드 접근 게이트가 아니라 진행 상태**로만 구현되어 있다.

---

## 2. 현재 구현 (코드 기준)

### 2-1. 지층은 처음부터 40m

`MineLayerDistribution` 기본값:

| Band | 깊이 | 내용 |
| --- | --- | --- |
| 상층 | 1~15m | 구리 |
| 중층 | 16~35m | 철·가스 |
| 심층 | 36~40m | 리튬 |
| 신호 | 38m, `x=14` | `tile.locked.signal` 1칸 |

맵 깊이는 항상 40m다. 해금 여부로 생성 범위를 줄이지 않는다.

타일 좌표:

```
cellY = TopY - depth + 1
```

기본 `TopY = -2`이면 깊이 35m → `y = -36`, 깊이 36m → `y = -37`.

HUD 깊이는 `DroneContextCalculator.CalculateDepth(surfaceY, playerY)`  
=`max(0, round(surfaceY - playerY))`다. 봉인 경계는 **HUD가 36m로 읽는 선**과 같아야 한다. `surfaceY`와 `TopY`가 어긋나면 플레이어는 35m인데 타일은 이미 심층이 되는 오차가 난다. 구현 전에 Integration Scene 값을 맞춰 확인한다.

### 2-2. 해금이 실제로 막는 것

`IDeepZoneAccessProvider.IsDeepZoneUnlocked` (`SaveRuntimeController`가 `zone.deep`을 읽음).

`MiningSystem.TryStartMining`은 **`tile.locked.signal`일 때만** 이 값을 본다.

- 해금 전: `MiningFailureReason.DeepZoneLocked`, 타일 유지
- 해금 후: 타일을 지우지 않고 `DeepZoneSignalAccessed`만 발생

리튬(`tile.lithium`)은 일반 채굴이다. 막는 조건은 `requiredDrillLevel: 2`뿐이다. `zone.deep`과 무관하다.

### 2-3. 보호 경로가 심층까지 뚫려 있다

`BuildProtectedRoute`는 `ProtectedRouteX`(기본 -9)로 **1m부터 SignalDepth(38m)까지** 세로 통로를 비운 뒤, 38m에서 신호 칸까지 가로로 잇는다.

`HasSafeRouteToSignal()`는 이 통로가 시작점→신호까지 통과 가능해야 한다고 검증한다.

그래서 해금 전에도 튜토리얼 축을 따라 떨어지면 38~40m에 도착한다. 채굴 게이트만 넣으면 이미 뚫린 구멍을 막지 못한다.

### 2-4. 해금 조건 (유지)

`DeepZoneUnlockRule.Mvp`:

- 완료 목표 1개 이상
- 드릴 속도 Lv.2
- 드론 스캔 Lv.2
- 가스 저항 Lv.1

조건 충족 시 `ProgressionService.TryUnlockDeepZone`이 `zone.deep`을 한 번 기록하고 팝업을 띄운다. 구매는 Surface Base에서만 하므로, **봉인 해제는 지상에서 확정되고 다음(또는 현재 세션의 다음) 하강부터 열린다.**

### 2-5. 하지 말 것

- 36~40m 지층을 생성하지 않는 방식으로 “잠금”을 흉내 내지 않는다. 시드·스냅샷·리튬 광맥이 깨진다.
- 봉인 신호를 지워 해금을 대체하지 않는다. 신호는 해금 **이후** 목표다.
- 해금 조건을 바꾸거나 업그레이드 수치를 건드리지 않는다.
- 전체 물리 시뮬레이션·별도 맵 Scene을 만들지 않는다.

## 3. 목표 체감

| 상태 | 허용 | 차단 |
| --- | --- | --- |
| 해금 전 | 1~35m 이동·채굴(기존 드릴/전력 규칙) | 36m 이하 이동, 36~40m 타일 채굴, 봉인 신호 확인 |
| 해금 후 | 36~40m 진입, 리튬 채굴(드릴 2 유지), 봉인 신호 확인 | 없음 (기존 바닥 경계암만) |

해금 전에도 **카메라로 36m 아래가 살짝 보여도 된다.** “저 아래가 잠겨 있다”가 보여야 한다. 다만 손·몸·낙하로는 넘어가지 못한다.

성공 문장:

1. 해금 전 보호 경로를 타고 내려가도 **36m 봉인에서 멈춘다.**
2. 35m에서 아래를 캐도 **심층 타일이 빠지지 않는다.**
3. 해금 팝업 후 재하강하면 **같은 자리에서 길이 열린다.**
4. 해금 전 세이브를 36m 아래에서 불러도 **35m 안전 칸으로 올려 보낸다.**

---

## 4. 범위

### In scope

- 해금 전 36m 수평 봉인(전폭 통과 차단)
- 해금 전 깊이 ≥ 36 타일 채굴 거부
- 봉인에 막혔을 때 한국어 실패 이유·짧은 안내
- 해금 후 봉인 해제(같은 런/다음 하강)
- 잠금 상태로 심층에 있는 세이브 위치 보정
- 보호 경로·안전 경로 테스트 재정의
- 심층 탭/가이드 문구를 “36m 진입 해금”에 맞게 수정

### Out of scope (후속)

- 해금 전 리튬을 다른 층에 배치
- 해금 후 추가 광맥·조명·BGM 전용 연출 (봉인 해제 이펙트 최소 1개는 In scope)
- 40m 이후 신규 지층
- 해금 조건을 드릴만으로 단순화
- 월드 생성기 시드/버전 변경

## 5. 설계

깊이 상수 하나와 세 겹 게이트를 쓴다. 하나만 넣으면 우회된다.

```
DeepZoneMinDepth = 36   // MineLayerDistribution 심층 band.MinDepth와 동일
```

단일 원천은 `MineLayerDistribution`의 심층 band 최솟값이다. 매직 넘버 36을 Mining/Player/UI에 흩뿌리지 않는다.

```
해금 전 하강
  → (1) 36m 봉인 타일/콜라이더에 막힘
  → (2) 그래도 심층 칸을 캐려 하면 Mining 거부
  → (3) 세이브·낙하로 선을 넘으면 35m로 보정
해금 후
  → (1) 봉인 비활성
  → (2) 심층 채굴은 기존 드릴 규칙만
  → (3) 봉인 신호는 기존 IsDeepZoneUnlocked 경로
```

### 5-1. 월드 봉인 (필수, 1차 차단)

해금 전, 깊이 36m 행 전체에 통과·채굴 불가 봉인을 깐다.

권장:

- 새 종류 `MineLayerCellKind.DeepSeal` 또는 기존 `BoundaryRock`과 구분되는 `tile.deep.seal`
- `isMineable = false`, 전력/시간 소비 없음 (`rule` Phase E: 경계/잠금 타일은 비용 없음)
- 좌우 경계암을 제외한 `MinX+1 .. MaxX-1` 전폭
- 보호 경로(`x = ProtectedRouteX`)도 **예외 없이** 덮는다. 지금 38m까지 뚫린 세로 구멍이 여기서 끊긴다.

생성기는 36~40m 리튬·신호를 **그대로 생성**한다. 봉인은 그 위(36m 한 줄)만 덮는다. 해금 후 그 줄만 걷어내면 아래 광맥이 드러난다.

해금 후 처리:

- 런타임에 봉인 줄을 `SetTile(null)` 하거나 통과 가능 타일로 교체
- 월드 스냅샷에 반영해 엘리베이터 왕복·이어하기 후에도 열린 상태 유지
- 이미 해금된 세이브로 Mine에 들어오면 생성 직후 봉인을 바로 걷는다

해금은 Surface에서 일어나므로, Mine Scene이 로드될 때 `IDeepZoneAccessProvider`를 읽어 봉인 on/off를 결정하면 충분하다. Mine 안에서 해금이 토글될 필요는 없다. 그래도 Provider가 바뀌면 즉시 반영하도록 구독은 넣는다.

### 5-2. 채굴 게이트 (필수, 사거리 우회 차단)

채굴 사거리는 약 1.35칸이다. 35m에 서서 36m 리튬을 대각/아래로 캘 수 있다.

`MiningSystem.TryStartMining`에 깊이 검사를 **잠금 신호 검사보다 앞이나 동등한 위치**에 추가한다.

```
cellDepth = TopY - cell.y + 1   // MineLayerLayout.GetCell과 동일
if (!deepZoneAccess.IsDeepZoneUnlocked && cellDepth >= DeepZoneMinDepth)
    → Fail(DeepZoneLocked)
```

`tile.locked.signal` 기존 분기는 유지한다. 해금 전 심층 실패 이유는 하나로 통일한다: `MiningFailureReason.DeepZoneLocked`.

HUD/채굴 실패 문구:

- 해금 전: `심층 구역이 잠겨 있습니다 (36m)`
- 해금 후 신호 확인: 기존 경로

리튬의 `requiredDrillLevel: 2`는 그대로 둔다. 해금과 드릴은 다른 축이다.

- 해금됨 + 드릴 1 → 진입은 되나 리튬은 드릴 부족으로 실패
- 드릴 2 + 미해금 → 36m에서 막힘, 리튬에 손도 못 댐

### 5-3. 위치 보정 (필수, 세이브·낙하 안전망)

봉인을 뚫고 들어가 있는 상태(구 세이브, 붕괴로 바닥이 사라진 경우)를 허용하지 않는다.

잠금인데 `Run.Depth >= 36` 이거나 플레이어 Y가 36m 선보다 아래면:

1. 깊이 35m, 가능하면 `ProtectedRouteX` 열의 비어 있는 칸으로 스냅
2. 그 칸이 막혀 있으면 같은 깊이에서 가장 가까운 빈 칸
3. `GameplayDepthStatusBridge.Refresh()`로 HUD를 즉시 35m로 맞춤

매 프레임 강제 클램프는 봉인이 정상이면 타지 않아야 한다. 봉인 충돌이 1차, 보정은 예외 처리다.

### 5-4. 안내

최소:

- 봉인 타일에 막히거나 심층 채굴이 거절되면 기존 채굴 실패/드론 안내 경로로 한국어 한 줄
- 심층 탭 본문: `해금 후 36~40m 진입과 리튬·봉인 신호 접근이 가능합니다`
- 잠금 상태 Surface/업그레이드 문구에 `현재 최대 진입 깊이 35m`를 넣는다

큰 연출·전용 컷신은 넣지 않는다. 봉인 줄 타일 비주얼(기존 경계암과 다른 색/무늬)이면 충분하다.

### 5-5. 보호 경로·생성기 테스트

생성 데이터上 보호 경로는 38m까지 남겨 둔다. 해금 후 그 축으로 신호까지 가는 동선이 유지돼야 한다.

테스트만 나눈다.

| 검증 | 잠금 | 해금 |
| --- | --- | --- |
| 시작점 → 35m 안전 경로 | 있음 | 있음 |
| 시작점 → 봉인 신호 | 없음 (36m에서 끊김) | 있음 |
| `HasSafeRouteToSignal` | 잠금 월드는 false이거나, API를 `includeDeepSeal`로 분기 | true |

기존 `MineLayerGeneratorTests`의 “항상 신호까지 통로” 단언은 **해금 후 레이아웃** 기준으로 옮긴다. 생성기가 심층 구멍을 없앤 것이 아니라, 런타임 봉인이 구멍을 막는 것이 맞다.

### 5-6. 스냅샷

봉인 줄은 월드 변경점이다.

- 잠금 생성 → 봉인 타일이 있는 스냅샷
- 해금 후 봉인 제거 → `miningChanges` 또는 동등한 변경점으로 빈 칸 저장
- 지상 저장이 빈 스냅샷으로 봉인 상태를 지우면 안 된다 (`elevator-mine-persist-plan.md`와 동일 원칙)

이미 해금된 슬롯을 이어하기하면 Mine 로드 시 봉인이 없어야 한다. 스냅샷에 봉인이 남아 있어도 Provider가 해금이면 로드 직후 한 번 더 걷는다.

## 6. 구현 순서

의존: **1 → 2 → 3 → 4 → 5**. 1만으로도 “못 내려간다”는 체감이 생긴다.

```
1. 깊이 상수 + 셀 깊이 계산 공유
2. 해금 전 36m 전폭 봉인 타일
3. MiningSystem 심층 깊이 게이트
4. 잠금 위치 보정 + HUD/문구
5. 테스트·생성기 단언 수정·수동 QA
```

### 6-1. 깊이 상수와 셀 깊이

- `DeepZoneMinDepth`를 심층 band에서 읽거나 Shared 상수로 고정하고 테스트로 band.MinDepth == 36을 잠근다
- 타일 셀 → 깊이 변환을 `MineLayerLayout.GetCell`과 같은 공식으로 한곳에 둔다
- `GameplayDepthStatusBridge`의 `surfaceY`와 `TopY`가 36m에서 같은 경계를 가리키는지 Integration Scene에서 확인한다

### 6-2. 봉인 타일

- `tile.deep.seal` (또는 동등 ID) + 채굴 불가 정의
- Mine 로드 시 `IsDeepZoneUnlocked == false`이면 깊이 36 행 전폭에 봉인
- true이면 봉인 행을 비운다
- `MiningTileResolver`에 등록. 보호 셀 예외를 두지 않는다

### 6-3. 채굴 게이트

- `MiningSystem`이 셀 깊이 ≥ 36 이고 미해금이면 `DeepZoneLocked`
- PlayMode: 35m 타일은 가능, 36m 리튬은 거부, 해금 후 동일 셀 허용
- 기존 봉인 신호 테스트는 그대로 통과해야 한다

### 6-4. 보정과 문구

- Mine 로드·Restore 직후 잠금+심층 위치면 35m 스냅
- 실패 문구 / 심층 탭 / Surface 잠금 문구에 35m·36m를 명시
- 해금 팝업 문장은 유지하되, 필요하면 `36m 아래 심층 구역이 열렸습니다`로 구체화

### 6-5. 테스트와 QA

## 7. 테스트

### 7-1. EditMode

- `DeepZoneMinDepth == 36` 이고 심층 band와 동일
- 셀 `(x, TopY - 36 + 1)`의 깊이가 36
- 잠금 레이아웃: 깊이 36 행이 전폭 봉인(좌우 경계 제외), 보호 경로 포함
- 해금 레이아웃: 깊이 36 행에 봉인 없음, `HasSafeRouteToSignal() == true`
- `GetDeepZoneAccess` / `TryUnlockDeepZone` 기존 조건 테스트 회귀 없음

### 7-2. PlayMode

- 미해금: 플레이어를 보호 경로로 낙하/이동시켜도 `Run.Depth`가 36에 닿지 않음
- 미해금: 36m 리튬 `TryStartMining` → `DeepZoneLocked`, 타일 유지
- 미해금: 35m 철/암석은 기존처럼 채굴
- 해금: 같은 경로로 40m 도달, 리튬 채굴(드릴 2), 신호 상호작용
- 미해금 + 플레이어를 38m에 두고 로드 → 35m로 보정, HUD 일치
- 해금 세이브 이어하기 → 봉인 없음

### 7-3. 수동 QA

1. 새 게임. 업그레이드 없이 축을 타고 하강. **36m에서 막힘.** 아래 리튬이 보여도 안 캐짐.
2. 드릴 2만 올리고 재하강. **여전히 36m에서 막힘.** (드릴 ≠ 해금)
3. 드론 스캔 2 + 가스 저항 1까지 올려 해금 팝업 확인.
4. 엘리베이터로 재하강. **막혔던 줄이 열려 36~40m 진입.**
5. 리튬 채굴, 봉인 신호 확인.
6. 해금 전 치트로 40m에 둔 뒤 저장→로드. **35m로 돌아옴.**

## 8. 위험

| 위험 | 대응 |
| --- | --- |
| HUD 36m와 타일 36m 줄이 한 칸 어긋남 | `surfaceY`/`TopY`를 맞추고, QA에서 HUD 35/36과 봉인 줄을 동시에 확인 |
| 보호 경로 테스트가 전부 실패 | 신호까지 통로는 “해금 후” 단언으로 이동 |
| 봉인 제거가 스냅샷에 안 남음 | 해금 슬롯은 로드 시 Provider 기준으로 봉인을 한 번 더 걷음 |
| 붕괴가 봉인 줄을 지움 | 봉인 타일은 보호 셀 또는 붕괴 후보 제외. 잠금 중 심층 천장은 붕괴 대상이 아님 |
| 기존 40m 세이브 | 잠금이면 35m 스냅. 이미 캔 리튬은 인벤에 유지(회수하지 않음) |
| 카메라가 봉인 아래를 너무 많이 보여 줌 | 허용. 진입만 막으면 된다. Confiner는 후속 |

## 9. 완료 기준

- 해금 전: 어떤 경로로도 36m 미만(더 깊은 쪽)에 발이 닿지 않는다.
- 해금 전: 36~40m 자원·신호를 캘 수 없다.
- 해금 후: 36~40m 진입·리튬·신호 확인이 된다.
- 해금 전후 차이가 이동만으로 느껴진다. 탭 문구를 보지 않아도 안다.
- 기존 해금 조건, 드릴 레벨, 40m 생성, 엘리베이터 월드 유지가 깨지지 않는다.

이 기준을 만족하면 “심층 구역 해금”이 진행 플래그가 아니라 **36m 문**이 된다.
