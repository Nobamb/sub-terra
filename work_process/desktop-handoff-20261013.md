- 이번 안내 문구 후속 변경도 사용자 요청으로 codex/demo-failure-recovery에 커밋·푸시한다. GitHub main에 병합됐다고 가정하지 않는다. 이 브랜치의 후속 커밋을 받은 뒤 정확한 HEAD를 기록한다.

- 사용자 변경/stash/저장 슬롯을 보존한다. git reset --hard, 전체 캐시 삭제, 사용자 Unity 강제 종료를 기본 절차로 사용하지 않는다.

## 실행 시작

1. Assets/_Project/Scenes/App/Bootstrap.unity를 열고 정상 컴파일 후 Play한다. Mine_Demo_Integration만 직접 실행한 결과로 새 게임·이어하기 통과를 판단하지 않는다.
2. 기존 전달 QA 빌드가 후보 소스를 포함하는지 먼저 확인한다. 오래된 빌드를 현재 소스 검증에 사용하지 않는다. 새 빌드는 필요한 경우 한 번만 만들고 커밋/빌드 ID/ZIP 해시를 기록한다.
3. 사용자 실제 저장을 덮어쓰지 않는 새 QA 저장 경로/슬롯을 사용한다. 경로 분리 인자는 QA/Development 지원을 확인한다. Release에서도 적용된다고 가정하지 않는다.
