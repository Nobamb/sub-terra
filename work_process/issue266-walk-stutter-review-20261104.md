# #266 느린 걷기에서도 끊겨 보이는 구간 검토

## 확인 범위

- 사용자 제보: 느린 시험 보행 GIF에서 걷기가 뚝 끊겨 보임.
- 기존 실제 실행 CSV, 원화8장, 중간/핵심 자세 비교표를 확인했다. 이번 검토에서 Unity나 전체 Demo 검사를 반복하지 않았다.
- 기존 코드 실행 근거는 `issue266-walk-rhythm-20261104/result.txt`의 PASS와 앞선 실제 광산 검사다. 자연스러운 걷기 완성 판정은 아니다.

## 관찰

1. 걷기 주기가 약0.90022초이고 고유 원화는8장이다. 각 자세를 약0.11초씩 유지하므로 프레임 전환이 보인다. 미리보기만60fps로 출력해도 새로운 자세가 생기지는 않는다.
2. `walk/key-02 → middle-02 → key-03`에서 middle-02는 양발이 벌어진 다음 contact 자세인 key-03과 비슷하다. key-02의 지나가는 다리 자세에서 이 contact까지의 중간 무릎/팔 위치가 부족하다. 팔과 몸통 원근도 한 번에 바뀐다.
3. `walk/key-04 → middle-04 → key-01`에서도 middle-04가 다음 key-01과 비슷한 보폭/팔 자세다. 두 '중간' 그림이 실질적인 자세 간격을 충분히 나누지 못한다. 세부적인 형태 차이도 있어 동일 프레임이라는 뜻은 아니다.
4. 실제 느린 이동 기록58개에서 인접 이동 표본 간격은 최대약0.0676초였다(정지 구간 사이의 간격 제외). 이동 중 매번 대기로 초기화되는 현상이나 수백ms짜리 기록 공백은 해당 구간에서 발견하지 못했다. 이 기록만으로 모든 환경의 프레임 끊김을 부정하지 않는다.
5. 정지에서는 `walk/middle-02 → idle` 등으로 즉시 전환된다. 낮은 걷기 자세와 팔 위치에서 서 있는 대기로 바로 바뀌는 별도 연결 간격도 남아 있다.

## 이번 조치와 게시 범위

- 두 문제 구간과 대기 참고를 묶은 `issue266-walk-stutter-review-20261104/pose-transitions.png`, 표본 요약 `inspection.json`을 남겼다.
- 원화의 부족을 시간 조절·프레임 복제·교차 페이드·팔다리 변형으로 해결했다고 하지 않는다. 이번 검토에서는 원화나 재생 코드를 추가 변경하지 않았다.
- 사용자가 커밋·푸시를 요청하여, 앞서 실행을 통과한 시험 속도/리듬 보정과 이번 검토 기록을 같은 PR #270 브랜치에 게시한다. 시험 중 이동 속도만 낮아지며 종료 시 원래 값으로 복원되는 구현이다.
- **끊김은 해결 완료가 아니다.** 현재 시험 보정을 완성 여자 모션 세트로 정식 적용하지 않는다.

## 다음 실제 수정 순서

1. middle-02 / middle-04를 앞뒤 핵심 자세 사이의 실제 중간 팔·무릎·발 위치로 **전신을 새로 그려 교체**한다. 원본8장은 보존하고 새 버전으로 비교한다. 얼굴·머리·몸통 방향이 유지되는지도 함께 확인한다.
2. 걷기→대기 정지 연결의 중립 자세1장을 먼저 제작한다. 어느 걸음에서 멈춰도 무조건 같은 자세를 재생해 자연스러울 것이라고 가정하지 않는다.
3. 이 연결 구간을 통과한 뒤 채굴·사다리 크기/손·드릴·발 접점 및 사다리 흰 잔점을 정리한다.
4. 전체 모션 세트 채택 후 게임 적용·캐릭터 선택·저장 연결을 진행한다.

## 미검증

- 새 중간/정지 원화는 아직 제작하지 않았다.
- 전체 지지발의 가로 미끄러짐, 경사·화물·피격/채굴 연결, 사용자가 실제 Game View에서 보는 최종 자연스러움.
