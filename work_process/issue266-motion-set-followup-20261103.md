- 사용자가 승인한 걷기 핵심4자세는 `e757084b`로 커밋·푸시했다. 브랜치 `codex/issue-266-character-selection`, 기존 PR #270에 반영된다.

## 배경과 프레임 배치

- 사용자가 허용한 코드는 배경/외곽과 전신 셀 배치에만 사용했다. `MiningWhiteMatte-20261103.cs`는 배경/외곽, `WholeCelLayout-20261103.cs`는 **연결된 전신 그림 전체**를 여백 있는 셀로 옮긴다.
- 일부 원화의 발/헬멧이 원래2×2 경계에 가깝거나 넘어가므로, 단순 격자 크롭은 하지 않았다. 전신 경계를 먼저 찾고 768×768 캔버스로 정수 픽셀 이동한다. 가로/세로 확대·축소, 팔다리 절단/변형은 하지 않는다. 자세별 이동은 `layout.txt`에 기록된다.
- 모든 새 검토 셀은768×768이다. **캔버스 크기가 같다는 것이 모션별 인체 크기·접점 정렬까지 완료됐다는 뜻은 아니다.** 실제 머리/발/손 기준과 Unity pivot/PPU 정렬은 다음 적용 단계에 남아 있다.
- 위4모션의 흰색/검정 합성에서 외부 잔점, 헬멧/신발 외곽, 치마 가림을 비교했다. 원화의 일반 반사광은 유지했다. 기존 사다리 흰 잔점 해결 판정은 별개다.

- 각 배경 정리본의 불투명 내부 RGB 변경0, 셀 외부4px 여백의 비투명 픽셀0.
- 걷기 GIF8프레임, 점프6/피격5/쓰러짐6프레임(정지/복귀 셀 포함), GIF/APNG4쌍 디코딩 정상. `motion-followup-verification-20261103.txt` 참조.
- 그림 수와 파일 검사는 자연스러운 완성 모션의 합격 판정이 아니다. **미검증:** 실제 반복 재생 인상, 걷기 체중 이동/머리 높이/팔 타이밍, 모션 간 장비·얼굴 비율, 완전한 관절 가림과 지지 발 미끄러짐, 실제 게임 속도/물리 궤적/모션 전환.
- 특히 걷기 중간 시트와 기존 핵심 시트의 팔 위치/몸통 원근, 점프 전후 치마 형태, 쓰러질 때 허벅지 장비/배낭 가림이 팀원 리뷰 대상이다. 완벽하게 일치한다고 보고하지 않는다.
- Unity 실행·게임 적용·전체 프레임 연결·캐릭터 선택·저장 검사는 하지 않았다.

## 이어서 할 일

1. 네 모션의 리뷰에서 튀는 **자세 번호**를 받아 해당 원화만 보정한다. 중간 프레임 수를 무작정 늘려 해결됐다고 하지 않는다.
2. 승인된 원화에서 필요한 연결 자세를 더 그리고, 걷기/점프/피격/쓰러짐 전환을 하나의 크기·발 기준으로 맞춘다.
3. 선택·저장 연결 전, 필요한 전체 프레임과 사다리/채굴 세트의 채택 여부를 확정한다. 미완성 여자 세트를 남자 이미지로 섞어 완성처럼 적용하지 않는다.
4. 이전 사다리 흰 잔점과 채굴 후속 리뷰는 별도 추적한다.
