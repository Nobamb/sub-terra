- 최신 origin/main을 기능 브랜치에 로컬 통합했다. 충돌 없음. 통합 커밋 66752dfc.
- 시설 퀘스트 10개의 저장된 씬 이미지 GUID/fileID와 해당 BuildingData.Icon이 모두 일치하는 것을 파일 참조 검사로 확인했다. B 목록과 상세 View도 같은 item.Icon을 사용한다. 메뉴·퀘스트에 임의로 새 그림이나 별도 배율 규칙을 추가하지 않았다.

## 다음 작업 순서 및 진행 상태

1. B 건설 메뉴·시설 퀘스트 이미지 반영: 최신 main 통합으로 기존 구현을 첫 번째 프로젝트에 반영했다. 새 게임 이미지를 보려면 첫 번째 프로젝트에서 Play를 종료하고 Bootstrap부터 다시 실행한다. 이미 실행 중인 이전 씬 인스턴스를 최종 결과로 판단하지 않는다.
2. 구형 시설 자동 확대와 이동의 통합: main의 안전한 자동 확대가 이동 기능과 함께 들어왔으므로 변경된 저장 경로의 좁은 검사 7개와 컴파일만 실행한다. 기존 11개 전체를 반복하지 않고 실제 게임 씬·Windows 빌드·성능 측정은 실행하지 않는다.
3. ComputeBuffer 종료 경고: 같은 버전의 패키지 소유 코드에 적용할 패치를 준비했지만 등록 정보 변경 허용 답변이 없어 미적용이다. 패키지 변경 허용이 확정된 후 최소 컴파일과 종료 재현만 수행한다.
4. 채굴 끊김: 제품과 측정 도구의 CPU 구간 분리는 준비했다. 10월 12일 전체 씬 Editor 측정은 메모리 압박으로 중단해 유효 결과 없음. 최소 검사 요청에 따라 재시도하지 않는다. 여유가 있는 데스크탑에서 동일 조건의 짧은 측정으로 병목이 확인된 부분만 수정한다.

사용자 폰트 stash, 기존 슬롯, 자동 설정 변경 보존 원칙을 유지한다. 관련 XML 결과는 아래 완료 기록에 남긴다.

## 메모리 압박과 캐시 정리

- 사용자가 렉을 보고했을 때 디스크 여유 10.9GB, 사용 가능한 RAM 약 0.36GB/전체 7.4GB였다. Unity와 에셋 가져오기 작업자 2개가 실행 중이었다. 디스크 여유만으로 정상 실행 성능을 보장하지 않는다.
- 사용자가 필요한 작업을 저장하고 Unity를 닫았다고 확인한 뒤, 실행 중인 Unity가 없는 것을 확인했다.
- 첫 번째 프로젝트의 Library/Bee(493.1MB), Library/PlayerDataCache(467.3MB), Library/BuildPlayerData(3.2MB), 비어 있는 BuildInstructions/TempArtifacts만 정리했다. 합계 약 0.94GB, 정리 후 디스크 여유 11.64GB였다.
- 소스·Assets·사용자 저장·Git·폰트 stash·에셋 가져오기 캐시 Artifacts·PackageCache·ShaderCache·ScriptAssemblies는 보존했다. 삭제한 빌드 캐시는 이후 필요할 때 다시 생성된다.
- Unity 종료 후 RAM 여유는 약 1.38GB였으며 다른 앱 사용에 따라 변한다. 캐시 정리가 모든 렉의 원인을 해결했다고 주장하지 않는다.
- 이후 작업에서 전체 씬 자동 측정/Windows 빌드는 기본으로 실행하지 않는다. 필요한 좁은 검사와 컴파일만 진행하고, 작업용 Editor는 검사 후 종료한다. 디스크·RAM 여유가 부족하면 무거운 검증을 시작하지 않는다.
