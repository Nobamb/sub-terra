## 조작 제안과 구현

- 시설에서 우클릭 → 바로 이동 미리보기 → 빈 위치에 좌클릭 확정 → 우클릭 취소.
- 좌클릭으로 시설을 먼저 선택하는 단계는 추가하지 않았다. 기존 채굴/시설 클릭과 충돌할 가능성을 줄이고 한 번의 우클릭으로 시작한다. 일반 시설 사용 E키는 유지한다.
- 이동 대상: PR #168의 조명·정산 콘솔·충전기·보관함·보건소. 엘리베이터/코어/사다리 등 기존 비지원 시설은 우클릭으로도 이동하지 않는다. 빈 곳의 우클릭은 아무 선택을 만들지 않는다.
- 기존 System.TryBeginMoveAt을 사용하여 시설 footprint 칸으로 대상을 고른다. 새 이동/보관/대기 상태 시스템을 만들지 않는다.
- B 메뉴의 이동 버튼은 보조 경로로 유지하며 텍스트를 '이동 (우클릭)'으로 바꿔 새 조작을 알린다. B 버튼으로 먼저 대상을 고르는 경로와 직접 우클릭 경로가 같은 초기화 메서드를 사용한다.
- 이동 중 우클릭은 원래 위치를 유지하고 미리보기를 정리한다. UI 위 우클릭은 월드 입력으로 처리하지 않으며 UiPauseGate 중에는 시작/취소 입력을 수행하지 않는다.
- 기존 건설 선택 중 시설을 우클릭하면 이전 건설 선택의 취소 이벤트를 전달하고 이동으로 전환한다. 지원되지 않는 대상을 누르면 기존 선택은 유지한다.
- 비용 차감/설치 점유/이동 이벤트/시설 인스턴스 ID/보관 내용/충전·회복 대기 유지 규칙은 기존 #168 이동 경로를 사용한다.

## PR #181 게시 이후: 시설 아래 호버 안내

- 사용자가 시설에 마우스를 올릴 때 작게 '우클릭 이동' 안내를 요청했다. 기존 시설 이름표의 청록 프레임을 재사용해 바닥 중앙 아래에 `우클릭 · 이동`을 표시한다.
- 같은 시설에 0.15초 머물면 등장한다. 이름표보다 작은 0.008 월드 배율이며 바닥에서 0.08 간격을 둔다. 상단 시설 이름과 아래 조작 안내가 겹치지 않도록 분리했다.
- 실제 우클릭과 호버는 System.TryGetMovableAt/CanMoveInstance의 같은 지원 대상 판정을 사용한다. 호버는 선택/위치/점유/자원을 변경하지 않는다. 빈 칸은 점유 사전에서 먼저 제외하고, 안내 Canvas는 하나만 생성해 재사용한다.
- UI 위, 이동/건설 선택 중, 일시정지, 비지원/비활성 시설, 시설 이탈, Bridge 비활성화 때 즉시 숨긴다. Bridge 파괴 시 안내도 정리한다. UI 입력을 가로채는 레이캐스터는 추가하지 않는다.

- 기존 회귀 검사에 조회 후 선택/이동 상태 및 위치가 그대로인지, 바닥 중앙 좌표가 맞는지, 비활성 시설 조회가 거부되는지 추가했다. Native NUnit 실행은 하지 않았다.
