# #266 여자 대기·걷기 Play 한정 시험

## 게시와 범위

- 대기→걷기 진입 검토본은 사용자 승인으로 **2971f632** 커밋·푸시. 기존 PR #270 브랜치에 반영했다.
- 이어서 사용자가 **대기·걷기만 시험 적용**을 선택했다. 정식 여자 세트·캐릭터 선택·저장 연결은 이번 범위가 아니다. 초기 도구는 로컬에 남겼으며, 11월4일 거리/접지 보정 후 게시 승인을 받아 같은 브랜치에 함께 반영한다.
- 추가 도구는 `Assets/_Project/Editor/FemaleLocomotionReviewWindow.cs`와 `FemaleLocomotionReviewSmoke.cs` 및 Unity 생성 meta다. 런타임 게임 코드·기존 프리팹·씬·세이브·패키지·설정은 변경하지 않았다.

## 시험 표시 도구

1. 첫 번째 Unity 프로젝트를 연다 (`sub-terra/`).
2. `Assets/_Project/Scenes/Bootstrap/Bootstrap.unity`에서 Play 후 광산으로 진입한다.
3. 메뉴 `SubTerra > Review > Female Idle Walk (Play Only)`를 연다.
4. `대기·걷기 시험 켜기`를 누른다. 걷기 한 주기 기본1초, 진입 기본0.16초로 시험한다. 현재 8장에 기존 남자40fps를 그대로 쓰지 않는다.
5. 평지에서 출발·정지·좌우 전환을 확인한다. 실제 속도 표시와 주기 슬라이더를 비교한다.
6. 시험 끄기·Play 종료·창 닫기·스크립트 재로드 시 임시 그림과 텍스처를 해제한다.

- 원래 대기/걷기 Sprite 집합을 확인하고 Game 카메라가 렌더할 때만 임시 여자 Sprite를 표시한다. 렌더 종료 때 원래 Sprite로 복원한다. `ConfigureFrames`/SerializedProperty 쓰기/AssetDatabase 저장을 사용하지 않는다.
- 점프·채굴·사다리·피격 등은 **원래 모션으로 표시**한다. 여자 전체 세트 적용처럼 보고하지 않는다.
- 검토 PNG는 저장소 `work_process/images/issue266/`에서 직접 읽는다. PPU 약667.42857/pivot 약(0.4592634,0.50390625)은 앞선 정렬 기록의 기존 VisualRoot 보존 후보다. 정식 임포터/meta에 적용하지 않았다.
- 최저 불투명 신발 픽셀의 진단점은 화면 발 위치 비교용이다. IK 접점이나 어느 다리가 지지 다리인지 판단하는 장치는 아니다.

## 자동 Play 검사

- 명령: Unity6000.5.4f1 `-batchmode -projectPath <Unity프로젝트> -executeMethod SubTerra.Editor.FemaleLocomotionReviewSmoke.Run -logFile <로그>`.
- Bootstrap에서 Play 한 뒤 임시 평지에 실제 Player 프리팹을 생성한다. 이동/애니메이션 외의 입력·플레이 상태 컴포넌트는 임시 인스턴스에서 비활성화한다. 실제 이동 속도/가속·물리와 SpriteRenderer를 사용한다.
- 새 게임/슬롯/세이브 API는 호출하지 않는다. 실제 광산의 충돌·경사·화물·시설·이펙트/입력 전체와 동등한 검사는 아니다.
- 첫 실행은 잘못 지정한 Bootstrap 경로 때문에 중단됐다. 실제 경로를 검색해 수정했다. 재시도는 컴파일 및9시점 캡처, 카메라 렌더 종료 후 원래 Sprite 복원, 시험 종료를 통과했다.
- 연속 캡처 후속은 `issue266-locomotion-play-review-20261103/`에 기록한다. 최종 결과와 제한은 아래에 추가한다.

## 실제 실행 결과

- Unity6000.5.4f1에서 새 도구 컴파일 통과. 후속 Play 검사는 약4.75초의 실제 이동, 출발/정지/좌우 전환, 카메라 렌더 직후 원래 Sprite 복원, 도구 종료를 실행했다. `result.txt`의 PASS는 이 **도구/임시 무대 실행 검사**만 가리킨다. 자연스러운 걷기나 발 미끄러짐 해결 판정이 아니다.
- 실제 캡처29시점과 이동/신발 진단점 CSV를 남겼다. 느린 노트북의 캡처 간격이 일정하지 않아 GIF는 CSV의 실제 시간 간격으로 생성했다. 이상적인60fps 재생이나 성능 측정 자료가 아니다.
- 걷기8자세 모두와 진입2자세가 기록에 등장했다. 흰/검정 원화 비교뿐 아니라 이번 실제 렌더 캡처9장 묶음도 직접 확인했다.
- **미끄러짐 발견:** 기본1초 주기에서 실제 최고 가로 속도 약5.76456unit/s. 같은 걷기 그림/접지 상태가 연속 기록된2구간에서 최저 불투명 신발 진단점의 가로 변위는 최대0.472unit였다. 이 값은 동일 이미지의 화면상 신발 픽셀이 움직인 값이며 지지 다리/IK의 정확도나 전체 구간의 미끄러짐 최대값을 보증하지 않는다.
- 진단점의 높이는 일부 접지 구간에서999.44unit, 임시 바닥 상단은999.5unit였다. 약0.06unit의 접지 표시 차이도 남아 있다. 기존 남자 표시와 실제 광산의 VisualRoot/콜라이더 대조 전에는 여자 원화만의 문제라고 결론내리지 않는다.
- 초반에 플레이어가 바닥에 정착하는 동안은 원래 점프/착지 모션이 표시된다. 이는 대기·걷기만 시험하는 도구의 범위 밖 표시이며 여자 모션 세트의 일부라고 하지 않는다.
- `actual-play-trial.gif`는 이번 실제 임시 무대 렌더 연속 캡처다. 초기화부터 좌우 출발/정지까지 포함하며 실제 광산 영상은 아니다. `contact-half.png`, `movement-trace.csv`, `sole-diagnostic.json`도 함께 보존했다.
- Unity 실행 로그에는 라이선스/서비스 연결 및 Codex 프로세스 서명 수집 등의 환경 경고가 있다. 게임 코드 예외가 없다는 말로 환경 경고까지 없었다고 표현하지 않는다.
- 실행 종료 후 `git status`에서 기존 사용자 문서 수정 외에 기존 프리팹·씬·ProjectSettings·Packages 변경 없음. 이번 추가 Editor 도구와 meta/검사 기록은 아직 커밋·푸시하지 않았다.

## 바로 다음 보정

1. 여자 그림의 보폭과 실제 이동 거리 차이를 기준으로 **시험용 거리 기반 재생**을 비교한다. 게임 이동 속도나 남자40fps를 여자 그림에 맞추느라 일괄 수정하지 않는다.
2. 실제 Player VisualRoot에서 남자/여자 최저 발 위치를 같은 지면에 겹쳐 비교하고 필요한 여자 표시 오프셋만 확정한다.
3. 그 뒤 실제 광산 Play에서 벽/화물/카메라/시설과 함께 확인한다. 캐릭터 선택·저장은 여자 전체 세트 채택 후 진행한다.

## 남은 수동 확인

- 실제 광산 화면에서 카메라/시설/지면과 함께 표시되는 크기와 발 접점.
- 화면에서 팔·무릎·머리 높이의 진입 변화가 거슬리지 않는지.
- 무거운 화물, 벽 밀기, 일시정지, 점프/채굴 진입, 좌우 반전과 시험 종료.
- 게임이 실제로 수정한 속도를 기준으로 재생 주기를 정할지, 거리 기반으로 바꿀지 결정. 원화의 좁은 보폭과 빠른 이동 속도 차이를 그림 장수만 늘려 해결했다고 하지 않는다.
