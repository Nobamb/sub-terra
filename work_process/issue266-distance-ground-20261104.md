# #266 여자 대기·걷기 거리 재생과 접지 보정

## 범위

- `codex/issue-266-character-selection`, 어제 게시본2971f632 이후의 시험 도구 작업. 후속 요청에서 커밋·푸시 승인을 받아 기존 PR #270 브랜치에 게시한다.
- 원화/신체 부위/장비/의상은 변경하지 않았다. Editor의 Play 한정 대기·걷기 표시를 수정했다. 정식 여자 세트·선택 UI·저장 연결은 이번 범위가 아니다.
- 기존 Player 프리팹·이동 속도6·가속/충돌·남자40fps·게임 저장 스키마를 수정하지 않았다.

## 바뀐 동작

- `FemaleLocomotionReviewWindow.cs`: 걷기 진행을 실제 가로 이동 거리로 계산한다. 기본 한 주기 이동 거리0.78 local unit은 기존 그림의 가까운 발 이동 폭 약260px/반주기와 PPU667.42857을 참고한 **검토값**이다. 실루엣/지지 다리의 정밀 계측값으로 확정한 것이 아니다. 실제 Transform의 가로 배율을 반영한다.
- 진입2자세도 이동 거리0.12 local unit 기준으로 진행한다. 8장에 남자40fps를 적용하지 않는다. 이전1초 고정 재생과 비교하는 토글은 유지한다.
- 벽을 밀고 있어도 실제 속도가0이면 대기한다. 입력을 놓고 감속하는 동안은 실제 속도를 따라가며, 정지/좌우 반전/큰 위치 이동 시 진입 상태를 초기화한다.
- `바닥 높이에 발 맞춤`: 몸통 콜라이더 아래의 외부 지면을 Raycast로 확인한다. 자기 콜라이더/Trigger/벽 노멀은 제외한다. 여자 그림 최저 불투명 신발 픽셀을 지면에 맞추는 세로 표시 이동만 적용하며 보정 한도는±0.15unit이다. 접지하지 않았거나 지면을 찾지 못하면 적용하지 않는다.
- 카메라 렌더 종료 시 원래 Sprite와 Transform 위치를 복원한다. 콜라이더·이동 위치·프리팹·meta 임포트 설정을 수정하지 않는다.
- 남자 대기 PNG의 최저 신발 픽셀도 같은 위치에서 별도로 측정한다. 여자 그림을 원래 남자 발 위치에 맞췄더라도 실제 콜라이더 지면보다 낮을 수 있다는 점을 구분한다.

## 실행한 최소 비교

- Unity6000.5.4f1, Bootstrap Play 안에서 같은 Player 프리팹·임시 평지/벽·이동 속도로 기존 시간 재생과 거리/접지 재생을 순서대로 비교했다.
- 기존 시간 방식: 기록76개, 지면과 신발 진단점 차이 최대0.0601unit, 정지 상태 중 걷기/진입 표시16개.
- 거리/접지 방식: 기록86개, 접지 측정81개에서 지면 차이0, 정지 상태 중 걷기/진입 표시0개. 양쪽 최고 속도는 동일하게5.76456unit/s였다.
- 같은 걷기 그림이 연속 기록된 쌍은 기존25개/수정0개다. 수정 쪽의 해당 값이 없으므로 **미끄러짐0이나 개선율을 계산하지 않는다.** 거리 재생의 보폭·리듬과 지지 다리 가림 일관성은 시각 리뷰 대상이다.
- 남자 대기 참고 발도 바닥보다 약0.06unit 아래에 측정됐다. 따라서 어제의 침하를 여자 원화 피벗 하나만의 오류로 단정하지 않는다. 이번 보정은 여자 시험 표시만 대상으로 한다.
- 보정 전후 실제 렌더9시점 묶음을 직접 확인했다. Sprite뿐 아니라 렌더 직후 Transform도 원래 값으로 복원되는지 검사했다.
- 광산 후속: 별도 시험 저장 폴더를 명령줄로 지정해 Bootstrap→새 게임→SurfaceBase→Mine 씬 로드까지 실행했다. 첫 검사에서는 이후 이동 시작 조건을 기다리다 시간 제한에 걸려 **전체 결과 FAIL**이다. 평지 비교 통과와 광산 이동 통과를 섞어 보고하지 않는다.
- 기존 통합 검사에서 사용하는 최초 퀘스트 진행 데이터 준비를 반영해 광산 부분만 별도로 재실행한다. 첫 대기의 정확한 원인은 최종 진단 전까지 미확정이다.

## 광산만 재실행한 결과

- `RunMineOnly`는 평지 비교를 반복하지 않고 별도 시험 슬롯으로 Bootstrap→SurfaceBase→Mine을 진행했다. 기존 통합 검사와 같은 최초 퀘스트 진행 데이터를 설정한 뒤 이동 검사를 실행해 **PASS**를 기록했다. 첫 검사의 정확한 대기 원인을 확정한 것은 아니다.
- 실제 광산의 기존 바닥/엘리베이터/카메라에서 약1.8초 출발·정지·반대 방향 이동을 실행했다. 검사를 위해 임시 인스턴스의 PlayerController 입력만 잠시 비활성화하고 PlayerMovement.SetMoveInput을 사용했다. 끝날 때 입력과 원래 Sprite/Transform을 복원했다. 실제 키보드 입력 검사는 아니다.
- 광산 기록9개 중 여자 표시/접지 측정7개에서 신발 진단점과 지면이 모두 y=-1로 일치했다. 최고 속도5.76456unit/s, 정지 기록2개 모두 대기였다. 세로 보정량은 약0.055~0.059unit. 같은 위치의 남자 대기 참고 발은 최대0.06251unit 아래에 측정됐다.
- `mine-contact-half.png` 묶음과 원본 `mine-04.png`를 직접 확인했다. 원래 월드·광산 카메라를 사용한 실제 캡처이며 대상 RenderTexture에는 화면 전체 HUD가 포함되지 않는다.
- 재실행 폴더의 `movement-trace.csv`, `comparison.json`, `mine.gif`, `result.txt`에 별도 보존했다. GIF는 기록된 시간 간격을 쓰지만9시점 저빈도 검사 캡처이므로 모션의 부드러움을 판정하는 완성 영상으로 제시하지 않는다.
- RunMineOnly 결과 메시지에는 공통 코드의 'Before/after fixture' 문구도 들어 있으나 **이번 재실행에서 평지 검사를 다시 한 것은 아니다.** 평지 비교 근거는 앞선 실행의 기록이다.
- 컴파일과 실제 실행에서 새 C# 오류는 검출되지 않았다. 첫 광산 준비 타임아웃, 라이선스/서비스 경고, D3D12 업로드 버퍼 경고 등은 로그에 남아 있다. Windows 빌드/전체 Demo 검사/성능 측정은 하지 않았다.

## 이번 판정

- 구현/실행 확인: 실제 거리 기반 재생, 벽 막힘·정지 시 대기, 기존 움직임 속도 유지, 발 세로 지면 맞춤, 렌더/시험 종료 후 원래 표시·위치 복원, 실제 광산의 짧은 이동.
- **미검증/추가 리뷰:** 지지하는 발의 전체 가로 미끄러짐, 빠른 이동에서의 자연스러운 리듬, 8장 사이의 원화·얼굴·장비 일관성, 경사/큰 화물/점프·채굴 전환. 같은 그림 연속 측정이0쌍인 것을 미끄러짐0으로 해석하지 않는다.
- 원화/게임 속도 변경 없이 거리 재생을 적용한 단계다. 빠른 현재 속도에서는 주기가 약0.13초로 짧아질 수 있다(0.78×0.95/5.76456). 부드러운 최종 보행 판정에는 실제 Game View 재생 리뷰가 필요하다.

## 남은 시각 판단

- 8장의 짧은 보폭과 현재 빠른 이동 속도를 맞추면 재생 주기가 짧아진다. 거리 동기화만으로 부드러운 걷기 완성이라고 하지 않는다. 게임 이동 속도를 임의로 낮추거나 그림을 과장해 늘리지 않았다.
- 실제 광산에서 추가적인 화물 배율·지면 경사·점프/채굴 전환은 별도 확인 대상이다. 이번에는 대기·걷기와 짧은 방향 전환만 우선 확인한다.
