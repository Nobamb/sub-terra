- 이전 #252의 ESC 창 닫기 요구 대신 #260의 새 규칙(ESC=설정, X=현재 창 닫기)을 적용한다.

## 변경

- SurfaceBaseBinder.Update: ESC에서 다른 팝업을 먼저 닫는 처리와 모달/닫힘 중 설정 열기를 막는 조건을 제거한다. 설정창이 열렸으면 취소, 아니면 기존 설정 버튼 경로로 연다. 개발자 터미널 가드는 유지한다.
- SurfaceBaseView.SetSettingsVisible: 설정창을 켤 때 업그레이드를 닫던 부작용을 제거한다. 기존 최상단 정렬·열림/닫힘 연출을 재사용한다.
- 설정 적용 시 광산 초기화 확인창을 닫던 부작용도 제거해 설정 아래 창을 유지한다.
- X·설정 닫기 버튼·업그레이드 U·인벤토리 I·기존 닫힘 연출·효과음 및 광산 입력 코드는 유지한다. 씬/프리팹/ProjectSettings/Packages 변경 없음.
- 기존 인벤토리 검사에서 업그레이드 닫기를 ESC 대신 X로 바꾸고, 설정 표시 검사는 기존 창 유지로 갱신한다.
- 신규 PlayMode 검사: 지상 퀘스트·업그레이드·인벤토리에서 ESC로 설정 열기, ESC/X로 설정만 닫기, 이어서 X로 기존 창 닫기를 확인한다.

## 검증

- EditMode 관련 기존 창 유지 검사 1/1 통과(4.835초).
- 첫 PlayMode 실행은 `-nographics`에서 기존 해상도 검사 도구가 `No graphic device is available to initialize the view`를 출력해 중단됐다. 게임 입력 동작의 실패로 분류하지 않는다. 그래픽 모드에서 같은 1건을 재실행한다.
- 새 검사만 지상 씬 로딩 제한을 30초로 지정한다. 다른 검사는 기존 10초를 유지한다. 화면 증거는 `work_process/images/issue260/`에 남긴다.
- 그래픽 모드 PlayMode 재실행 1/1 통과(25.205초, ExitCode 0). 퀘스트·업그레이드·인벤토리를 유지한 채 ESC로 설정을 열고, ESC/X로 설정만 닫은 후 X로 기존 창을 닫는 입력 흐름을 확인했다.
- 퀘스트/업그레이드 위 설정창 캡처를 절반 크기로 묶어 `comparison.jpg`에서 확인했다. 설정이 전면에 표시되며 업그레이드가 뒤에 남아 있다. 퀘스트는 설정창에 가려져 유지 여부는 화면만으로 판단하지 않고 런타임 IsOpen 검사와 후속 X 닫기로 확인했다.
- 최종 컴파일 성공, diff 공백 검사 통과. 검사 중 자동 갱신된 폰트는 시작 시 깨끗했던 상태로 복원했다. Unity 검사 프로세스 종료 확인. 기존 다른 단축키 검사 전체나 Windows 빌드는 추가 실행하지 않았다.
- 사용자 슬롯을 읽거나 저장하지 않는 기존 UiTestEnvironment 지상 씬을 사용한다.
