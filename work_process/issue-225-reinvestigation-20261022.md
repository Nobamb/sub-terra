## 확인된 사실

1. 기존 #225는 흔들림 복제본을 전경보다 앞으로, 배경은 전경보다 뒤로 정렬한다. 원본 alpha=0 + 별도 SpriteRenderer 복제본이라는 구조는 그대로다.
2. StructuralCrackOverlay.cs 441~451행에서 전경의 sharedMaterial을 복제본에 배정하고 원본 셀 alpha를 0으로 바꾼다. 416행에서는 기존 복제본의 Sprite 참조만 갱신한다. Tilemap의 전체 변환·재질 변경·출력 픽셀이 항상 동일하다는 검증은 없다. 이 차이가 실제 제보의 원인이라는 뜻은 아니며 렌더링 비교가 필요한 후보 경로다.
3. MineTileCornerVisual은 런타임에 전경 재질을 MineRoundedCorners로 교체한다. 따라서 기본 Sprite 셰이더/1픽셀 흰 Sprite인 합성 fixture 검사는 실제 타일·둥근 모서리 셰이더와 같은 조건이 아니다.
4. 기존 검사는 GetSprite/GetTile/색·정렬 값과 인접 bounds를 검사했다. 실제 렌더 픽셀이나 암부 점프 장면을 검사하지 않았다. 이 통과만으로 제보 해결 완료를 선언할 수 없다.
5. 실제 씬의 생성기·채굴·구조 시스템은 같은 ForegroundTilemap(1443727076)을 참조한다. 암부 코드는 화면 마스크/점유 텍스처를 사용하며 광석 TileBase를 일반 암석으로 SetTile하는 경로는 찾지 못했다.
6. 씬의 균열 Tile은 실제 yellow/orange/red overlay PNG에 연결돼 있다. PNG 원본 alpha 조사: 완전 투명 픽셀 약 84.83%/85.11%/82.24%, 평균 alpha 0.067/0.079/0.100. 그림 전체가 불투명한 일반 암석이라는 가설은 지지하지 않는다. 렌더링 결과 자체를 증명한 것은 아니다.
7. 추가 결함 후보: 실제 씬의 MineLayerTilemapGenerator.structuralSystem 참조는 null(씬 10038행). Regenerate의 재생성 전 ClearRuntimeRiskState는 이 경우 실행되지 않는다. EditorConfigure만 참조를 채우며 런타임 fallback은 없다. WorldSnapshotSystem은 복원 끝에서 별도 위험 재구성을 수행하므로 이 누락만으로 이어하기/점프 증상 전체를 설명할 수는 없다.

## 제안하는 해결 순서

1. 동일 셀에서 기본 표시/현재 흔들림/복제본 없이 원본 표시를 비교한다. 구리·철·가스와 일반 암석, 암부 밖/안, 모션 감소 조건을 고정한다. 논리 Tile ID와 실제 그린 Sprite/재질을 함께 비교한다. 단순 GetSprite 확인으로 종료하지 않는다. 복제본을 제외하면 두 증상이 함께 없어지는지, 어느 하나만 없어지는지 구분한다. 원본만 표시해도 남는 증상은 모서리 셰이더·배경·화면 마스크의 별도 경로로 조사한다.
2. Demo에서 안전한 최소 대안: 원본 타일 alpha·색·플래그를 변경하지 않고 원본을 계속 표시한다. 광석 본체 복제본은 만들지 않고 균열의 작은 흔들림·농도 변화·분진으로 위험을 전달한다. 원래 본체가 흔들리는 연출은 줄어드는 명시적인 변경이다.
3. 본체 흔들림을 반드시 유지해야 한다면 실제 셰이더·재질·변환 조건을 재현한 후 별도 설계한다. 정렬 숫자만 다시 변경하거나 Tilemap collider 갱신 비용을 확인하지 않고 SetTransformMatrix로 치환하지 않는다.
4. 재생성 전 참조 누락은 런타임 참조 복구 또는 기존 builder를 통한 연결로 보완한다. scene YAML을 직접 편집하지 않는다. 정상 복원 뒤 위험 재계산과 원본 색/플래그 복구도 확인한다.
5. 수정 후 최소 검사는 원본 표시 보존·인접 광석 보존·제거/재생성 3범위와 실제 재현 화면 한 구간으로 제한한다. 후속 커밋은 기존 PR #225에 추가한다. #211 및 다른 PR과 섞지 않는다.
