# 최종 선택: 팀원 GIF 배경 제거 및 동일 동작 적용

## 사용자 선택과 범위

- 사용자는 첨부한 팀원 GIF를 배경만 정리해 사용하고 이번 걷기 작업을 마무리하도록 요청했다.
- 이전 AI 신규 원화/왕복 재생/속도 비교 작업은 채택 경로에서 제외한다. 팀원 캐릭터를 다시 그리거나 신체를 분해·변형하지 않는다.
- 원본 사본: `images/teammate-walk-gif-20261027/source.gif`.
- 원본은 **512×539, 47프레임, 각100ms(10fps), GIF 전체 반복4.7초**다. GIF에 들어 있는 동작 순서를 그대로 쓰며 16장으로 줄이거나 역순으로 돌리거나 임의로 1초에 맞추지 않는다. 4.7초는 전체 GIF 반복 길이이며 한 걸음에 강제한 시간이 아니다.

## 배경 처리

- `tools/prepare_teammate_walk.py`: GIF의 프레임별 합성 결과를 읽고 외부와 이어진 검정 배경만 투명하게 만든다.
- GIF의 검정 배경이 프레임마다 서로 다른 아주 어두운 색으로 양자화돼 있어 단일 RGB 색만 지우면 검정 조각이 남았다. 가까운 검정색 영역을 외부에서 구분하고, 몸체 색에 인접한 2px 안의 원본 어두운 윤곽은 보존했다. 눈동자 같은 닫힌 내부 검정 영역은 제거하지 않는다.
- **원본 크기 투명 PNG 47장의 RGB는 원본 GIF의 같은 프레임과 완전히 같다.** 변경은 배경 알파이며 얼굴·장비·팔다리를 재생성/변형하지 않았다. 원본의 미세한 흐림/눈깜빡임/동작도 유지한다.
- `transparent-walk.gif`: 투명 배경의 재생 파일. 47장·각100ms 유지. GIF의 팔레트 제한으로 작은 색 양자화 차이는 있지만, PNG에는 원래 RGB를 보존한다.
- 투명 GIF를 다시 디코딩하여 47장/4700ms, 각 프레임의 알파가 투명 PNG와 정확히 같은지 확인했다. 이전 프레임이 누적되는 출력 잔상을 검사했다.
- 47장 전체를 흰색·검은색 배경 비교표로 확인했다. 초기에 남은 큰 검정 조각은 제거했다. 이 기록은 원본 GIF의 작화나 물리적인 보행 전체를 새로 검증했다는 뜻은 아니다.

## 게임 적용

- 원본 전체 이미지에 공통 배율과 위치 정렬만 적용한 `runtime-frames/walk-01.png`~`walk-47.png` (256×256 RGBA)를 사용한다. 기존 Idle과 비슷한 226px 키, 발 기준점 약16px에 맞췄다.
- 런타임/클립/가이드/조작 단말은 **47장·10fps**로 통일했다. 빌더가 이 경로만 등록하므로 이전 AI 원화로 되돌아가지 않는다.
- 기존 `walk_01`~`walk_16` GUID를 보존하고, 17~47 및 해당 메타데이터는 Unity Editor로 생성했다. 프리팹의 47개 배열과 가이드 그림 목록도 Editor API로 갱신했다. YAML 수동 편집 없음.
- 기존 문서의 16장/1초는 이전 적용 이력이다. 현재 재생을 설정하는 값이 아니다.

## 최소 검증 결과

- Unity 6000.5.4f1, 배치 실행 `RedrawnWalkCycleBuilder.BuildAndValidate`.
- EditMode `PlayerWalkCycleTests` **3건 통과 / 실패0 / 누락0 / ExitCode0**, 약3.56초.
- 검증: 원본에서 준비한 47 PNG와 실제 런타임 PNG 바이트 일치, 47개 참조/재생순서/4.7초 반복/Idle 복귀, 클립 속도·길이, 가이드 동일47장·10fps, 키/발 기준점/잘림.
- 빌더의 Idle→Walk 입력 점검도 실행했다. 실제 Bootstrap 플레이 화면과 Windows exe는 이번에 실행하지 않았다.
- ProjectSettings와 Packages manifest/lock은 실행 전 해시와 일치한다. 버전 변경 없음.
- 로그/결과: `work_process/tools/teammate-walk-gif-20261027/` (로컬 검증 캐시는 커밋하지 않는다).
