# B-149 드론 분석 창 터미널 연출 + 점수 표시 제거 (#119)

## 목표
드론 분석 창(Digger-Bot 창)은 지금 즉시 켜지고 꺼지며, 글자도 0.5초마다 통째로 바뀌어서 밋밋하다.
CCTV 창과 런 실패 연출에 이미 있는 효과를 재사용해서 터미널 느낌의 열기·타이핑·닫기 연출을 넣는다.
화면에 보이는 점수 숫자는 빼고, 근거 줄에는 실제 수치를 보여 준다.

## 먼저 읽을 코드
- App/UI/Drone/DroneDialoguePanelView.cs (현재 창: 헤더, 대사, 추천, 근거 목록)
- App/UI/Drone/DroneRecommendationPresenter.cs, DroneUiBinder.cs (0.5초마다 다시 분석)
- App/Drone/DroneAnalysisModels.cs (Recommendation, Reasons의 ActualValue·Unit, IsUrgent)
- App/Drone/DroneAnalysisService.cs (추천 선택: 안전 우선순위 → 점수)
- App/Drone/DroneOperationalState.cs (IDLE / SCANNING / PRIORITY)
- App/UI/HUD/HudPanelChromeController.cs (Tab·드론 클릭 토글, X 닫기)
- Editor/DataValidation/PromptB34DiggerBotUiBuilder.cs (레이아웃)
- 재사용 참고
  - CoreCctvTimeline / CoreCctvPopupView / CoreCctvArt: 가로선 펼침 열기, 한 줄씩 타이핑, 항목 순차 등장, 접힘 닫기, 스캔라인
  - RunFailureRevealTimeline / RunFailureGlitchArt: 글리치 띠
  - ControlTerminalTimeline: 위에서 아래로 훑는 스캔 빔
  - DroneTerminalCloseButtonFeedback: X 버튼 연출 (그대로 유지)

## 1. 열기 (약 0.3초)
- 가운데에 가로 청록선이 번쩍 생기고, 위아래로 펼쳐지면서 창이 나타난다 (CCTV 창 방식).
- 펼쳐진 직후 옅은 스캔라인이 위에서 아래로 한 번 훑고 지나간다.
- 즉시 SetActive로 켜던 방식을 이 연출로 바꾼다. 연출 중 다시 Tab을 누르면 닫기로 자연스럽게 넘어가야 한다.

## 2. 글자 등장
- 헤더 "DIGGER-BOT // AI ANALYSIS"가 먼저 타이핑되고, 상태(IDLE / SCANNING / PRIORITY)가 끝에 붙으며 커서가 깜빡인다.
- 대사가 빠르게 타이핑된다.
- "AI 추천 // 행동" 문구가 타이핑된다. **점수 [N]는 표시하지 않는다.**
- 근거 줄 [01], [02]…가 0.05~0.1초 간격으로 한 줄씩 나타난다.
- 열고 나서 글자가 다 나올 때까지 전체 약 1초 이내.
- 연출 중 창을 클릭하거나 Enter를 누르면 끝 상태로 바로 건너뛴다.

## 3. 점수 제거와 실제 수치
- 추천 옆 [점수], 근거 옆 (+점수)를 화면에서 뺀다.
- 점수 계산과 추천 선택 로직(DroneAnalysisService)은 바꾸지 않는다.
- 근거 줄 끝에 실제 수치와 단위를 붙인다 (ActualValue + Unit, 예: "가스 노출 7.2초", "전력 18%").
  - 값이 없거나 의미 없는 근거는 수치 없이 문구만 둔다.
  - 단위·소수점 표기 규칙은 근거 종류별로 확인해서 보고한다.
- 근거가 없으면 기존처럼 "추가 위험 근거 없음".

## 4. PRIORITY 전환
- 상태가 PRIORITY로 바뀌는 순간, 헤더가 주황으로 두 번 깜빡이고 창 전체에 짧은 글리치 띠가 한 번 지나간다 (약 0.3초).
- PRIORITY가 유지되는 동안에는 반복하지 않는다. 다른 상태로 갔다가 다시 PRIORITY가 되면 한 번 더 한다.

## 5. 다시 분석할 때 (0.5초 주기)
- **추천 행동이 바뀌었을 때만** 대사·추천·근거 타이핑을 다시 한다.
- 추천 행동이 같으면 수치만 조용히 바꾼다. 타이핑·깜빡임이 반복되면 안 된다.
- 근거 줄 개수만 바뀌는 경우 처리 방식(새 줄만 등장 등)을 정해서 보고한다.

## 6. 닫기 (약 0.25초)
- 열기의 역순: 위아래가 가운데로 접혀 가로선이 되었다가 사라진다.
- X 버튼, Tab, 드론 클릭 모두 같은 닫기 연출을 쓴다. X 버튼 자체 연출은 그대로 둔다.

## 구현 방향
- 연출 계산은 순수 클래스로 분리한다 (예: DroneTerminalTimeline: 열기·타이핑·근거 순서·닫기 / DroneTerminalChangeDetector: 추천 변경 여부, PRIORITY 진입 감지). View는 계산된 값만 적용한다.
- CCTV·런 실패 쪽 계산이나 그림(스캔라인, 글리치 띠)을 재사용할 수 있으면 재사용하고, 복사보다 공용으로 빼는 게 작으면 그렇게 한다. 기존 창 동작이 바뀌지 않게 한다.
- 레이아웃 변경이 필요하면 PromptB34 Builder 패턴을 따른다. 창 크기·위치는 바꾸지 않는다.
- 시간·색 값은 인스펙터에서 조정할 수 있게 둔다.
- 필요하면 이미지 생성이나 단순 반복 확인은 다른 에이전트에게 맡겨도 된다.
