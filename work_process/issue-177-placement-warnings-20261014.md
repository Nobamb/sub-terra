## 확인한 #177 경로와 수정

- Bridge의 마우스 확정은 locationValid/CanAfford 조건으로 걸러졌기 때문에 실패한 클릭이 이벤트를 만들지 않았다. UI 위 클릭 방어는 유지하면서 모든 월드 확정 클릭을 TryPlaceAt에 전달한다.
- C키 후보 없음은 PublishIfChanged(Invalid)만 보내 동일한 재시도와 실패 경고가 빠졌다. 명시적 설치 시도는 매번 Failed 이벤트를 보낸다. 매 프레임 미리보기는 기존 중복 억제를 유지한다.
- BuildingPlacementSystem은 위치 검사 뒤에 비용을 검사하여 겹침이 자원 부족을 가렸다. 기존 wallet 검사를 CanAffordSelection으로 묶어 CanPlaceAt와 최근접 후보 검색에서 먼저 판정한다. 비용 차감/생성/설치 점유 규칙은 변경하지 않는다.
- 실패 시 Bridge/Presenter가 선택을 지워 다음 입력이 무시됐다. 실패 후 선택을 유지해 같은 시설을 재시도할 수 있다. 성공/사용자 취소 때의 선택 정리는 유지한다.
- Presenter는 명시적 실패마다 건설창 상태 문구와 기존 PlayerStatusWarnings 머리 위 창을 함께 갱신한다. 현재 보유량이 부족하면 자원 부족을 우선 표시한다. 같은 경고는 기존 스택의 Extend 동작으로 표시 시간이 연장되며 중복 오브젝트를 쌓지 않는다.

## 최소 검증

- 현재 소스 기준 경량 컴파일 6개 성공: Player, Building, App, App.GameplayIntegration, Building.EditModeTests, App.Tests.EditMode.
- 기존 생성 csproj가 새 main 파일 목록을 포함하지 않아, 임시 컴파일 입력은 실제 asmdef 소유 폴더의 현재 소스로 구성했다. 다른 assembly 하위 소스는 제외했다. Unity csproj/캐시 DLL은 덮어쓰지 않았다.
- 회귀 검사 소스: 부족한 자원+막힌 지형에서 자원 부족 우선, 클릭 재시도 이벤트 2회, 비용/생성물 없음, 자원 확보 뒤 지형 사유 복귀. Presenter는 선택 유지·동일 실패 경고 2회·자원 우선·무차감을 검사한다.
- 검사 소스도 컴파일했으나 NUnit/Unity Test Runner와 실제 클릭/C키/머리 위 창은 실행하지 않았다. 테스트 통과나 실제 Demo 통과로 기록하지 않는다.
- diff 검사 통과. 임시 컴파일 출력은 삭제. 아직 커밋·푸시·PR 게시하지 않았다.
