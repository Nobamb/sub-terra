## 제작 기준

기존 `Frames/Idle/player_idle_01.png`를 외형·질감 기준으로 사용했다.
기존 `Frames/LadderBack/ladder_back_01.png`는 자세 참고로만 사용했다.
파츠 리그가 아닌 완성된 캐릭터 한 장이며, 약간 돌아선 뒷모습에 양손을 올리고 양발을 같은 높이에 둔 중립 매달림 자세다.
헬멧·배낭·어깨의 명암을 보강하고, 회색 작업복과 주황색 장비를 기존 광부와 맞추려 했다.
사다리나 배경은 포함하지 않았으며 투명 배경으로 제작했다.

사용한 방식: 내장 imagegen. 기존 PNG만 교체했으며 `.meta` GUID는 변경하지 않았다.
출력 크기: 1254 × 1254. 모서리 알파 0 확인.

### 제작 프롬프트 요약

> 기존 대기 광부를 외형 기준으로, 같은 황금빛 주황 헬멧·헤드램프, 짙은 회색 작업복·장갑·부츠, 청록 표시등이 있는 소형 배낭을 유지한다. 약간 돌아선 뒷모습 중립 등반 자세 한 장을 제작한다. 양손은 귀/헬멧 높이에, 양발은 같은 기준선에 두고 무릎은 가볍게 굽힌다. 상단 왼쪽 광원과 섬세한 윤곽으로 입체감을 표현한다. 캐릭터 전체를 사각 투명 캔버스에 중앙 배치한다. 얼굴·사다리·배경·그림자·문구·분리 파츠·시트는 넣지 않으며 팔과 귀 사이도 실제 알파로 투명하게 한다.

v2 수정 프롬프트: 몸통·배낭·다리를 중앙의 거의 대칭인 뒷모습으로 변경하고 큰 3/4 회전을 제거한다. 헬멧에만 최대 5도 정도의 작은 회전감을 남긴다. 장비·재질·조명·양손/양발 중립 자세·캔버스 크기를 유지한다.

교차 동작 프롬프트: 승인된 v2를 편집 대상으로 사용한다. 1254 사각 투명 캔버스, 카메라·중심·헬멧·머리·몸통·배낭의 크기와 위치, 색·명암은 유지하고 팔다리만 작은 등반 동작으로 변경한다. 양손은 항상 어깨보다 위에 유지한다. 왼손을 살짝 높이며 오른발을 약 한 부츠 높이만큼 올리는 프레임과, 오른손을 높이며 왼발을 올리는 프레임을 각각 제작한다. 올리지 않은 발의 중립 기준선은 유지한다. 사다리·분리 파츠·시트·배경은 포함하지 않으며 내부 빈 공간도 투명하게 한다.

오른손·왼발 프레임의 왼팔/귀 사이에 생긴 작은 갈색 잔여물은 해당 공간만 투명하게 하는 imagegen 수정으로 제거했다.

## 적용 내용과 남은 단계

1. v2 스타일 확정 및 중립·왼손/오른발·오른손/왼발 3장 적용 완료.
2. 1254 사각 캔버스, 기존 PPU 1254, 중앙 피벗과 GUID 유지. 전체 플레이어 에셋 빌더는 실행하지 않았다.
3. 현재 거리 기반 `0 → 1 → 0 → 2`, 하강 역방향, 정지 0번 구조와 기존 이동/사다리 판정은 변경하지 않았다.
4. Bootstrap 자동 검증은 아래 기록 참조. 화면 캡처는 사용자가 필요 없다고 요청하여 제외했다.
5. 팀원은 실제 Game 화면에서 명암·선명도와 손발 접점의 미세한 시각적 완성도를 확인하면 된다. 자동 검증은 미술 품질의 육안 확인을 대체하지 않는다.
6. 모서리 효과 식별성은 다음 작업이며 이번 변경에 섞지 않았다.

## 검증 기록

- Unity 6000.5.4f1 일반 에디터 모드에서 컴파일 및 `SubTerra.Gameplay.Player.Tests.PlayerMovementPlayModeTests` 실행: 30개 통과, 실패 0개.
- 상승/하강 공유 프레임·역방향 거리 재생, 정지 자세, Walk 혼입 방지, 일시적 접촉 공백, 점프 및 재탑승 관련 기존 테스트 포함.
- 테스트 결과: Unity 프로젝트의 `Temp/pr138-player-playmode.xml`. 실행 로그: `Temp/pr138-player-editor.log` (Git 제외).
- 최초 제한 환경 실행은 Package Manager IPC 연결 실패, 헤드리스 재시도는 해당 라이선스 부재로 시작하지 못했다. 일반 에디터 실행으로 검증했다.
- Unity가 자동 갱신한 무관한 URP 설정은 해당 파일만 검증 전 상태로 복원했다.
- 기존 main에서 가져온 Unity 직렬화 파일에 공백 경고가 있다. 이번 사다리 작업으로 전역 포맷을 정리하지 않았다.
- 새 이미지 적용 후 `LadderBackBootstrapPlayModeTests.Bootstrap_NewGame_ClimbUsesImportedBackFramesOnly` 통과(1개).
- 실제 Bootstrap → MainMenu → 새 게임 → SurfaceBase → 탐사 씬 경로를 실행했다. 테스트 세이브는 Unity 프로젝트 `Temp/ladder-save-20261001-v4`에 격리해 실제 세이브를 사용하지 않았다.
- 실제 씬 플레이어와 5칸 `Ladder_Buildable` 프리팹을 사용하여 중립 자세, 상승·하강 중 새 3개 스프라이트만 선택, 정지 시 0번 복원, VisualRoot 위치 고정, 이탈 시 일반 스프라이트 복원을 검증했다.
- 테스트 및 임시 시설은 씬/프리팹에 저장하지 않았다. Unity가 재실행 시 Temp를 정리하므로 최종 결과 XML은 이 폴더의 `validation/`에 보존한다.
- 새 이미지 적용 후 기존 `PlayerMovementPlayModeTests` 재실행: 30개 통과, 실패 0개. 결과: `validation/player-regression.xml`.
- 최종 Bootstrap 재실행도 1개 통과, 실패 0개. 결과: `validation/bootstrap.xml`, 실행 로그: Unity 프로젝트 `Logs/ladder-bootstrap-final.log`.
- 화면 캡처나 육안 게임 화면 검토는 하지 않았다. 이미지 자체는 생성 결과를 시각 확인했으며, 인게임 미술 품질·접점은 수동 확인 대상으로 남긴다.
- 사용자가 적용 결과를 확인하고 커밋·푸시·PR 게시를 승인했다. 기존 PR #138에 이번 변경과 검증 결과를 추가한다.
- 원본 백업·제작 시안·검증 XML과 실행 로그는 로컬에 보존하며 게시 대상에서 제외한다. Git에는 적용 PNG 3장, 회귀 테스트와 이 작업 기록을 포함한다.
