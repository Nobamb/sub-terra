# 서로 다른 텍스처의 스프라이트가 머티리얼 하나를 공유하면 첫 텍스처로 다 그려지고, 등장 연출 값은 화면에서 직접 보고 정한다

- 날짜: 2026-11-18
- 태그: reticle, sprite, material, motion, issue306, verification
- 실수: B-202-2에서 조준선·등장 연출을 넣고 EditMode 테스트만 통과시킨 채 "완료"로 보고했다. 실제로는 (1) 꺾쇠·조준선·칸 틴트가 `Sprites/Default` 머티리얼 하나를 공유해 모두 첫 텍스처(틴트)로 그려져 뭉툭한 청록 덩어리가 됐고, (2) 등장 연출은 명세 초안 값(110%, 0.15초)이 화면에서 거의 안 보였다. 사용자는 "너무 단순한 L 표식", "조준선이 안 보임", "연출이 안 보임"이라고 했다.
- 원인: 머티리얼을 `new Material(shader)` 하나로 만들어 모든 렌더러에 `sharedMaterial`로 꽂았다. 이 렌더 경로에서는 같은 배치로 묶여 첫 텍스처가 모든 스프라이트에 쓰였다. 테스트는 스프라이트·색·위치만 보고 실제 렌더 결과는 보지 않았다. 연출 값은 초안 상수를 그대로 썼고 프레임으로 확인하지 않았다.
- 다음부터 할 일: 텍스처가 다른 스프라이트는 부품마다 머티리얼을 따로 만들고 `mainTexture`를 직접 넣는다(테스트로 `sharedMaterial` 분리와 `mainTexture == sprite.texture`를 확인). 시각 요소를 바꾸면 임시 프리뷰 씬(`EditorSceneManager.NewPreviewScene`)에서 실제 타일 위에 프레임을 렌더해 PNG로 직접 본다(카메라 `transform.position` z=-10을 빠뜨리면 빈 화면이 나온다). 연출 시간·배율은 1080p 기준 칸 약 108px로 환산해 눈에 보이는지 확인한다. 명세 초안 값이 화면에서 안 보이면 값을 키우고 보고서에 이유를 적는다.
- 관련: B-202-2, 이슈 #306, PR #374
